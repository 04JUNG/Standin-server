# 04J-344 포즈 검색 후보 보강

기존 러프 100장과 정답 포즈 114개로 최종 표시 순위를 평가했다. 한 장에 정답 포즈가 여러 개면 하나라도 Top K에 들어갈 때 적중으로 집계했다.

| 실험 | 입력 | Top 1 | Top 5 |
| --- | --- | ---: | ---: |
| 이전 실험 앱 · 회전 복구 | 새 인식 | 25/100 | 50/100 |
| 개선 로컬 | 저장된 인식 결과 | 62/100 | 90/100 |
| 개선 실험 앱 | 새 인식 | 44/100 | 74/100 |

로컬 적중에는 검토 후보로 표시된 1장이 포함된다. 실험 앱의 Top 5 적중은 전부 라이브러리 후보였다. Luna는 분석 시 low 설정을 사용한다. 6필드 자세 설명은 설명을 요청하는 장면에서 한 번 호출하며, 얽힌 인물의 개별 검색이 차단된 경우 설명을 건너뛴다.

## 요청 처리

1. 기존 분석 API에서 러프의 인물과 관절을 새로 읽고 Luna로 검색용 자세 설명을 받는다.
2. 관절 위치·방향과 태그로 후보를 검색한다. 가려진 관절과 회전은 관찰 근거를 다시 계산해 보강한다.
3. 손 접촉, 보이는 관절의 투영, 깊이와 태그 근거를 비교해 후보를 재정렬한다. 후보군마다 같은 라이브러리의 BVH를 사용한다.
4. 기존 출력 계약에 맞춰 후보를 반환한다. 손 메시 검사와 미리보기 검증을 통과한 결과만 해당 조건에 맞게 표시한다.

재정렬은 요청에서 추출한 정보, 라이브러리 인덱스, 수치 가중치를 사용한다. 가중치는 평가에서 각 러프를 학습에서 제외한 5개 분할로 만들었고 요청 이미지 해시로 분할을 고른다. 평가용 러프, 정답 대응표, 채점 결과와 이전 요청의 응답은 서버 코드에 포함하지 않았다.

## 검증 환경에서 켜기

`ROUTING_RECALL_ASSETS_DIR`을 모델 디렉터리로 설정한다. 추론 서버에 전신 검색, Luna 및 손 메시 검사 서비스가 구성되어 있어야 한다. 프로필은 설정이 없는 환경에서 꺼진다.

| 모델 디렉터리 항목 | 용도 |
| --- | --- |
| `pose-model/manifest.json`과 매니페스트가 가리키는 모델 | HumanArt 관절 추출 및 회전된 인물 영역 재추출 |
| `body.onnx` | RTMPose-X 관절 비교 |
| `depth.onnx` | RTMW3D 관절과 깊이 비교 |
| `multilingual-e5-small/` | 검색 문장과 태그 임베딩 |
| `grounding-dino/` | 관절 근거가 부족한 일부 장면의 물체 확인 |
| `cache/` | 라이브러리 BVH에서 계산한 손끝 접촉 인덱스 |

물체 감지 프로세스는 `ROUTING_RECALL_PROP_PYTHON`으로 지정한 Python에서 실행한다. 별도 지정이 없으면 서버와 같은 Python을 사용한다. 이 환경에는 PyTorch, Transformers, Pillow, safetensors가 필요하다. 모델 파일은 로컬에서 읽는다. `/healthz`와 추론 응답의 `pose_search_profile`로 활성화를 확인한다.

74%는 독립 실험 앱에서 측정한 수치다. `develop` 검증에서는 같은 모델 및 라이브러리 번들을 연결하고 지연과 새 인식 100장 적중률을 다시 측정해야 한다.
