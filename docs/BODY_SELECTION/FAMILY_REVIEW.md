# 이미지 기반 남녀 계열 재검토 — 2026-10-17

`124702:p0`를 최종 원격 실행에서 **여성 BASE (`female-base-v0-3-4`)**로 교정했다. `124637:p0`는 남성 BASE를 유지했다. 특정 인물 ID·파일명·해시 분기, 작가 설정 메타데이터, 정답 주입은 없다. 배포·환경변수 활성화·머지는 하지 않았다.

## 원인과 근거

이전 보고서의 `124702`는 VLM이 남성을 확정한 것이 아니라 **중성형 → 설정 남성 BASE** 경로였다. 같은 입력을 다시 실행하면 각진 미완성 두상과 어깨, 상의 경계선을 남성 골격·근육으로 읽어 남성 MUSCULAR까지 추천했다. 따라서 기본값만 여성으로 바꾸어서는 해결되지 않는다.

crop 확대·발끝 여백·얼굴 확대·간단한 한국어 질문·BASE 렌더 비교·모델 교체만으로는 반복해서 남성/중성 판독이 나왔다. 얼굴 → 의상의 목선·소매·옷단 → 몸의 디자인을 먼저 기술하는 별도 계열 판독에서는 상의를 튜브톱으로 읽고 여성 계열을 추천했다. 이는 의상과 신체 선의 해석 순서가 영향을 주었다는 실험 근거이며, VLM의 설명을 실제 내부 추론의 증명으로 보지는 않는다.

사용자 정답은 평가 직전에만 별도로 읽는다. 모델 입력에는 불투명 인물 ID와 기존 인물 crop·동일 crop의 대상 표시본만 넣는다. 원본 전체 이미지는 로컬 검수에만 사용한다.

## 구현과 회귀 방지

- 기존 `GeminiCoarseClient`의 최초 판독과 프리셋 매핑은 유지한다.
- 선택적 `family_review`는 대상이 분명하고 남녀 계열이 잠정/미확정인 `character|face_only`만 읽는다. 확실한 남녀 판독·stick·소유권 모호 입력은 변경하지 않는다.
- 재검토는 최초 결론·정답·수동 힌트를 받지 않고 이미지의 얼굴·의상·몸 근거를 먼저 기록한다. 계열이 미확정이면 잠정 최선 추천도 허용한다.
- **이미 알려진 계열을 반대 계열로 바꾸려면 재검토가 clear여야 한다.** 잠정 남성 ↔ 잠정 여성 충돌은 기존 추천을 유지하고 `status=conflict` 및 두 판독 근거를 남긴다. 남→여와 여→남에 같은 규칙을 적용한다.
- 계열 해석이 교정되면 초기 해석에서 나온 특수 체형 근거를 tentative로 낮추고 새 계열 BASE를 추천한다. 원래 특징 값·이유는 남긴다. 같은 계열 확인에서는 명확한 근육·비율 특징을 유지한다.
- 재검토 오류·미확정·시간 소진은 최초 추천을 그대로 보존한다. 재시도하지 않고 기존 체형 요청의 남은 시간만 사용한다.
- `coarse_classification.family_review`에 최초 계열·독립 재검토 근거·상태를 추가한다. 확신도가 낮아도 구체적인 추천 ID와 대안을 모두 기록한다. 자동 적용은 false다.
- HTTP 검증기의 기존 결함도 수정했다. 잠정 계열에 의도적으로 추가한 반대 계열 BASE를 거부하던 조건을 바로잡았다. 확실한 계열에 반대 계열을 섞거나, 반대 계열 특수 체형을 대안으로 넣는 것은 여전히 거부한다. 선택 필드가 null인 캐시 응답도 허용한다.

중간 구현은 재검토 결과를 무조건 따랐다가 `124637`을 여성으로 바꾸었다. 이 후보는 폐기했고 위 충돌 가드로 원격 응답을 재생해 회귀가 사라진 것을 확인했다. 결과를 지우거나 정답으로 덮어쓰지 않았다.

## 최종 평가

동일한 원본·crop·context·target 및 20종 catalog를 사용했다. 최초 모델은 실제 응답 `gemini-3.5-flash-lite`, 재검토는 `gemini-3.8-flash`다. 최종 28명에서 최초 판독 API 오류 0, 재검토 3명 성공, 추천 기록 28/28, 자동 적용 0이다.

| 같은 최초 응답 → 최종 재검토 | 남성 BASE → 여성 BASE | 추천 ID **27/27 유지**; 미확정 1명의 판독만 남성으로 구체화 |

| 회귀가 있었던 중간 실행에 최종 가드 재생 | 여성 BASE 교정 유지 | 추천 ID **27/27 유지**, 124637 남성 BASE 보존 |

작가 확인 정답은 `124637=남성`, `124702=여성` 두 건이다. **이 두 건의 판독·추천 정답률은 1/2 → 2/2**다. 전체 28명의 정확도나 독립 검증 성능이 아니다. 다른 26명의 작가 정답과 세부 체형 정답은 없다.

이전 보고서 대비 세부 프리셋 변동 2건은 재검토가 실행되지 않은 인물의 **최초 모델 출력 변동**이다. 동일한 최초 응답으로 비교하면 이 두 건도 유지된다.

- `131127:p0`: 남성 MUSCULAR → BASE. 원본에서 작업복으로 몸통이 가려지고 근육 강조가 뚜렷하지 않아 BASE는 설명 가능한 추천이다. 최초 모델의 근육 certainty가 달라졌다.
- `131224:p0`: 여성 BASE → SLIM. 보이는 팔·다리는 가늘지만 몸통·골반은 차문에 가려져 있다. 최초 모델의 slim certainty가 tentative → clear로 달라졌다. 어느 프리셋이 작가 의도에 맞는지는 미확인이다.

따라서 **최종 남녀 계열에 새 오분류는 관찰되지 않았지만, 전체 세부 추천의 무회귀를 입증했다고 주장하지 않는다.** 같은 temperature=0 요청도 출력이 달라진다. `--baseline` 비교는 인물별 ID 변화를 기록하고, 확정 정답의 개선/회귀와 미확인 변경을 분리한다. 전체 프리셋 개수만 같은 결과를 무회귀로 처리하지 않는다.

## 활성화와 시간 제한

기본값은 재검토 비활성이다. 활성화할 때만 `BODY_COARSE_FAMILY_REVIEW_MODEL=gemini-3.8-flash`를 지정한다. 기존 `BODY_CLASSIFICATION_STRATEGY=coarse`, `BODY_VLM_MODEL=gemini-flash-lite-latest` 설정과 함께 사용한다. legacy에는 재검토 옵션을 전달하지 않는다.

`BODY_TIMEOUT_SECONDS`는 최초 호출과 재검토가 공유한다. 기본 12초를 바꾸지 않았다. **이번 오프라인 평가의 120초 예산을 운영 추천 설정으로 간주하지 않는다.** 분리 실험과 통합 실행에서 재검토 지연이 수십 초 이상, 한 실행에서는 최초 응답 저장부터 재검토 응답 저장까지 약 106초였다. BFF 전체 상한에 맞춘 지연·비용 검증 전에는 활성화하면 안 된다. 12초 운영 예산에서 동일한 성공률은 확인하지 않았다.

최초 판독이 잘못되었더라도 clear이면 이 재검토는 개입하지 않는다. 잠정 계열끼리 반대로 충돌하는 경우도 잘못된 최초 추천이 남을 수 있다. 이 경로는 남녀 판독의 완전한 해결이나 보정된 확률 모델이 아니다.

```bash
python scripts/eval_body_coarse.py \
  --protocol /path/to/camera_real_rough_20260921_v2/protocol.json \
  --out /path/to/final-live --remote --env-file /path/to/.env \
  --labels docs/BODY_SELECTION/COARSE_CONFIRMED_LABELS.json \
  --baseline /path/to/baseline/results.json --focus-case 124702:p0 \
  --family-review-model gemini-3.8-flash --timeout-seconds 120
```

`--focus-case`는 결과 표를 대상/나머지로 나눌 뿐 모델 요청·추천에 영향을 주지 않는다. 비교할 원본·crop·context·target·catalog·case ID가 다르거나 중복이면 비교를 거부한다.
