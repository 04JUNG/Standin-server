## 구현과 안전 조건

`BODY_CLASSIFICATION_STRATEGY=integrated`, `BODY_MATCHING_MODE=shadow|auto`에서만 첫 프롬프트/응답 스키마를 확장한다. `body-integrated.v3.compact`는 얼굴·의상·몸 근거를 먼저 기록하고 남녀 디자인 계열 → BASE → 명확한 근육/체격/비율 특징 순으로 추천한다. 나이·아동·정확한 등신 수나 관절 좌표를 생성하지 않는다. 프리셋 ID는 모델이 만들지 않고 기존 20종 morphology catalog로 서버가 매핑한다.

원본 VLM 슬롯 인덱스로 관측을 연결해 출력 좌우 정렬과 분리한다. 체형 배열 길이/중복/외부 인덱스가 잘못되면 체형 블록만 unknown으로, 한 행 오류는 해당 행만 unknown으로 처리한다. 사람 수·shot·박스·가시성·손·태그·포즈의 원래 파싱과 선택 계산은 바꾸지 않는다. 연결 근거가 없는 검출기 슬롯에 다른 인물의 체형을 전용하지 않는다.

추가 crop 판독·계열 재검토·숨은 재시도는 없다. 주 추천은 불명확할 때도 기본값과 근거를 기록하지만 `auto_body_id/applied_body_id/selected_asset=null`, 실행 자산 candidates=[], render=false다. `auto` 설정에서도 이 추천을 자동 적용하지 않는다. BFF 수동 선택/기본값 우선순위를 유지한다. off/legacy의 원래 프롬프트는 그대로다. 선택적 OpenAI 어댑터도 동일 확장 계약을 지원하나 원격 정확도는 Gemini만 평가했다.

`VLM_BODY_THINKING_LEVEL=low`를 평가에 사용했다. 기본 빈 값은 모델 기본을 유지한다. Gemini 3.8은 minimal을 거부했다(400). 통합 첫 호출은 기존 주 VLM 요청·총 예산을 공유하며 별도 BODY_TIMEOUT_SECONDS는 사용하지 않는다. 전체 파이프라인의 호출을 하나로 줄인 것은 아니다: 인물 태그, 포즈 설명·좌우 재검토, 생성은 기존 독립 단계다.
