# 통합 체형 후속 복구 — 2026-10-17

v3 평가에서 발견한 124702 계열 오답, 청룡성:p0 연결 소실, 포즈 제공 4건 소실의 후속 수정이다. 특정 사례 ID·파일명·정답·hash를 런타임 분기에 사용하지 않는다. 기본 legacy/off, 실제 .env와 배포는 변경하지 않았다.

## 원인과 변경

- 계열: 각진 소체 선을 해부학 경계로 읽거나 의상 경계를 생략하면서 124702의 첫 판독이 중성/미확정이 됐다. catalog 기본값인 남성 BASE가 추천되어 오답으로 이어졌다. 첫 호출 프롬프트 강화·해상도·추론량 변경은 124637 등에서 퇴행/불안정이 관찰되어 채택하지 않았다. 첫 통합 판독을 유지하고, **미확정 계열만** 별도 독립 crop 판독을 최대 1회 batch로 실행한다. v5는 얼굴·의상·몸 근거를 각각 35자, 결론 근거를 70자로 짧게 요청하고 명시된 `VLM_BODY_THINKING_LEVEL`을 재검토에도 적용한다. 기존 binary 계열은 tentative여도 건드리지 않는다. 재검토 실패는 제어 분석을 재시도하지 않는다. 추정 추천을 확정 판독/자동 적용으로 승격하지 않는다.
- 연결: VLM이 박스 x1>x2를 출력해 그 슬롯이 비고, 남은 정상 검출 결과가 기대 인물 수 제한에 막혀 버려졌다. 단순 좌표 정렬은 엉뚱한 좁은 중앙 박스를 만들므로 사용하지 않는다. VLM/검출 수 일치, 정확히 하나의 무효 박스와 미배정 검출, 다른 슬롯의 명확한 소유권, 구조·겹침 검사를 모두 통과하면 소거법으로 연결한다. 원본 provider 박스·오류 사유를 보존하고 `quality_trace.box_recovery`에 출처를 남긴다. count confidence 규칙은 그대로다.
- 포즈: 131000:p1은 ally 양손 수, 131056:p2는 bag 양손 수 조건이 모든 후보를 제거했다. 4.56.21:p0는 팔 자세 해석이 달라져 조건 통과 후보가 사라졌다. 청룡성:p0는 앞선 연결 실패의 후속 소실이다. 조건 통과 후보/기존 생성은 변경하지 않고, 후보가 없을 때만 유효 관절·인물 소유권·자세·기하 거리 상한을 유지한 참고 후보를 제공한다. `geometry_fallback`, `review_required=true`, `not_exact_match=true`, `constraints_satisfied=false`를 API에서 강제한다. 원래 의미 조건을 만족했다고 세지 않는다. 자동 refine/export 불가다.

실제 라이브러리에서 기록된 최종 관절/마스크/포즈 설명으로 36개 출력 인물을 재생했다(원격 호출/생성 재현 없음). 기존 비어 있지 않은 24개 선택은 **24/24 그대로**였다. 기존 포즈 소실 3건과 추가 1건(131224:p0)에 기하 참고가 생겼다. 원래 API 순위 재현은 35/36으로 171734:p0의 Top-1은 같지만 후순위가 달랐다. 미수집 중간 정보가 있는 재생이며 전체 live 무회귀나 포즈 정답률을 보장하지 않는다.

기록된 v3 최초 응답을 고정하고 실제 v5 재검토 helper만 실행했다. 28명 중 이전에 연결됐던 27명에서 124702만 여성 BASE로 교정됐고 다른 26명은 추천 ID가 모두 유지됐다. 미연결 1명은 앞선 실제 검출/배정 복구로 따로 확인했다. 5개 재검토 batch는 오류 0회였다. 36개 전체 VLM 슬롯에서는 평가 대상 밖 131112 slot 2도 추천이 바뀌어 별도로 기록했으며, 작가 정답이 없어 이 변경의 품질은 판정하지 않는다. 인물 수·박스·원본 raw 등 제어 필드는 모든 재생에서 그대로였다.

독립 짧은 재검토 반복 실험은 이전 124702 crop에서 3/3 여성 추천(3.4~4.6초), 124637은 3/3 미확정으로 기존 남성 BASE를 유지했다. 이 두 crop의 소규모 반복을 전체 분포의 정확도/서비스 SLA로 사용하지 않는다.

## 최종 v6 후처리 재평가

v5 실측 대조에서 `124629:p0`의 IDEAL83가 BASE로 떨어진 일반 후처리 오류를 찾았다. 중성/unknown을 남성으로 해소하는 것까지 실제 남녀 계열 충돌로 처리해, 명확한 긴 팔다리·비율 근거도 강등하고 있었다. v6는 **미확정 해소만으로 독립 축 근거를 낮추지 않는다**. 기존 binary 계열을 반대로 교정할 때의 강등·충돌 가드는 유지하고, standalone coarse의 기본 정책도 변경하지 않았다. 원래 판독의 tentative 특징을 clear로 올리는 보정은 없다.

이 마지막 수정은 요청 프롬프트·모델·호출 분기를 바꾸지 않는 후처리다. 실제 저장한 v5 최초/재검토 응답을 `review_uncertain` → `CoarseBodyService` → 실제 API 체형 검증기로 재생했다. 원격 호출이나 포즈 추론을 다시 실행하지 않았고 **17컷·36개 출력 인물의 사람/박스/관절/포즈 JSON은 원래 v5와 완전히 같음**을 확인했다. body 정보만 재계산했다. 새로 v6 end-to-end 시간을 측정한 것으로 표현하지 않는다.

## 실제 전체 실행과 시간

최종 후처리의 입력이 된 **v5 실제 API 실행**은 최초 16/17 성공했다. 마지막 청룡성 첫 VLM이 504로 실패해 최초 남녀 점수는 25/28, 프리셋 20/28, 인물 연결 25/28이었다. 성공한 16컷은 바이트 단위로 보존하고, 결과가 없는 청룡성만 동일 설정으로 후속 실행했다. 후속 성공 시 v5 추천은 남녀 28/28, 프리셋 23/28이었다. 최종 v6 후처리로 프리셋 1건을 추가 복구했다. 최초 실패나 유효한 오답 응답을 지우고 좋은 결과로 교체하지 않았다.

V5 후속 완료 기록의 API 시간은 중앙값 **24.459초**, p95 **56.376초**, 최대 **68.176초**, 성공하고 12초 이하 **0/17**이다. 이는 원래 16컷+후속 1컷의 소스 실행 시간이며, 연속 실행 성공률 또는 v6 새 end-to-end 실측이 아니다. 이미지 디코딩~JSON 직렬화 범위이며 BFF·업로드·기동은 제외하고 기존 생성 비용은 포함했다. 실제 제품 전체 12초 달성 근거로 사용할 수 없다. live 포즈 설명·재검토·생성 결과가 달라져, 과거 v3 중앙값보다 낮은 관측값을 통계적인 성능 향상으로 주장하지 않는다.

V5의 체형 재검토 6회는 오류 0회, 2.765~5.333초였다. 이전 v4는 4/4가 상한 근처에서 실패했으므로 v4 기록과 별도로 보존했다. 응답이 안정적이라는 보장이나 큰 분포의 SLA 검증은 아니다.
