# 미확정 체형 재검토 병렬화

2026-10-17 · `body-integrated.v7.parallel-review` · 배포 및 실제 환경 설정 변경 없음.

## 실행 계약

첫 Gemini 통합 판독 → (검출·포즈 추출·검색 ∥ 미확정 체형 crop 재검토) → 남은 예산 내 합류 → 체형 추천 sidecar.

남녀 계열이 미확정인 인물만 기존 최대 1회 batch 재검토를 실행한다. 프롬프트·모델·추천 정책·재시도 횟수는 변경하지 않았다. 확정된 남녀 계열은 tentative여도 재검토하지 않는다. 체형 off/legacy 및 review 비활성 경로는 작업을 만들지 않는다. 직접 `GeminiVLMClient.analyze()`를 호출하면 기존처럼 동기 실행한다.

- 요청별 분석·이미지·설정 복사본에서 실행하고 포즈 작업이 끝난 뒤 원본 VLM 슬롯으로만 합친다. 출력 좌우 정렬은 연결에 영향을 주지 않는다.
- 최초 주 VLM의 총 deadline과 재검토 시작 시 `BODY_TIMEOUT_SECONDS` 중 이른 기한을 유지한다. 합류 시 새 예산은 없다. 기한 내 완료됐다면 포즈가 더 오래 걸려도 응답을 채택한다.
- 시간 초과·예외·스냅샷 인물 ID 불일치는 최초 추천을 보존한다. 포즈 실패 시 기다리지 않고 작업 참조를 해제한다. 실행 중 SDK HTTP 요청은 강제 중단할 수 없고 기존 timeout까지 지속될 수 있으나, 복사본만 갱신하므로 늦은 응답이 결과에 반영되지 않는다.
- `body_matching.parallel_review`에 겹친 시간·합류 대기·상태를 기록한다. 사람 수·박스·태그·관절·포즈 선택 제어에는 쓰지 않는다. 자동 적용·Export 권한도 바꾸지 않는다.

## 회귀 검증

실제 저장된 V5의 17컷 최초/재검토 응답을 현재 정책의 동기 경로와 병렬 경로에 동일하게 재생했다. 원격 VLM·포즈 모델을 새로 실행한 평가가 아니다. 정답 라벨은 판독 경로에 전달하지 않았다.

| 항목 | 동기 / 병렬 비교 |
|---|---|
| 출력 36명 체형 추천 전체 | 36/36 완전 일치 |
| 17컷 사람·박스·관절·포즈 JSON | 17/17 완전 일치 (기록 보존 확인) |
| 승인 28명 인물 연결 | 28/28 |
| 승인 28명 남녀 추천 | 28/28 (100%) |
| 승인 28명 세부 프리셋 | 24/28 (85.7%) |
| `124702:p0` | 여성 BASE 유지 |

28명은 사용자가 승인한 개발 기준이며 독립·블라인드 정답이 아니다. 기록된 포즈 결과를 보존하므로 이 재생만으로 새 모델 실행에서의 사람·포즈 정확도나 안정성을 입증하지 않는다. 실제 Pipeline 동시 실행은 별도 11개 Event/Barrier 기반 테스트로 확인했다. 요청 간 격리, 포즈 선행 시작, 출력 순서 변경, 완료 기한, 늦은 응답, provider 실패, 포즈 실패, 비활성 경로를 검증했다. 전체 CI 1,740 passed / 9 skipped / 28 subtests, 스모크 54/54, compileall·diff check 통과.

## 대기 시간 검증과 한계

실제 Pipeline에 VLM/포즈 지연을 주입한 합성 실험이다. 각 모드 3회 중앙값이며 실서비스·Gemini·RTMPose 측정이 아니다.

| 주입한 재검토 / 포즈 지연 | 동기 | 병렬 |
|---|---:|---:|
| 120ms / 200ms | 333.7ms | 208.8ms |
| 200ms / 120ms | 331.9ms | 206.3ms |

재검토와 포즈 비용이 겹쳐 실행됨을 확인했다. 첫 호출·포즈 설명·생성 등 다른 비용은 줄이지 않으므로 **전체 파이프라인 12초 달성을 주장하지 않는다**. V7 원격 end-to-end 시간은 이번에 새로 측정하지 않았다. 기존 V5의 실제 시간은 [이전 복구 평가](INTEGRATED_REPAIR.md)에 별도 보존한다.
