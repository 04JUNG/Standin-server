# MVP 릴리스 가이드 — 작가 실사용 30분 시연

> **작성**: 2026-07-31 · **담당**: 도원(추론 서버)
> **출시 정의**: 작가가 **자기 러프**를 들고 와서 **라이브로 30분** 돌린다. 녹화·편집 없음.
> **한 줄**: 이 시연의 성패는 refine 품질이 아니라 **검색 커버리지와 실패 처리**에서 갈린다.

---

## 1. 이 문서가 정하는 것

"MVP에 뭘 넣고 뭘 빼는가"의 **단일 소스**. 논쟁이 생기면 §3 표로 돌아온다.
판단 기준은 하나: **작가 앞 30분 동안 눈에 보이는가, 그리고 깨질 수 있는가.**

---

## 2. 왜 컷라인이 이렇게 잡히는가

30분 라이브 시연은 데모 영상과도, 정식 배포와도 다르다.

| | 영상 데모 | **작가 실사용 30분** | 정식 배포 |
|---|---|---|---|
| 실패 컷 | 편집으로 제거 | **그대로 노출** | 재현 어려움 |
| 입력 | 고른 컷 | **작가가 즉흥으로 가져옴** | 임의 |
| 필요한 것 | 인상 | **인상 + 정직한 실패 처리** | 안정성·운영 |

→ 시연에서 가장 비싼 것은 **예측 못 한 입력에서 조용히 이상한 결과를 내는 것**이다.
   "못 찾았습니다"는 괜찮다. "이상한 걸 자신 있게 내놓았다"는 못 회복한다.

## 4. 리스크 순위 (시연에서 실제로 깨지는 것)

```
1. 검색 커버리지 ────────  작가 즉흥 컷이 라이브러리에 없으면 refine 유무 무관하게 실패
2. 추출 실패 ───────────  SEARCH_EVAL #7 케이스. 30분이면 한 번은 난다고 봐야 함
3. 환경/실행 사고 ───────  한글 경로(해결됨), SQLite 락, mock 조용한 폴백
4. refine 품질 ─────────  안전 게이트가 있으면 4순위로 내려감
```

**1번이 1순위인 이유**: refine은 틀린 베이스를 못 살린다. 그래서 §3의 1번(재평가)이
4번(refine)보다 **먼저** 와야 한다. 재평가 결과가 나쁘면 refine 작업 자체가 무의미해지고
예산을 라이브러리 보강으로 돌려야 한다.

---

## 5. 실행 순서

```text
1. [필수] 1511 라이브러리 재평가 (14컷 + 작가 실제 컷 스타일 몇 장)
     └─ 결과가 나쁘면 → 여기서 멈추고 라이브러리 보강. refine 착수 금지.
2. [필수] 임계값 재보정 (FALLBACK_DISTANCE / MIN_SKELETON_SCORE)
3. [필수] PersonOut keypoints·scores 추가            ← refine 채택 여부와 무관
4. [필수] refine 축소판 + 안전 게이트 + eval_refine.py
5. [필수] 시연 리허설 — 작가가 쓸 실제 컷으로 1회 완주
```

3번은 1·2번과 병렬 가능(의존 없음). 4번은 1번 결과 확인 후 착수.

## 7. 시연 중 사고 대응

| 증상 | 즉시 조치 |
|------|-----------|
| refine 결과가 이상함 | `REFINE_ENABLED=0` → 검색 결과만으로 진행 |
| 특정 컷에서 계속 실패 | 넘어간다. 사전 검증 컷으로 전환 |
| 전체 응답이 느림 | `top_n_search` 축소 |
| mock으로 떨어진 정황 | **즉시 중단**. 가짜 결과 서빙이 최악 |

원칙: **막히면 우회하고, 의심되면 멈춘다.** 30분 안에 디버깅하려 들지 않는다.
