# 러프 검색 비포 애프터 검수

기존 4시점 검색과 좌우 두 해석·원근 투영·카메라 미세 조정·윤곽 재정렬을 비교하는 로컬 실험이다. 기본 서버 검색이나 배포 설정을 바꾸지 않는다. 사용자가 보유한 러프 테스트셋의 10장으로 입력·추출 관절·양쪽 Top-5 3D 미리보기를 검수할 수 있다.

## 비교 조건

Before는 0°·45°·90°·180°의 수평 직교 시점과 원래 관절 이름을 사용한다. After는 같은 Human-Art XY와 유효 마스크로 좌우 두 관절 해석을 검색하고, 117개 시점과 가까운 거리에서 시작한 카메라 미세 조정 비용을 비교한다. 기존 117개 비용 25%와 미세 조정 비용 75%를 섞으며 117개 검색의 첫 포즈를 유지한다. 상위 20개 중 2~20위에는 윤곽 비용을 비중 1.0으로 더한다. 후보 하나라도 윤곽 렌더링에 실패하면 해당 입력은 카메라 혼합 순위를 유지한다.

두 방법은 전체 1,981개 갤러리에서 같은 관절 위치를 비교하며, 조회 포즈의 Z나 2D 정답 초안은 입력하지 않는다. 결과는 개별 pose_id 기준이고 운영의 태그 필터·family 중복 제거·VLM·다인물 처리를 재현한 것은 아니다. 서버 전체의 응답 품질로 해석하지 않는다.

set1의 한 명·전신 5장 전부와 나머지 테스트셋의 같은 조건에서 시드 20261013으로 5장을 선택했다. 추론 전에 선택을 기록했으며 실패한 입력을 교체하지 않았다. Human-Art는 RGB·192×256·픽셀 foreground crop·4방향 회전 중 몸 관절 점수 중앙값으로 회전을 선택한다. 몸 관절 6개 이상과 양쪽 어깨·골반이 모두 점수 0.3 이상이어야 검색한다.

## 10장 결과와 검수 상태

검색 가능 9장, 관절 기준 미달 rough_178 1장이다. 검색 가능 9장 모두 Top-5 후보 구성이 달라졌고 8장에서 1위가 바뀌었다. rough_279는 후보 렌더 실패로 윤곽 재정렬 대신 카메라 검색 결과를 유지했다. 이러한 변화 횟수는 정확도 개선 수치가 아니다. 원본 3D 정답과 완료된 사람 평가는 없다.

현재 채팅에서 받은 부분 피드백은 다음과 같다. 선호한 후보 ID는 라이브러리의 원본 정답 ID를 의미하지 않는다.

| 러프 | 개선 검색에서 선호한 후보 | 사용자 의견 |
| --- | --- | --- |
| rough_006 | 2위 webtoon_daily_18 | 2위가 더 마음에 듦 |
| rough_288 | 1위 sd_cmu_113_29_f03664 | 몸 자세는 좋지만 고개 방향이 아쉬움 |
| rough_279 | 4위 rokoko_PlayingSaxophone_mixamo_00087_mirror | 4위가 가장 맞음 |
| rough_291 | 4위 cmu_49_21_01499_mirror | 다리 교차와 팔꿈치 직각 굽힘이 중요 |

1위 유지 정책과 평균 관절 거리만으로 사용자가 중요하게 보는 특징을 충분히 정렬하지 못할 수 있다. 이 피드백에 맞춰 이번 검색 순위를 바꾸지 않았다. 추가 특징이나 1위 변경 정책은 개발 표본에서 따로 정하고 새 검증으로 확인해야 한다. 미리보기의 고개·얼굴·손가락 방향은 몸통 기반 근사이며 BVH의 실제 머리 회전을 재현하지 않는다.

후속 실험에서는 이 원본 결과를 보존한 채 특징 점수, 첫 후보 고정 해제, 수동 검수 조건과 입력 영역 복구를 별도 폴더에서 비교했다. 결과와 최신 다섯 검수 내용은 [러프 검색 특징 검수와 첫 번째 후보 정렬](PERSPECTIVE_FEATURE_REVIEW.md)에 정리했다. 자동 특징 추가는 개발 기준을 통과하지 못했으며, 수동 조건을 넣은 결과는 자동 인식 정확도 개선으로 해석하지 않는다.

## 로컬 재현

프로젝트 의존성과 Human-Art ONNX, 사용 권한이 있는 러프 데이터 및 라이브러리가 필요하다. 아래 경로는 각자의 로컬 위치로 바꾼다. 출력 폴더는 새 경로를 사용한다.

```sh
python scripts/review_perspective_roughs.py \
  --dataset-root /path/to/vlm-pose-30x5-v1 \
  --library-root /path/to/source_bundle \
  --model /path/to/humanart/end2end.onnx \
  --out out/rough-perspective-review

python scripts/build_perspective_review.py \
  --study out/rough-perspective-review \
  --output out/rough-perspective-review/review-fragment.html \
  --standalone out/rough-perspective-review/review.html

python scripts/audit_perspective_rough_review.py \
  --study out/rough-perspective-review \
  --dataset-root /path/to/vlm-pose-30x5-v1 \
  --library-root /path/to/source_bundle
```

생성된 `review.html`을 브라우저에서 연다. 러프 선택, 각 방법의 1~5위 선택, 관절 표시, 동일한 45° 시점 비교가 가능하다. 각 방법의 Top-5에 쓸 만한 후보가 있는지와 전체 선호를 선택하고 메모를 적는다. 브라우저에 검수 상태를 저장하며 JSON으로 내보낼 수 있다. Codex에서 제공하는 메시지 전달 기능이 없는 일반 브라우저에서는 검수 결과 전달 버튼이 JSON을 화면에 표시한다.

미검수·판단 어려움과 추출 실패는 그대로 보존해야 한다. 파일명과 pose_id를 검증된 정답으로 자동 변환하지 않는다.

## 검증과 공개 범위

실제 9장의 전체 갤러리 비용·카메라 미세 조정·순위를 재실행해 저장 결과와 일치함을 확인했고, 입력/관절/후보 미디어 200개와 비교 그림 10개를 검사했다. 좌우 대응·투영·미세 조정·윤곽 정렬·패딩 관련 테스트 23개가 통과했다. 별도 임시 브라우저에서 이미지 로딩, 후보/시점/관절 전환, 검수 저장 및 복원, 실패 표시, 모바일 가로폭을 확인했다. UI 테스트에서 입력한 평가 값은 격리된 임시 브라우저의 테스트 데이터이며 사람 검수 결과에 포함하지 않는다.

실험의 protocol·predictions·costs·rankings·검수 화면은 로컬 `out/`에 보관한다. 공개 저장소에는 코드·템플릿·테스트와 이 문서만 올린다. 기존 `.gitignore`에 따라 원본 러프, base64 이미지가 들어간 생성 화면, 모델, DB, BVH는 커밋하지 않는다.
