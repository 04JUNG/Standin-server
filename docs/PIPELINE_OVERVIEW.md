## 0. 한 줄

**웹툰 러프 콘티 컷 1장(PNG) → 그 컷의 인물별 3D 포즈 후보 Top-K(BVH) → 작가가 고른 1개를 러프에 맞춰 자동 미세조정.**
최종 산출물은 Clip Studio Paint(CSP) 데생 인형에 얹는 BVH 파일이다.

### 경계 (중요)

| | 담당 |
|---|---|
| **이 저장소** | VLM 분석 → 검색 → refine. 입력=컷 이미지, 출력=`CutResult`(JSON) + BVH 파일 |
| 밖 | 데스크톱 앱(Tauri)·캡처·뷰어·인증/Job(BFF)·CSP 좌표 보정·내보내기 |

이 서버는 **동기·무인증·무상태 추론 API**다.

## 1. 핵심 아이디어 — 왜 "3D 복원"을 하지 않는가

그림에서 3D를 복원(lifting)하지 **않는다.** 대신:

1. 라이브러리에는 **이미 3D인 포즈**(BVH, 1프레임)가 있다.
2. 각 포즈를 **4개 가상 카메라로 2D 투영**해 미리 색인한다.
3. 러프에서 뽑은 2D 스켈레톤과 **같은 피처 공간에서 기하 kNN**을 돈다.

즉 "3D를 맞히는" 문제를 "2D끼리 비교하는" 문제로 바꾼다. 리프팅의 불안정성을 회피한다.

refine 단계에서만 3D가 다시 등장한다: **러프는 깊이가 없고, 검색된 베이스 포즈는 깊이가 있다.**
둘을 합치면 "이 러프와 같은 3D 포즈"를 만들 수 있다.

## 2. 데이터 표현 규약 (추론에 반드시 필요)

### 2-1. 키포인트

- **COCO-17** 순서 고정:
  `0 nose, 1 left_eye, 2 right_eye, 3 left_ear, 4 right_ear, 5 left_shoulder, 6 right_shoulder,
   7 left_elbow, 8 right_elbow, 9 left_wrist, 10 right_wrist, 11 left_hip, 12 right_hip,
   13 left_knee, 14 right_knee, 15 left_ankle, 16 right_ankle`
- left/right는 **인물 기준**(관찰자 기준 아님).
- 얼굴 5점(0–4)은 BVH에 대응 관절이 없어 Head로 근사 → **매칭에서 제외**한다.
  실제로 쓰는 것은 몸통 12관절(5–16).

### 2-2. 좌표계

| 단계 | 규약 |
|---|---|
| BVH 3D | Y-up, 오른손 좌표계. 루트=Hips |
| 투영 | Y축(수직축) 회전 후 **정사영**. 원근 없음 |
| 투영 직후 | y가 위로 + |
| 이미지 정합 | **y 부호 반전** → 이미지 좌표(y 아래로 +)와 일치 |

가상 카메라 4개(= `view` 값): `front` 0°, `three_quarter` 45°, `side` 90°, `back` 180°.

### 2-3. 정규화 피처 (검색과 refine이 **공유**)

`normalize_skeleton(keypoints(17,2), scores(17)) → feature(34,) float32`

1. **힙 중심 이동**: 좌우 hip 중점을 원점으로
2. **스케일 정규화**: 몸통 길이(어깨중점–힙중점 거리)로 나눔
3. **결측 마스킹**: `score < 0.3`인 관절은 좌표를 0으로

→ 카메라 거리·인물 크기에 불변. `(17,2)`를 flatten해 `(34,)`.

> ⚠ **float32다.** 이 사실이 나중에 최적화 버그의 원인이 된다(§6-1).

### 2-4. 뼈(bone) 정의 — 12개

```
팔:   (5,7) (7,9)      좌 상완·전완
      (6,8) (8,10)     우 상완·전완
다리: (11,13) (13,15)  좌 대퇴·정강
      (12,14) (14,16)  우 대퇴·정강
몸통: (5,6) 어깨선  (11,12) 골반선  (5,11) (6,12) 몸통 측면
```

`bone_dirs(feature) → (dirs(12,2), valid(12,))` — 각 뼈의 **2D 단위 방향**과 유효 마스크.
양 끝점 중 하나라도 마스킹(0)됐으면 그 뼈는 무효.

### 2-5. 거리 함수

| 이름 | 정의 | 성질 |
|---|---|---|
| `pose_distance` | 정규화 공간에서 몸통 12관절 **위치 L2 평균** | 비율 차이에 페널티(웹툰 과장에 불리) |
| `angle_distance` | 양쪽 다 유효한 뼈에 대해 **mean(1 − cos θ)** | **길이 불변**, 결측 뼈 자동 제외 |
| `hybrid` | 가중 결합 | — |

환경변수 `DISTANCE`로 선택. **refine과 목적함수를 일치시키려면 `angle` 권장.**
잘린 다리 등 결측이 많은 컷에서는 `angle`이 명확히 유리하다(무효 뼈를 자동으로 뺌).

## 3. 파이프라인 (검색까지)

```
컷 PNG
 │
 ├─[1] VLM 1회 호출 → {사람 수, shot, 대략 박스}
 │      · shot ∈ {full_half, bust, face}
 │      · ⚠ VLM은 관절 좌표를 절대 생성하지 않는다
 │
 ├─[2] 라우팅: face→skip(종료) / bust→검색 스킵 / full_half→계속
 │
 ├─[3] 검출 + 개수 보정
 │      · reconcile: 검출기 사람 수 vs VLM 사람 수 이진 일치 → high/low
 │      · 모델 score는 스케일이 제각각이라 신뢰도로 못 씀 → 개수 일치를 신호로 사용
 │
 ├─[4] 포즈 추정(RTMPose Body) → 인물별 (17,2) + scores(17)
 │
 ├─[5] 피처화: normalize_skeleton (§2-3)
 │
 └─[6] 검색: 기하 kNN
        · 라이브러리 = 포즈 1510개 × view 4 ≈ 투영 6040개
        · 태그로 필터링하지 않는다(기하와 중복이라 설계상 제외)
        · 같은 pose_id의 여러 view 중 최선 1개만 남겨 후보 다양성 확보
        · Top-1 거리 > FALLBACK_DISTANCE(0.45) → 저신뢰 '폴백'(작가 직접)
```

출력 `CutResult`: 인물별 `{box, tags, candidates[Top-K], keypoints(17,2), scores(17)}`.
`keypoints`/`scores`를 응답에 싣는 이유는 refine을 **순수 함수**로 만들기 위해서다
(클라이언트가 그대로 되돌려주면 러프 재전송·포즈 재추론이 없다).

## 4. refine — 문제 정의

### 4-1. 입력/출력

```
입력: base_bvh (검색으로 고른 1개), rough_kp2d(17,2), scores(17), view
출력: 조정된 1프레임 BVH  또는  베이스 원본 그대로
```

**핵심 약속: "좋아지거나, 그대로."** 안전 게이트 중 하나라도 걸리면 베이스를 반환한다.
refine이 결과를 나쁘게 만드는 경로는 존재하면 안 된다.

### 4-2. 파라미터 (무엇을 푸는가)

**BVH 관절의 오일러 회전각(degree)만.** 루트/힙 **위치는 절대 고정.**

| 사지 | 푸는 관절 | 파라미터 |
|---|---|---|
| left_arm | LeftArm(어깨), LeftForeArm(팔꿈치) | 2관절 × 3채널 = 6 |
| right_arm | RightArm, RightForeArm | 6 |
| left_leg | LeftUpLeg(고관절), LeftLeg(무릎) | 6 |
| right_leg | RightUpLeg, RightLeg | 6 |

고정: 손목/손, 발목, 척추, 목/머리, 쇄골. (러프에서 노이즈로 그려져 잘못된 신호를 줌)

### 4-3. 전방 계산 (forward)

```
파라미터 θ
 → FK(BVH 계층) → 3D 관절
 → coco17 매핑(관절명 접미사 기준, 힙 중심 이동)
 → 매칭 view로 투영 + y 반전
 → normalize_skeleton            ← 라이브러리 색인과 동일 함수 (불변식)
 → bone_dirs → 2D 뼈 방향 (12,2)
```

### 4-4. 손실

```
L(θ) = Σ_bone w_b · (1 − cos(θ_proj_b , θ_target_b))  /  Σ w_b        # 활성 뼈만
     + Σ_k λ_k · ((θ_k − θ_k^base) / 30°)²                            # 베이스 정규화
     + Σ_i λ_i^svd · (v_iᵀ(θ − θ^base) / 30°)²                        # §5-2
```

최소제곱 형태로 풀며, `‖d_cur − d_tgt‖² = 2(1 − cos)`이므로 잔차와 손실 척도가 일치한다.
보고되는 손실은 `mean(1−cos)`으로, **검색의 `angle_distance`와 같은 척도**라 비교 가능하다.

바운드: `θ^base ± 45°` (채널당 하드 바운드).

### 4-5. 최적화

- scipy `least_squares`(TRF, 바운드) → 없으면 **numpy 전용 LM 폴백**(코어 의존성=numpy 원칙)
- 수치 야코비안. **`diff_step`을 반드시 명시**해야 한다 — 이유는 §6-1

## 5. refine의 근본 난점과 대응

### 5-1. 근본 난점 (모든 실패의 단일 원인)

> 손실은 **매칭된 view 하나의 2D 뼈 방향**만 본다.
> 2D는 3D 자세를 부분적으로만 구속한다 → **투영에서 관측되지 않는 자유도는 "공짜"로 움직인다.**
> 매칭 view에선 좋아 보이는데 3D로는 이상해진다. CSP는 3D라 작가가 인형을 돌리는 순간 드러난다.

대표 사례: **뼈 자기 축 회전(비틀림).** 상완을 자기 축으로 돌리면 투영된 뼈 방향이 **전혀 안 변한다.**
손실은 0을 보고하지만 팔꿈치가 향하는 방향과 그 아래 전완·손이 통째로 돌아간다.
→ "각도는 맞는데 자연스럽게 이어지지 않는" 팔.

**관측 감도** 정의: `감도 = |ΔL| / Δ(3D 이동량, 몸통 길이 정규화)`. 낮을수록 위험.

실측(무작위 표본):

| 측정 | 값 |
|---|---|
| 감도 중앙값 | 팔 0.78 · **다리 0.28** |
| 다리 감도 분포 | 10%: 0.08 ~ 90%: 0.60 (**8배 범위**) → 컷마다 다름 |
| 팔 **한 관절 안** 축별 편차 | 중앙값 **14배** (최대 3444배) |
| σmin/σmax가 축 최소비의 1/10 미만 | **24%** → 못 보는 방향이 **축 조합**인 경우 |

마지막 줄이 중요하다: 관측 불가 방향이 항상 오일러 축 하나에 정렬되지는 않는다.

### 5-2. 대응 (구현됨)

| 층위 | 이름 | 방법 |
|---|---|---|
| 사지 | **가시성 동결** | 러프에서 그 사지의 뼈가 하나라도 무효면 사지 전체를 베이스로 고정 |
| 사지 | **관측 감도 게이트** | 사지별 감도를 측정해, 그 컷에서 최고 사지 대비 34% 미만(또는 절대 0.10 미만)이면 동결 |
| 축 | **P1a 축별 λ** | `λ_k = clip(base_λ /(감도_k + ε), λ_min, λ_max)` — 안 보이는 축을 베이스에 고정 |
| 방향 | **P1b SVD λ** | 야코비안 SVD의 **작은 특이값 방향** `v_i`에 정규화. 축에 정렬되지 않은 null 방향까지 덮음 |
| 전역 | **P2 이동량 게이트** | 사지별 3D 이동량 검사(평균/말단 최대). 초과 사지는 베이스로 되돌림 *(기본 OFF, 개발 중)* |
| 전역 | **P3 충돌 게이트** | 몸통을 캡슐 코어로 근사, 팔이 새로 관통하면 그 사지를 되돌림 |

> **감도 측정 시 섭동 크기는 자유 파라미터가 아니다.** 목적함수가 float32라 1e-6° 이하 섭동은
> 변화량이 정확히 0이 된다. 현재 10°. 하한 ~1e-2°.

### 5-3. 분리성 (설계상 중요한 성질)

기본 모형에서 **문제는 사지별로 완전히 분리된다**:
왼팔 파라미터는 왼팔 뼈 잔차에만 영향, 손실은 뼈별 합, 바운드·P1a λ는 대각, 루트·척추 고정.

따라서 **"한 사지를 되돌리고 나머지를 재계산"해도 같은 값이 나온다** — 재계산은 불필요하다.
단, 아래 둘은 분리성을 깬다:

- **P1b SVD를 전체 파라미터에 대해 한 번에 돌리면** 특이벡터가 사지를 섞는다.
  (수학적으로 J는 사지 기준 블록 대각이라 섞이면 안 되지만, 블록 간 특이값이 근접할 때
  numpy가 축퇴 부분공간에서 임의 회전을 고른다. 실측: 모드의 9%, 최대 50:50)
  → **사지별 블록 SVD**로 계산하면 해소된다.
- **P3 충돌 항**은 물리적으로 사지를 결합한다. 이건 진짜 결합이므로 되돌린 뒤 재검사가 필요하다.

### 5-4. 안전 게이트 (하나라도 걸리면 베이스 반환)

| reason | 뜻 |
|---|---|
| `disabled` | `REFINE_ENABLED=0` 비상 스위치 |
| `low_skeleton_score` | 러프 스켈레톤 자체가 신뢰 불가 |
| `base_mismatch` | 검색 Top-1 거리 > 임계 → **검색이 실패한 컷엔 refine을 돌리지 않는다** |
| `multiframe_base` | 멀티프레임 베이스(조용한 프레임 손실 방지) |
| `insufficient_target_bones` / `low_observability` | 맞출 뼈·관측 가능한 사지가 없음 |
| `already_matched` / `no_gain` / `global_no_gain` | 개선 여지 없음 또는 개선 부족 |
| `movement_gate` | P2 이동량 초과 |
| `collision_gate` / `collision_unresolved` | P3 충돌 |
| `joint_limit` | 팔꿈치·무릎 과굴곡 |
| `diverged` | 최적화 실패 |

`base_mismatch`가 특히 중요하다: **refine은 틀린 베이스를 못 살린다.**
검색이 실패했는데 억지로 맞추면 베이스보다 이상해진다. 그건 **라이브러리 커버리지 문제**다.

## 6. 실패에서 배운 것 (같은 실수 반복 금지)

### 6-1. scipy가 조용히 아무것도 안 한 사건

scipy `least_squares`의 기본 유한차분 보폭은 **상대 ~1.5e-8**이다. 그런데 목적함수가
float32로 양자화되어(§2-3) 그 크기의 섭동에서는 손실 변화가 **정확히 0.0**이 된다.
→ 야코비안 전부 0 → "기울기 0 = 이미 최적" 판단 → **nfev=1로 시작점 반환** →
조정을 안 했는데 `no_gain`("개선 여지 없음")으로 보고.

| | nfev | 손실 |
|---|---|---|
| 기본 보폭 | **1** | 1.0842 → 1.0842 |
| `diff_step=1e-1` | 164 | 1.0842 → 0.0037 |
| numpy 폴백(보폭 1e-2) | 781 | 1.0842 → 0.0032 |

scipy 유무에 따라 결과가 갈렸고, **아무것도 안 한 것이 정상 판정처럼 보였다.**
조치: `diff_step` 명시 + `nfev ≤ 2`면 폴백으로 전환 + **두 백엔드 판정 일치 테스트** 추가.

### 6-2. 검증이 문제를 볼 수 없게 생겨 있었다

1. **단일 view만 렌더했다.** 손실이 그 view만 보는데 그 view만 그리면 당연히 좋아 보인다.
   → 4개 view 진단 도구 필수. 단일 view 스크린샷 판정 금지.
2. **"악화 0건" 지표가 순환논법이었다.** 독립 지표라던 `angle_distance`가 refine이
   최소화하는 값과 같은 척도였다. → 독립 지표는 **3D 이동량·해부학·다른 view**여야 한다.
3. **합성/라이브러리 BVH를 쿼리로 쓴 검증**은 노이즈가 없어 실패를 못 본다. 실 러프 필수.

## 7. 설계 불변식 (수정 시 반드시 지킬 것)

1. **VLM은 좌표를 생성하지 않는다.** 사람 수·shot 같은 제어 신호만. 관절은 검출기·포즈 모델 몫.
2. **피처 공간 대칭성.** 쿼리(추출 스켈레톤)와 라이브러리(3D→2D 투영)가 **같은 정규화 함수**를
   통과해야 kNN이 성립한다. refine의 전방 계산도 이 함수를 공유한다. 한쪽만 바꾸면 조용히 망가진다.
3. **개수 일치 = 신뢰도 신호.** 모델 score는 스케일이 제각각이라 신뢰도로 쓸 수 없다.
4. **매칭은 순수 기하.** 태그로 필터링하지 않는다(기하와 중복).
5. **refine은 좋아지거나, 그대로.** 게이트를 약화시키는 방향으로 바꾸지 않는다.
6. **refine은 검색의 대체재가 아니다.** 베이스가 틀리면 게이트가 막는다.
7. **BVH 쓰기는 HIERARCHY 원문을 그대로 복사**하고 MOTION만 교체한다. 계층·OFFSET(뼈 길이)을
   재직렬화하지 않으므로 하류(CSP 좌표 보정)가 영향을 받지 않는다.

## 8. 현재 상태

| | 상태 |
|---|---|
| 검색 파이프라인 | 동작. 라이브러리 1510포즈 / 투영 6040개 |
| refine 코어 + 게이트 | 동작 |
| P1a 축별 λ · P1b SVD λ | 구현됨 (P1b는 전역 SVD — 블록화 검토 중) |
| P2 이동량 게이트 | **구현 중, 기본 OFF** |
| P3 충돌 게이트 | 구현됨 |
| 다리 조정 | 기본 `REFINE_LIMBS=arms`(팔만). 감도 게이트로 조건부 확장 가능 |
| 실 러프 대규모 눈검수 | **미완** |
| export 주문서에 조정본 연결 | **미완**(현재 `/export-order`는 베이스 URL만 반환) |

### 미해결 / 논의 중

1. **P2 임계값**(평균 0.20 / 말단 최대 0.35 몸통 길이)은 실 러프로 보정 필요.
   라이브러리 커버리지에 종속되므로 **라이브러리 정리 이후**에 잡아야 한다.
2. **P1b를 사지별 블록 SVD로 바꿀지** — 바꾸면 분리성이 복원되어 P2가 단순해진다.
3. **감도는 베이스 포즈의 국소 성질**이라 최적화가 움직이면 달라진다. λ를 고정하는 것이
   과한 제약이 될 수 있다.
4. **가장 우선하는 것은 refine이 아니라 검색 품질**(라이브러리 커버리지·중복 정리).
   베이스가 좋아지면 refine이 할 일 자체가 줄고, P2 임계값도 그때 잡아야 제대로 잡힌다.

## 9. 용어

| 용어 | 뜻 |
|---|---|
| 러프(rough) / 컷 | 작가가 그린 콘티 그림 1장 |
| 베이스(base) | 검색으로 찾은 라이브러리 3D 포즈. refine의 출발점 |
| view | 4개 가상 카메라 각도 중 하나. 검색이 함께 반환 |
| 관측 감도 | `|ΔL| / Δ3D이동량`. 낮으면 손실이 그 방향을 못 본다 |
| 게이트 | 조정을 폐기하고 베이스를 반환하는 안전 조건 |
| 사지(limb) | left_arm / right_arm / left_leg / right_leg |
| 몸통 길이 | 어깨중점–힙중점 거리. 모든 3D 이동량의 정규화 단위 |
