## 출처와 검수 근거

- CMU 원본 캡처 기반 209개, 직접 설계한 상황 포즈 44개.
- [CMU Graphics Lab](https://mocap.cs.cmu.edu/) 공식 ASF/AMC 자료를 사용했다. 제품에 포함하는 사용 조건과 데이터 자체 재판매 제한을 기록한다. [Acclaim 포맷 문서](https://graphics.cs.cmu.edu/nsp/course/cs229/info/ACCLAIMdef.html)를 기준으로 단위, 회전 축, 계층을 처리한다.
- 직접 설계는 기존 Quaternius CC0 리그를 이용했다. 캡처 결과나 러프에서 추출한 포즈로 표시하지 않는다.
- ASF/AMC 어댑터는 좌표·고정축 FK를 검증하고, 1프레임 BVH의 외부 몸 관절 좌표 오차를 검사한다. 척추 회전을 분산하고 팔꿈치 방향을 정리한다.
- CMU 손가락 채널을 실제 캡처로 오인하지 않는다. 양손 30개 손가락 관절과 기본 손 모양을 합성했다. 직접 설계본은 상황별 손 프리셋을 쓴다. 식기·공·악기·의자 등 실제 소품은 포함하지 않으며 정밀한 소품 접촉은 별도 작업이다.
- 도달 불가능한 직접 설계 목표 44개는 리그의 실제 팔·다리 길이에 맞게 고쳐 다시 생성했다. 피부 교차만 있는 후보는 원본을 보존한 별도 배치에서 팔 회전을 보정했다. 보정 후에도 검사에 걸린 것은 채택하지 않았다.
- [기존 검수 기준](POSE_REVIEW_STANDARD.md)을 완화하지 않았다. 1프레임·유한 수치·관절 매핑·손가락 30개·허리·팔꿈치·피부 교차·렌더 해시를 확인했다. 남은 경고를 면제한 포즈는 없다.
- Master V2 실제 캐릭터의 정면·45도·측면·후면을 직접 보고 손·발 지지, 관절·허리, 몸통 관통, 동작 구분을 확인했다. 원본 소스 전체를 다 본 것으로 주장하지 않으며, 보지 않은 후보는 대기 상태다.
- 기존 1,709개와 신규 상호 간 골반 중심·몸통 길이로 정규화한 관절 RMS 거리 0.17 미만을 제외했다. 수치가 통과해도 시각적으로 반복되는 준비·회복 자세는 제외했다. 좌우 반전이나 손 모양만 바꿔 수를 늘리지 않았다.
- 실제로 시각 검수한 준비 후보 545개 중 우선 선택 257개에서 최종 중복 4개를 더 제외해 253개를 확정했다.

## 재현과 다음 확장

소스 변환(`sources/acclaim.py`, `sources/cmu_static.py`), 후보 추출(`expansion/cmu_pool.py`), 중복 선택(`expansion/selection.py`), 보정(`expansion/clearance.py`)을 분리했다. 다운로드는 Windows 인증서 저장소를 사용하며 TLS 검증을 끄지 않는다. 캐시는 원본 해시·설정·추출 개수·변환 코드가 바뀌면 재사용하지 않는다. 이 회차의 초기 풀은 캐시 식별 강화 전 생성본이므로 재현 시 새 출력 폴더를 사용한다.

```powershell
# 공식 원본 다운로드 또는 해시가 일치하는 캐시 확인
scripts/download_cmu_curation.ps1 -Config config/pose_expansion_cmu_20261008.json
scripts/download_cmu_curation.ps1 -Config config/pose_expansion_cmu_20261008_gaps.json

# 새 출력 폴더에서 후보 생성. 승인이나 게시를 수행하지 않는다.
.venv/Scripts/python.exe -m pose_curation.expansion.cmu_pool --source data/curation/sources/cmu --config config/pose_expansion_cmu_20261008.json --output <새-풀-폴더> --count 14 --workers 4
.venv/Scripts/python.exe -m pose_curation.expansion.selection --manifest <새-풀-폴더>/manifest.json --batch <새-배치-폴더> --database <동결한-기준-DB> --minimum-distance 0.17 --per-clip 9 --limit 300
.venv/Scripts/python.exe -m pose_curation render --batch-dir <새-배치-폴더> --blender <blender.exe> --character data/curation/characters/standin-master-v2.fbx --workers 4
.venv/Scripts/python.exe -m pose_curation qa --batch <배치-ID> --output <검수-출력>
```

시각 검수를 마친 현재 파일만 검수 서버에서 채택한다. 최종 후보 전체끼리 중복을 다시 비교하고, `python -m pose_curation publish`로 로컬 검색 DB를 만든다. 검수 기록은 BVH와 4방향 이미지 해시에 묶이며, 파일을 수정하면 보정·렌더·검수를 다시 해야 한다. `data/`의 원본·BVH·DB·미리보기·검수 자료는 Git에 넣지 않는다.
