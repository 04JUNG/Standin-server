# 2026-10-07 포즈 대량 확장

이번 회차는 직전 정리 라이브러리 1,584개를 기준으로 **125개를 추가해 1,709개**가 됐다.
직전 회차의 22개는 이 숫자에 포함하지 않는다. 신규 포즈는 모두 단일 프레임이며
양손 30개 손가락 관절, Master V2 캐릭터의 정면·45도·측면·후면 렌더와
현재 검수 정책에 묶인 승인을 갖는다.

|---|---:|---|

| 일상 | 23 | 앉아서 기지개·하품·몸 숙이기, 빨래 널기, 낮은 곳 작업, 짐 들기, 기어가기 |

125개는 렌더 후보 수가 아니라 수동 시각 검수와 최종 중복 검사를 통과한 수다.
파일·화면별 검수 대상은 `config/pose_mass_review_20261007.json`에 기록한다.
이 파일은 실제로 살펴본 렌더의 BVH·썸네일 해시를 기록한 검수 결과이며,
다른 파일 버전에 자동으로 적용하는 승인 목록이 아니다.

## 부족한 동작을 찾는 방법

기존 DB의 이름·태그 집계에서 농구·배구·라켓 스포츠·겨울 스포츠가 적었고,
히어로·이능력 및 바닥 생활 동작의 명시적 분류도 적었다. 기존 1,350개는
카테고리 태그가 없으므로 이름 검색의 0건을 실제 자세 부재라고 판단하지 않는다.
이 집계는 조사 우선순위만 정한다. 최종 후보는 분류 유무와 관계없이 기존
1,584개의 실제 BVH와 모두 대조한다.

중복 특징은 골반 중심, 몸통 길이로 정규화한 어깨·팔꿈치·손목·골반·무릎·발목
좌표다. 수평 회전만 정렬하고 기울기와 뒤집힘은 유지한다. 손가락·소품만 다른
자세로 수를 늘리지 않는다. 후보 선택에서 몸통 단위 RMS 0.15, 최종 선택에서
기존 전체와 신규 상호 간 0.17 미만을 제외했다. 숫자 기준에 더해 시각적으로
반복되는 준비·회복 프레임과 좌우 반전도 제외했다.

  낮은 드리블은 세 번째 시안에서 채택했지만, 발의 접지가 불분명한 바닥 앉기는

- 큰 척추 회전이 한 관절에 몰린 Quaternius 후보 50개는 기존 척추 분산 보정을

## 다음 회차 실행

`pose_curation/expansion/`은 조사 집계, 소스별 후보 생성, 기존 전체와의 중복
선택을 담당한다. 기존 렌더·검수·게시 모듈은 계속 사용한다. 새 회차마다 현재
게시 DB를 SQLite backup으로 고정하고 새 출력 디렉터리와 배치 ID를 사용한다.

```powershell
# 이름·태그 집계: 실제 자세 커버리지 판정과 구분한다.
.venv/Scripts/python.exe -m pose_curation.expansion.inventory --database <baseline.db> --families config/pose_mass_gap_families_20261007.json --out <inventory.json>

# 라이선스가 확인된 로컬 소스로 독립 후보 풀을 생성한다.
.venv/Scripts/python.exe -m pose_curation.expansion.accad_pool --source data/curation/sources/accad/bvh --output <accad-pool> --config config/pose_mass_accad_20261007.json --workers 4 --count 5
.venv/Scripts/python.exe -m pose_curation.expansion.scenario_pool --config config/pose_mass_scenarios_20261007.json --output <scenario-pool>

# 한 번 검수한 소스 프레임·ID를 제외하고 신규 몸 자세를 고른다.
.venv/Scripts/python.exe -m pose_curation.expansion.selection --manifest <pool/manifest.json> --batch <new-batch> --database <baseline.db> --minimum-distance 0.15 --per-clip 4
.venv/Scripts/python.exe -m pose_curation render --batch-dir <new-batch> --blender <blender.exe> --workers 2
```

이후 4방향 시각 검수 → 보정 또는 제외 → 재렌더 → 신규 상호 중복 검사 → 정확한
해시의 승인 기록 → `qa --scope accepted` → `publish` → `scoped-build` 순서다.
수정으로 BVH나 썸네일이 달라지면 이전 승인은 재사용하지 않는다. 검수 전후
DB ID 집합을 비교해 기존 포즈가 보존되고 채택한 포즈만 증가했는지 확인한다.

Windows 렌더 결과 JSON의 원자적 교체 중 발생한 일시적 파일 잠금은 최대
5회·0.1초 간격으로 재시도한다. 영구 오류는 계속 실패 처리하고, 재시작하면
이미 유효한 렌더를 재사용한다.

BVH·이미지·원본 소스는 Git에 넣지 않는다. 레시피·출처 해시·검수 결과와 코드를
추적하고, 검수 통과 자산은 번들로 배포한다. 스테이징 번들은 기존 개인정보
필터·리그 호환 검사·재생 게이트를 동일하게 통과해야 한다.

- 반신 대표 256개, 흉상 대표 96개를 1,709개 소스에서 다시 선정했다.
  검수 서버의 두 범위 API도 각각 256·96개를 반환했다.
- 확장·시나리오·검수·게시 관련 테스트 39개 통과. 이후 누락 관절 입력 검사를
  보강한 확장 모듈 테스트 4개를 다시 실행해 통과했다.
- 스테이징 전용 복사본에서 기존 비공개 ID 1개를 제외해 1,708개·6,832개 투영을
  만들었다. 로컬 원본에서 이 기존 포즈를 삭제한 것은 아니다.
- 고정 러프 145개 재생에서 개선 2개, 회귀 0개, 고위험 경계 악화 0개였다.
  새 125개 각각에 반전 복제본을 강제로 만들지 않도록 mirror closure만 명시적으로
  면제했다. 원본 손·지지 방향을 보존하고 중복을 늘리지 않기 위한 선택이며,
  관절·피부 관통·자산 누락·검색 쏠림·재현성 검사는 면제하지 않았다.
  이 재생 세트가 모든 새 스포츠 상황의 검색 성공을 보장하지는 않는다.
- 스테이징 번들 버전: `lib-20261006-3be087bb` (버전 날짜는 UTC 기준).
  아카이브 SHA-256: `d1774e7728b89a134cf470dba8f9ceb19797058a4d8d0144ed9c53c62f636c64`.
  업로드 전 기존 버전 확인과 ETag 조건부 쓰기를 사용했고 직전 버전을 롤백용으로 보존했다.

확실한 바닥 앉기다. 이번 후보는 검수에서 제외했으므로 이름만 붙여 채운 것으로
계산하지 않는다. 사용자 러프 이미지의 추가 다운로드는 수행하지 않았다.
