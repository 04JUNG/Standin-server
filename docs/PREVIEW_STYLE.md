# 미리보기 스타일

기존 라이브러리의 회색 배경과 부드러운 무광 캐릭터를 기준으로 한다.
미리보기의 조명은 포즈·카메라 정렬·신체 범위·FBX 변환과 별도로 관리한다.

- `converter/preview_style.py`: 색 관리, 배경, Blender 스타일 적용.
- `converter/preview_studio.sl`: 기존 검수 스튜디오의 주변광과 두 광원.
- 검수 서버의 전신·반신·흉상·두상과 변환기의 각도 보정 PNG는 같은
  Workbench 설정을 쓴다. Standard 색 변환, 흰색 단색 재질, cavity/specular 끔.
- EEVEE/Cycles의 조정본 썸네일과 클라이언트의 빠른 후보 렌더는 카메라 좌표의
  두 확산광과 주변광을 사용한다. 물체 크기·원본 PBR 재질·면 광원의 거리에 따른
  암부를 없애고, Workbench에 맞춘 0.72 밝기 계수를 적용한다. 엔진의 조명 계산과
  안티앨리어싱이 달라 픽셀 단위로 동일한 이미지를 보장하지는 않는다.
- 클라이언트 후보 목록과 저장 전 최종 모델 미리보기가 같은
  `preview/previewStyle.ts`의 광원·감쇠 식을 사용하며
  `previewStyleContract.ts`의 스타일 버전이 후보 이미지 캐시 키에 들어간다.
  이 버전 모듈은 Three.js를 import하지 않아 지연 로딩을 유지한다.

캐릭터·BVH·GLB 정점·카메라 행렬·메시 절단은 바꾸지 않는다. GLB의 재질을
화면에서만 대체하므로 기존 모델 자산을 다시 굽거나 업로드할 필요가 없다.
Blender도 최종 FBX를 읽은 후 미리보기용 재질만 적용하며 FBX를 다시 저장하지 않는다.

검수 이미지 캐시는 스튜디오 파일과 공통 Python 모듈의 해시로 갱신한다.
기존 검수 기록과 과거 렌더는 지우거나 새로운 렌더의 승인 기록으로 복제하지 않는다.
스타일이 이미 맞는 정적 라이브러리 번들은 유지한다. 새로운 정적 이미지가 필요한
경우 기존 render → 시각 검수 → publish 절차로 새 썸네일 해시를 검수해야 한다.

## 2026-10-09 로컬 확인

- 현재 배포 번들 1,967포즈의 정적 썸네일 7,868개를 검사했다.
  네 모서리의 평균 배경값은 152 또는 153이며 다른 배경 스타일은 없었다.
  이 검사는 배경 검사이며 모든 자세의 시각 품질을 새로 승인한 것은 아니다.
- 카메라 보정 전신 3개와 반신·흉상·두상 FBX에서 미리보기를 다시 생성했다.
  전신 3개의 원본 FBX SHA-256은 변경되지 않았다.
- 실제 클라이언트 렌더러로 후보 5개를 브라우저에서 표시했다.
  2개를 이미지로 직접 확인하고 과도한 밝기를 한 차례 낮췄다.
- 검증 자료: `data/curation/preview-style-20261009/`.
- CI에서 구 표면을 실제로 렌더하고 정면이 배경보다 밝고 하이라이트가
  잘리지 않는지 검사한다. 조명 방향이 뒤집히는 회귀를 탐지한다.

스테이징 앱에는 클라이언트 빌드와 변환기 배포 후 적용된다. BFF의 기존 PNG 캐시는
메모리에 최대 10분 남으므로 배포 시 재시작하거나 만료 후 확인한다. 로컬 검수
서버는 코드 변경 후 재시작해야 한다.
