# 포즈 미세조정 (Refine) 설계 — MVP판

> **담당**: 도원 (VLM→검색 추론 서버) · **상태**: P3a까지 구현·실 러프 3장 회귀 완료
> **개정**: 2026-08-01 — P1 관측 정규화 + P2 사지별 3D 이동량 게이트 추가
> **한 줄**: 검색된 라이브러리 포즈를 **러프에 맞춰 자동 미세조정**한다. 작가는 후보만 고르면 되고, 관절 조정은 서버가 한다.

---

## 0. 배경 / 목적

스튜디오가 "디테일한 포즈 조정"을 요구. 검색은 **닮은** 포즈를 찾아주지만 러프와 **정확히 같지는 않다**(상체는 맞는데 팔 각도가 다르다 등). 이를 **자동으로**, **작가 워크플로우를 건드리지 않고** 맞춰준다.

- **자동 (a)**: 작가가 관절을 직접 만지지 않는다. 서버가 조정한다.
- **선택한 포즈만**: Top-K 전부가 아니라, 작가가 **고른 1개**만 정제(연산 최소, 커밋된 포즈만).

### 0-1. 왜 지금인가 (파인튜닝·LLM과 구분)

refine을 "나중에 할 고급 기능"으로 분류하면 오판이다. 셋은 성질이 다르다.

| | 필요한 것 | 시연까지 가능? |
|---|---|---|
| **refine (이 문서)** | scipy 고전 최적화. 학습 없음, API 키 없음, 포즈당 수십 ms, 결정론적 | ✅ 가능 |
| 파인튜닝 | 러프↔정답포즈 **라벨쌍 데이터셋**. 지금 0건 | ❌ 수개월 |
| LLM으로 관절 조정 | — | ❌ **금지**. VLM은 좌표를 생성하지 않는다(`CLAUDE.md` 불변식 1) |

즉 refine은 **MVP에 들어갈 수 있는 유일한 "조정" 수단**이며, 스튜디오가 요구한 바로 그 기능이다.
파인튜닝·LLM 경로는 이 문서 범위 밖(`ROADMAP.md` 보류 항목으로 유지).

## 1. 접근 — 검색 + 2D 유도 정제 (retrieval + refinement)

| 요소 | 역할 |
|---|---|
| **베이스** | 검색된 3D 포즈(BVH). 해부학적으로 유효하고 **깊이(depth)를 제공** → 2D의 깊이 모호성 해소 |
| **타깃** | 러프에서 추출한 2D 스켈레톤 |
| **정제** | 베이스의 관절 회전을 **조금씩 돌려**, 매칭 뷰로 투영한 2D가 **러프의 뼈 방향과 일치**하도록 |

- **각도(뼈 방향) 기준**으로 맞춘다 → 웹툰 과장 비율에 강함. 뼈 길이는 CSP 데생 인형 비율 유지.
- **베이스에 정규화** → 큰 변형이 아니라 "미세조정". 자연스러움 유지, 포즈 안 깨짐.

> 핵심: 러프는 깊이가 없어 혼자선 3D를 못 정한다. **검색 포즈가 깊이를 + 러프가 2D 실루엣을** 주니, 둘을 합치면 "이 러프와 같은 3D 포즈"가 나온다.

### 1-1. 검색 metric과 목적함수를 일치시킨다

`features.angle_distance` / `features.bone_dirs`가 이미 구현되어 있다(`DISTANCE=angle` 토글).
refine의 각도 손실은 **이 함수를 그대로 재사용**한다. 검색이 최소화한 값과 refine이 최소화하는 값이 같아야
"검색이 고른 1등을 refine이 더 좋게 만든다"가 성립한다. 두 목적함수가 갈라지면 refine이 검색 순위를
뒤엎는 이상 동작이 생긴다.

→ **시연은 `DISTANCE=angle`로 고정**하고 refine도 각도 손실로 간다. 섞지 않는다.

## 2. 워크플로우 (무손상)

```
러프 → POST /analyze  (후보 Top-K + 인물 스켈레톤)
     → 작가가 후보 하나 선택
     → POST /refine(선택 포즈 BVH, 러프 2D 스켈레톤, 매칭 view)   ← 서버 자동
     → 러프에 맞춰 조정된 BVH → 내보내기 → CSP 데생 인형
```

작가 추가 단계 **0**. 고르는 순간 뒤에서 조정된 BVH가 나온다.

## 4. 알고리즘

### 4-1. MVP 축소판 (시연 범위) — **팔만**

파라미터가 많을수록 발산 확률과 부자연스러움이 같이 올라간다. 시연에서는 **변별에 실제로 기여하고,
2D 투영에서 관측 가능한 관절만** 푼다.

| | 관절 | MVP (`REFINE_LIMBS=arms`) |
|---|---|---|
| 조정 | 어깨, 팔꿈치 | ✅ 푼다 |
| 고정 | **고관절, 무릎** | ❌ 베이스 유지 — §6-4 참조 |
| 고정 | 손목/손, 발목, 척추, 목/머리 | ❌ 베이스 유지 |
| 고정 | 루트/힙 **위치** | ❌ 항상 고정 |

- 러프 콘티에서 변별점은 거의 항상 **팔 각도**다. 손목·목은 2~3px 노이즈로 그려져 잘못된 신호를 준다.
- **다리를 뺀 것은 임시방편이 아니라 측정 결과다.** 다리는 투영 관측 감도가 팔의 **1/3.4**라,
  손실이 거의 못 보는 방향으로 크게 움직인다(§6-4). `REFINE_LIMBS=all`로 켤 수 있으나
  P2 이동량 게이트가 생겼지만 다리는 아직 실사용 평가가 부족하므로 기본값은 팔만 유지한다.

**사지 단위 동결**: 러프에서 그 사지의 뼈가 **하나라도** 안 보이면 그 사지 전체를 베이스로 둔다.
한쪽만 맞추려 들면(예: 무릎은 보이는데 발목은 잘림) 부실한 타깃에 맞추려고 관절이 크게 돈다.

### 4-2. 전방 / 손실

- **전방(forward)**: `bvh.fk(회전각)` → 3D 관절 → `library.project_3d_to_2d(view)` → 2D.
- **손실(loss)**:
  ```
  L = Σ_bone  w_bone · (1 − cos(θ_proj, θ_target))        # 뼈 방향 각도 일치
    + λ · ‖회전각 − 베이스회전각‖²                          # 베이스 정규화(미세조정)
    + 관절한계 페널티                                        # 부자연 방지
  ```
  - **가시성 마스킹**: `scores[j] < MIN_SKELETON_SCORE`인 관절은 `w_bone = 0`.
    러프에서 안 보이는(또는 추출 실패한) 관절을 억지로 맞추면 포즈가 깨진다.
  - 팔·다리 가중(`w_bone`) 조절 가능.
- **최적화**: `scipy.optimize.least_squares`(Levenberg–Marquardt), **max 100 iter**. 포즈당 수십 ms.
- **재사용**: `src/features.py`(`bone_dirs`/`angle_distance`), `src/bvh.py`(`parse_bvh`/`fk`), `src/library.py`(`project_3d_to_2d`).

### 4-3. 안전 게이트 (MVP 필수 — 생략 금지) ✅ 구현됨

시연 중 팔이 뒤로 꺾인 인형이 한 번이라도 나오면 refine이 없는 것보다 나쁘다.
아래 중 **하나라도 걸리면 베이스 BVH를 그대로 반환**한다(`refined=false` + `reason`).

| # | 게이트 | `reason` | 조건 |
|---|--------|----------|------|
| 1 | 비상 스위치 | `disabled` | `REFINE_ENABLED=0` |
| 2 | 타깃 신뢰 불가 | `low_skeleton_score` | 몸통 12관절 mean(scores) < `MIN_SKELETON_SCORE` |
| 3 | 베이스가 틀림 | `base_mismatch` | 검색 Top-1 distance > `FALLBACK_DISTANCE` |
| 4 | 맞출 뼈 없음 | `insufficient_target_bones` | 유효 팔·다리 뼈 < 2개 |
| 5a | 이미 맞음 | `already_matched` | `L_base ≤ REFINE_MIN_LOSS` — 개선 여지가 추출 노이즈보다 작다 |
| 5b | 개선 없음 | `no_gain` | `L_final > L_base * REFINE_MIN_GAIN` |
| 6 | P2 사지 이동량 | `movement_gate` / `ok_partial` | 이동량은 기록하되 현재 하드 게이트는 기본 OFF(사람 평가에서 유용한 큰 조정을 폐기) |
| 7 | P3 새 자기 충돌 | `collision_gate` / `ok_partial` | 베이스보다 새로 깊게 손·전완이 몸통을 관통한 팔만 복구 |
| 8 | 부분 결과 개선 없음 | `global_no_gain` | 사지 복구 후 전체 gain이 다시 기준 미달 |
| 9 | 해부학 | `joint_limit` / `ok_partial` | 새 굽힘각 위반 사지만 복구(베이스가 이미 위반 중이면 면제) |
| 10 | 발산·충돌 불변식 | `diverged` / `collision_unresolved` | 최적화 예외·비유한값 또는 사지 복구 후 충돌 깊이가 예상값과 다름 |

**관절한계는 하드 바운드로도 건다**: 최적화를 `base ± REFINE_MAX_DELTA_DEG`로 제한한다.
소프트 페널티는 "많이 벗어나면 비싸다"일 뿐 벗어나는 걸 막지 못하지만, 바운드는 구조적으로 막는다.

> ⚠ **정정(2026-07-31)**: 이 문서는 한때 "채널당 45° 이내면 붕괴가 나올 수 없다"고 적었다.
> **틀렸다.** 각도 공간의 제약은 3D 공간의 제약이 아니다. 어깨에서 45°면 손목은 몸통 길이의
> 0.7배까지 움직인다(실측). 말단으로 갈수록 누적된다. 바운드는 상한일 뿐 "미세조정"을
> 보장하지 않는다. 현재 P2는 최적화 후 실제 3D 이동량을 재서 과이동 사지만 복구한다.
> 상세 정의와 검증 결과는 `REFINE_P2.md`를 따른다.

이 게이트가 refine을 **"좋아지거나, 그대로"** 로 만든다.

> 게이트 3이 가장 중요하다: refine은 **틀린 베이스를 못 살린다**(§5). 검색이 실패한 컷에
> refine을 돌리면 틀린 포즈를 러프에 억지로 끼워맞춘 더 이상한 결과가 나온다.
> 검색 실패 = refine 스킵 = 작가 폴백.

**실측(2026-07-31, 실 BVH 25쌍 × 4 view)**: 25/25 조정, **검색 척도(12뼈 `angle_distance`)로
악화된 건 0건**, 굽힘각 위반 0건. 손실 감소 예: 0.580 → 0.004.
지연은 numpy 폴백 기준 median 0.91s / p95 1.58s (scipy 설치 시 더 빠름).

### 4-4. 설정값

| env | 기본 | 뜻 |
|---|---|---|
| `REFINE_ENABLED` | `1` | 끄면 항상 베이스 반환(**시연 중 비상 스위치**) |
| `REFINE_LIMBS` | `arms` | `arms`(팔만·기본) \| `all`(다리 포함 — §6-4 읽고 켤 것) |
| `REFINE_MIN_GAIN` | `0.95` | 이 비율보다 손실이 안 줄면 베이스 반환 |
| `REFINE_MIN_LOSS` | `0.01` | 베이스 손실이 이 이하면 손대지 않음(≈뼈당 8°) |
| `REFINE_MAX_ITER` | `100` | 최적화 상한 |
| `REFINE_LAMBDA` | `0.05` | 베이스 정규화 강도. 클수록 덜 움직임 |
| `REFINE_AXIS_OBS` | `1` | P1a 축별 관측 감도 정규화. 저감도 회전축만 더 강하게 베이스에 고정 |
| `REFINE_AXIS_LAMBDA_MAX_MULT` | `100` | P1a 축별 lambda 강화 배수 상한(기존 lambda보다 약화하지 않음) |
| `REFINE_SVD_OBS` | `1` | P1b 축 조합 null-space 정규화. full SVD의 저특이값 방향을 베이스에 고정 |
| `REFINE_SVD_LAMBDA_MAX_MULT` | `2` | P1b 조합별 lambda 강화 배수 상한. 실 러프 3장 Top-5 스윕에서 손 방향 개선과 손목 이동 균형이 가장 좋았음 |
| `REFINE_MOVE_GATE` | `0` | P2 이동량 하드 게이트. 꺼져도 사지별 이동량은 진단값으로 기록 |
| `REFINE_MAX_MOVE_MEAN` | `0.20` | 사지 중간관절·말단 평균 이동량 상한(torso 단위) |
| `REFINE_MAX_MOVE_MAX` | `0.35` | 손목·발목 말단 이동량 상한(torso 단위) |
| `REFINE_COLLISION_GATE` | `1` | P3a 베이스 상대 손·전완-몸통 자기 충돌 게이트 |
| `REFINE_COLLISION_MIN_DEPTH` | `0.05` | 새 깊은 관통의 절대 하한(torso 단위) |
| `REFINE_COLLISION_WORSEN_DELTA` | `0.01` | 베이스 대비 관통 악화 하한(torso 단위) |
| `REFINE_MAX_DELTA_DEG` | `45` | 채널당 베이스 이탈 한계(하드 바운드) |
| `REFINE_MIN_BEND_DEG` | `20` | 팔꿈치·무릎 최소 굽힘각 |

`REFINE_DIR`(조정본 로컬 캐시)는 제거됐다. 조정본은 `POST /refine` 응답의 `bvh`
필드로만 나가고 보관은 소비자가 한다 — `REFINE_HANDOFF.md` §3 참고.

`REFINE_ENABLED=0` 한 방으로 refine 전체를 끌 수 있다. 시연 당일 이상 동작 시 탈출구.

### 4-5. 최적화 백엔드

scipy가 있으면 `least_squares`(TRF, 바운드 지원), 없으면 **numpy 전용 LM 폴백**으로 돈다.
코어 의존성을 numpy만으로 유지하는 원칙(`CLAUDE.md`) 때문이다.

> ⚠ **`diff_step`을 반드시 명시해야 한다(2026-08-01 버그).**
> 우리 목적함수는 `features.normalize_skeleton`을 거치며 **float32로 양자화**된다
> (라이브러리 색인과 같은 함수를 써야 하므로 의도된 것). scipy의 기본 유한차분
> 보폭은 상대 ~1.5e-8인데, 그 크기의 섭동에서는 손실 변화가 **정확히 0.0**이다.
> → 야코비안 전부 0 → scipy가 "기울기 0 = 이미 최적"으로 판단 → **nfev=1로
> 시작점을 그대로 반환** → 조정이 하나도 안 일어났는데 `no_gain`("개선 여지 없음")
> 으로 보고된다. **조용한 실패다.**
>
> | | nfev | 손실 |
> |---|---|---|
> | 기본 보폭 | **1** | 1.0842 → 1.0842 (안 움직임) |
> | `diff_step=1e-1` | 164 | 1.0842 → 0.0037 |
> | numpy 폴백 | 781 | 1.0842 → 0.0032 |
>
> 조치: `_SCIPY_DIFF_STEP=1e-1` 명시 + `nfev ≤ 2`면 `_NoProgress`를 올려 numpy
> 폴백이 받게 함 + 두 백엔드가 같은 판정을 내는지 검사하는 스모크 테스트 추가
> (`test_refine_backends_agree`).
>
> **교훈**: 백엔드가 둘이면 둘을 교차 검증하는 테스트가 있어야 한다. 없으면
> "어느 환경에서 돌렸느냐"에 따라 결과가 갈리고, 더 나쁘게는 **아무것도 안 한 것이
> 정상 판정처럼 보인다.** 이 저장소가 mock 폴백을 프로덕션에서 막는 것(`runtime_guard.py`)과
> 같은 종류의 위험이다.

수정 후 실측(무작위 10쌍 × 4 view): 두 백엔드 판정 **10/10 일치**, 도달 손실도 사실상 동일.
평균 시간 scipy 0.78s / numpy 0.49s(팔만 조정 기준).

## 5. 안전장치 / 한계 (정직하게)

- **베이스 정규화** → 작은 조정만. 러프가 노이즈여도 포즈가 붕괴하지 않음.
- **베이스가 깊이 제공** → 2D 모호성이 폭발하지 않음.
- **가려진 관절**(몸 뒤 팔 등)은 2D에 안 보여 못 맞춤 → **베이스 유지**(합리적).
- **미세조정은 베이스 근처만.** 러프가 라이브러리 어떤 포즈와도 크게 다르면 베이스가 틀린 것 → refine으로 못 살림. 그건 **검색 커버리지 문제**(라이브러리 확충으로 대응).
  - → 그래서 §4-3의 게이트 5번이 있다. **refine은 검색 품질의 대체재가 아니다.**
- 극단 러프는 자동으로 90% 맞추고, 정 필요하면 **CSP에서 손터치**(강제 아님).

### 6-2. 검증 도구 — "하나 골라야 다음으로 못 넘어간다" 문제

실사용은 "고른 뒤 refine"이라, 검증할 때도 하나를 골라야 하는 것처럼 보인다.
하지만 그건 **제품의 제약이지 검증의 제약이 아니다.** 오프라인에서는 연산이 공짜다.

| 도구 | 용도 |
|---|---|
| `scripts/refine_top5.py` | 러프 1장 → **Top-5 썸네일 + Top-5 전부의 조정 BVH** + manifest. 고르기 전에 결과를 다 본다 |
| `scripts/eval_refine_batch.py` | 폴더 단위. 컷마다 컨택트 시트 1장 + `summary.csv` + 이상 신호 트리아지 |
| `scripts/eval_refine.py` | 단건 정밀 확인(베이스·조정·러프 3열) |

배치의 판정 규칙: **WORSE 0건 · BEND 0건**이어야 하고, 검색이 틀린 컷은
`base_mismatch`로 SKIP이 떠야 한다(게이트가 일하고 있다는 증거).
사람은 플래그가 붙은 행과 표본 2~3장만 눈으로 본다.

> `refine_top5.py`는 게이트에 걸린 후보도 **베이스 원본을 복사해 5개 파일을 다 만든다.**
> 고를 때 빈칸이 없어야 하고, "좋아지거나 그대로"가 파일 수준에서도 지켜진다.

### 6-3. 관측: refine 후에는 후보 간 차이가 줄어든다

라이브러리 BVH를 러프 대용으로 넣은 회귀에서, Top-5가 **전부 러프에 거의 같은 정도로
수렴**했다(러프와의 12뼈 거리 0.008~0.013). 베이스는 0.054~0.212로 벌어져 있었는데도.

해석: refine이 잘 돌면 **최종 포즈는 러프가 결정하고, 베이스는 깊이·비율만 공급**한다.
→ 후보 선택의 의미가 refine 전보다 줄어든다.

이것이 **Top-K를 미리 전부 조정해서 보여주지 않는 이유**다. 조정본 5개는 서로 비슷해
보여서 오히려 고르기 어렵다. 작가는 **차이가 남아 있는 베이스로 고르고**, 조정은 그
뒤에 자동으로 받는 편이 낫다(§2 워크플로 유지).

⚠ 단, 위 관측은 쿼리가 깨끗한 라이브러리 BVH일 때의 **최선 케이스**다. 실 러프는
노이즈·과장이 있어 수렴이 약할 것이다. 실데이터 14컷에서 재확인해야 한다.

### 6-4. 실패 진단 — "다리가 부자연스러워진다" (2026-07-31)

작가 사용 중 **"잘되는 것도 있는데 오히려 이상해지는 것도 많다"** 는 보고. 특히 다리.
조사 결과 **검증 방법이 틀렸고, 설계에도 구멍이 있었다.**

#### 검증이 왜 못 잡았나 (내 실수 2건)

1. **단일 view만 렌더했다.** `eval_refine`·`eval_refine_batch`는 매칭된 view 한 각도만 그렸다.
   손실이 그 각도의 2D만 보므로, 그 각도에서 좋아 보이는 건 **당연하다.** 다른 각도에서
   망가졌는지는 구조적으로 볼 수 없었다.
2. **"악화 0건" 판정이 순환논법이었다.** 독립 지표라며 쓴 `angle_distance`는 refine이
   최소화하는 값과 같은 척도다. 당연히 악화가 안 나온다.
   → 게다가 sweep 쿼리가 라이브러리 BVH(깨끗한 스켈레톤)였다. 실제 러프의 노이즈가 없었다.

#### 실제 원인

**(가) 2D 투영은 3D 자세를 부분적으로만 구속한다.** 투영에서 안 보이는 방향으로는 손실이
거의 안 변하므로, 최적화가 그 방향으로 크게 움직여도 "좋아졌다"고 보고된다.

**(나) 다리가 특히 심하다.** 무작위 12쌍 × 4 view 측정 — 관측 감도 = 손실변화 / 3D이동량:

| | 중앙값 | 하위 25% |
|---|---|---|
| 팔 | 0.136 | — |
| **다리** | **0.040** | 0.012~0.020 |

**다리는 팔보다 3.4배 안 보인다.** 이유: ① 선 자세 대퇴는 거의 수직이라 투영 방향이 회전에
둔감 ② 웹툰 컷은 허벅지 아래가 잘려 타깃 자체가 부실. 구조적이지 우연이 아니다.

**(다) 각도 바운드가 3D 이동을 제한하지 못한다.** 실측 사례에서 손목이 몸통 길이의 **0.745배**
이동. §4-3 정정 참조.

#### 조치 (시연 범위)

- **`REFINE_LIMBS=arms` 기본** — 다리를 아예 풀지 않는다. 조치 후 같은 케이스에서 다리
  이동량 0.000, 효율(손실개선/이동량) 1.67 → 4.24.
- **사지 단위 동결** — 타깃 뼈가 하나라도 안 보이는 사지는 통째로 베이스 유지.
- **`scripts/diag_refine_3d.py` 추가** — 4개 view 렌더 + 3D 이동량/효율 표.
  앞으로 refine 변경은 이 도구로 **다른 각도까지** 확인한 뒤 판단한다.

#### 남은 과제 (시연 후, 다리를 다시 켜려면 선행)

1. ~~이동량 게이트~~ — **P2 완료.** 사지 평균·말단 이동량을 따로 검사하고 실패 사지만 복구한다.
2. **3D 이동량 정규화(선택).** 정상 조정이 P2에서 반복 탈락할 때만 검토한다.
3. **자기 충돌 검사(P3).** 이동량이 작아도 팔이 몸통을 관통하는 경우는 P2가 보장하지 않는다.
4. **다시각 손실(선택).** view 하나가 아니라 인접 view에도 페널티를 걸면 깊이 자유도가 줄어든다.

## 7. 스튜디오 데모 프레이밍

**"러프 넣으면 → 후보 → 고르면 → 러프에 맞춰 자동 조정된 3D 포즈."**
데모 화면: **베이스(검색) · 조정(refine) · 러프** 세 개를 나란히 → 조정본이 러프에 더 가까워진 걸 보여준다.

게이트가 걸린 컷은 숨기지 말고 **"이건 라이브러리에 비슷한 게 없어서 조정을 안 했습니다"**로 설명한다.
정직한 실패는 신뢰를 얻고, 억지 조정은 잃는다.
