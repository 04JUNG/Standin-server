# refine 개선 방향 — 정리

> 2026-08-01 · 도원 · 브랜치 `feat/refine-pipeline`
> 지금 당장 할 일이 아니라 **무엇이 문제이고 어떻게 고칠지**를 고정해 두는 문서.

---

## 1. 한 장 요약

**모든 문제가 원인 하나에서 나온다.**

> 손실은 **매칭된 view 하나의 2D 뼈 방향**만 본다.
> 2D는 3D 자세를 부분적으로만 구속한다 → **투영에서 안 보이는 자유도는 공짜로 움직인다.**
> 매칭 view에선 좋아 보이는데 3D로는 이상해진다. CSP는 3D라 작가가 돌리는 순간 드러난다.

같은 원인이 세 가지 입자도로 나타난다.

| 입자도 | 증상 | 상태 |
|---|---|---|
| **사지** | 잘린 다리를 노이즈에 맞추려 헤맴 | ✅ 관측 감도 게이트로 해결 |
| **축·방향** | 팔 방향은 맞는데 비틀려서 부자연스러움 | ❌ **미해결 — 1순위** |
| **전역** | "미세조정"인데 손목이 몸통 0.745배 이동 | P2 계측 유지·하드 게이트 보류 |
| **충돌** | 손·전완이 몸통을 관통 | ✅ P3a 베이스 상대 사지 복구 구현 |

## 2. 측정치 (판단 근거)

| 측정 | 값 | 뜻 |
|---|---|---|
| 관측 감도 = 손실변화 / 3D이동량 | 팔 0.78 · 다리 0.28 (중앙값) | 다리가 3배 안 보임 |
| 다리 감도 분포 | 10%: 0.08 ~ 90%: 0.60 (**8배 범위**) | 컷마다 다름 → 전역 on/off는 틀린 접근 |
| 팔 **한 관절 안** 축별 편차 | 중앙값 **14배**, 최대 3444배 | 사지 단위 게이트로는 못 잡음 |
| 최고축의 20% 미만인 축 | 전체의 **23%** | 이 축들이 "공짜로 움직이는" 구간 |
| 손목 3D 이동(실측 1건) | 몸통 길이의 **0.745배** | 각도 바운드는 3D 이동을 제한 못 함 |

## 3. 개선 방법 (우선순위)

### P1 — 관측되지 않는 자유도를 베이스에 고정  ⭐ 가장 큰 효과

**왜**: 팔이 부자연스러운 원인은 **뼈 자기 축 회전(비틀림)** 이다. 상완을 자기 축으로 돌리면
투영된 뼈 방향이 **하나도 안 변한다** → 손실에게 공짜 → 임의 방향으로 비틀림 → 팔꿈치가
향하는 방향과 그 아래 전완·손이 통째로 돌아간다. **방향은 맞는데 연결이 어색한** 팔.

두 단계로 나눈다. **P1a로 대부분 잡히고, 나머지는 P1b가 필요하다.**

#### P1a — 축별 λ  ✅ 구현

```
λ_k = base_lambda · clip( joint_max_sensitivity / (감도_k + ε),  1,  λ_max_mult )
```

- **clip이 필수다.** 감도가 0에 가까우면 λ가 발산하고, 작은 측정 노이즈가 결과를 지배한다.
- 기존 scalar λ보다 약하게 만들지 않는다(최소 1배). 잘 보이는 축은 기존값 유지,
  안 보이는 축만 최대 `REFINE_AXIS_LAMBDA_MAX_MULT`까지 강화한다.
- 잔차의 정규화 항 `sqrt_lam * (params - base) / _DELTA_SCALE_DEG`에서
  `sqrt_lam`을 **스칼라 → 벡터**로. (`src/refine.py`)

**감도 측정 조건 (고정할 것)**

| 조건 | 값 / 이유 |
|---|---|
| 섭동 크기 | `_PROBE_DEG=5°`. 정리 후 실 러프 3장·Top-5(관절 그룹 60개)에서 1°/5°/10° 비교: 최고축 95%, 최저축·λ≥5x 분류 98.3% 일치. 양자화 여유와 국소성 사이 중간값으로 고정 |
| 방향 | **±양방향 모두** 측정 후 평균. 바운드 근처·비선형 구간에서 한쪽만 보면 왜곡 |
| 3D 이동량 | 몸통 길이(어깨중점–힙중점)로 정규화 |
| 극단값 | clip. 한 축이 전체를 지배하지 않게 |
| 단위 | 전 파라미터 degree 통일(이미 그러함) |

#### P1b — 야코비안 SVD 기저 정규화  ✅ 구현

**측정 결과(팔 관절 49표본)** — "가장 안 보이는 방향"이 축에 정렬돼 있는가:

| | 값 |
|---|---|
| 축 노름이 사실상 0인 표본 | **57%** ← null 방향이 축에 정렬. P1a로 잡힘 |
| σmin/σmax 가 축 최소비와 같은 자릿수 | **61%** ← P1a로 충분 |
| **σmin/σmax 가 축 최소비의 1/10 미만** | **24%** ← **P1a로 못 잡음** |

즉 **네 번에 한 번은 못 보는 방향이 어느 한 축이 아니라 축들의 조합**이다.
그 경우 축별 λ는 각 축을 따로 묶을 뿐, 그 조합 방향은 그대로 열려 있다.

**방법**: 야코비안 `J`의 SVD를 구해 **작은 특이값 방향(vᵢ)에 정규화를 건다.**
잔차에 행 `sqrt(λᵢ) · vᵢᵀ(θ − θ_base)`를 추가하면 된다. λᵢ는 σᵢ에 반비례(clip 포함).
파라미터가 12~24개라 SVD 비용은 무시할 수준.

**강도 실측**: 정리 후 실 러프 3장 Top-5(15개)에서 상한 1/2/5/10/20/50/100x를
스윕했다. `2x`가 손 방향 변화 중앙값을 `39.6° → 36.0°`로 낮추면서 손목 이동
중앙값을 `0.311 → 0.308 torso`로 유지했다. 5x 이상은 2D 적합도 이득 없이 손목
과이동만 늘어 기본값을 `REFINE_SVD_LAMBDA_MAX_MULT=2`로 고정한다.

> 참고: LM(Levenberg–Marquardt)의 감쇠항이 비슷해 보이지만 **다르다.** LM은 *스텝*을
> 감쇠할 뿐 *도착점*을 제약하지 않는다. 우리가 원하는 건 "관측 안 되는 방향으로는
> 베이스에서 벗어나지 마라"라는 **도착점 제약**이다.

**판정**: `diag_refine_3d.py` 4-view + 팔 비틀림이 눈에 띄게 줄었는지.

### P2 — 정규화·게이트를 3D 이동량 기준으로

> 상세 설계와 실측 근거: `docs/REFINE_P2.md`

**무엇**: 지금 정규화는 관절각(°) 기준이라 근위 관절을 과소 페널티한다(어깨 45° = 손목 큰 이동).
3D 이동량 기준으로 바꾸고 **이동량 게이트**를 추가.

**왜**: "미세조정"과 "좋아지거나 그대로"를 **올바른 공간에서** 보장하기 위해.
작가에게 의미 있는 건 "어깨를 20° 돌렸다"가 아니라 "손목이 몸통의 0.3배 움직였다"이다.

**게이트는 두 개를 같이 본다** — 평균 하나면 문제가 숨는다(고정 관절이 평균을 낮추고,
한쪽 손목만 과하게 움직여도 평균은 작다):

```
mean_limb_move     ≤ 0.20 torso     팔다리 관절 평균
max_endpoint_move  ≤ 0.35 torso     말단(손목·발목) 최대
```

**임계값은 실 러프로 보정한다. 그리고 라이브러리 정리 이후에 한다** — 라이브러리 커버리지가
나쁘면 정당한 조정도 큰 이동을 요구해서, 지금 잡은 임계값이 나중에 과하게 조일 수 있다.

**어디**: `src/refine.py` 잔차 + 게이트. `REFINE_MAX_MOVE_MEAN` / `REFINE_MAX_MOVE_MAX` 신설.

---

### P3 — 자기 충돌 검사

> 상세 설계: `docs/REFINE_P3.md`

**상태**: ✅ P3a 구현. P2 하드 게이트는 끄고 이동량만 기록한다.

**무엇**: 몸통 내부 코어와 전완·BVH 손끝 구간을 캡슐로 근사해, P1이 새로 만든
깊은 관통만 검출한다. 충돌한 팔만 베이스로 복구하고 반대팔의 유용한 조정은 보존한다.

**실측**: `171734` #1/#2 왼손 관통(0.055/0.090 torso)을 검출했고 오른팔은 보존했다.
`124629` 정상 Top-5의 최대 얕은 근접은 0.043이어서 `MIN_DEPTH=0.05`로 분리했다.
`171734` #4처럼 P1이 건드리지 않은 사지/베이스 메시 문제는 P3a가 수정하지 않는다.

### P4 — 손목·머리 처리 재검토

**무엇**: 지금 손목을 고정하는데, 전완이 비틀리면 **손이 그 비틀림을 그대로 물려받는다.**
P1로 비틀림이 잡히면 자동 해소될 수 있으니 **P1 이후에 판단.**

---

### P5 (선택) — 다시각 손실

**무엇**: 매칭 view 하나가 아니라 인접 view에도 약한 페널티.
**왜**: 깊이 자유도를 근본적으로 줄인다. 다만 **인접 view의 정답을 모른다**(러프는 한 장)는
한계가 있어 "베이스에서 크게 벗어나지 마라" 수준의 약한 항으로만 쓸 수 있다. P1·P2가 먼저.

## 5. 검증 방법의 교훈 (반복 금지)

세 번 틀렸고, 전부 **검증이 문제를 못 보게 생겨 있었다.**

1. **단일 view만 렌더했다.** 손실이 그 view만 보는데 그 view만 그리면 당연히 좋아 보인다.
   → 이제 `diag_refine_3d.py`로 **4개 view** 확인. 단일 view 판정 금지.
2. **"악화 0건" 지표가 순환논법이었다.** 독립 지표라던 `angle_distance`는 refine이
   최소화하는 값과 같은 척도였다. → 독립 지표는 **3D 이동량·해부학·다른 view**여야 한다.
3. **백엔드 교차 검증이 없었다.** scipy 기본 유한차분 보폭(상대 1.5e-8)이 float32로
   양자화된 목적함수에서 변화를 못 만들어 야코비안이 0 → **nfev=1로 시작점 반환** →
   조정을 안 했는데 `no_gain`("개선 여지 없음")으로 보고. 환경에 따라 결과가 갈렸다.
   → `test_refine_backends_agree` 추가. **아무것도 안 한 것이 정상 판정처럼 보이는 경로**는
   `runtime_guard.py`가 막는 mock 폴백과 같은 종류의 위험이다.

**또 하나**: 합성/라이브러리 BVH를 쿼리로 쓴 검증은 노이즈가 없어 실패를 못 본다.
실 러프로 확인해야 한다.

## 6. 하지 말 것

- **조정 강도를 전역으로 낮춰 증상 무마하기.** 좋은 부분(2D 방향 맞추기)까지 같이 약해진다.
  비틀림은 작아질 뿐 방향은 여전히 임의다. 원인은 조정 강도가 아니라 축별 관측 불가지성이다.
- **"다리를 켜냐 끄냐" 같은 전역 이분법.** 감도가 컷마다 8배 흩어진다 — 측정해서 결정할 것.
- **게이트 약화.** "좋아지거나, 그대로"가 무너지면 refine은 없는 것만 못하다.
- **단일 view 스크린샷으로 판정.**

## 7. 순서

**P1과 P2를 한 번에 넣지 않는다.** 같이 넣으면 좋아졌을 때 어느 쪽 효과인지 알 수 없다.

```
0. 트래쉬·중복 BVH 정리 → 검색 결과 고정            ← 이게 먼저다
1. 실 러프 평가셋 선정 → 현재 결과를 baseline으로 저장
2. 축별 감도를 '진단 정보로만' 계산해 출력            ← 아직 적용 안 함
3. 감도가 view·사지·BVH에 따라 안정적인지 확인
4. P1a 축별 λ(clip) 적용 → 4-view·3D 이동량·백엔드 일치 회귀  ✅ 구현
5. 남은 실패가 §P1b의 '조합 방향' 케이스인지 확인 → 실측 24%로 확인, P1b 적용  ✅ 구현
6. P2 이동량 게이트(평균+말단 최대) 추가 → 임계값 실 러프로 보정
7. 남은 실패가 충돌이면 P3
```

현재 P1a/P1b/P2/P3a를 포함한 전체 스모크 테스트는 **40/40 통과**했다.

**0번이 이 전부보다 우선한다.** refine은 틀린 베이스를 못 살린다. 베이스가 좋아지면
refine이 할 일 자체가 줄고, P2 임계값도 그때 잡아야 제대로 잡힌다.
→ `docs/MVP_RELEASE.md` IN 항목 1·2.

## 8. 알려진 한계

- **감도는 베이스 포즈에서의 국소 성질이다.** 최적화가 움직이면 안 보이던 축이 보이게 될 수
  있는데, λ를 베이스 시점 값으로 고정하면 그 축을 과하게 묶는다. 조정폭이 작다는 전제
  하에서는 허용 가능. 문제가 되면 solve 중간에 1회 재계산.
- **P2 임계값은 라이브러리 커버리지에 종속된다.** 커버리지가 나쁠수록 정당한 조정도
  커진다. 0번(라이브러리 정리) 이전에 잡은 값은 신뢰하지 말 것.
- **P1b의 SVD도 만능이 아니다.** 잔차가 선형화 가능한 범위에서만 유효하다.
  조정폭이 커지면 야코비안이 바뀐다(위 첫 항목과 같은 문제).
