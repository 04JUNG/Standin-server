## 1. 결론

P2는 **진행한다.** P1이 관측되지 않는 회전축의 비틀림을 줄였다면, P2는 관측 가능한
방향이라도 결과가 너무 크게 움직이는 것을 막아 refine을 실제 의미의 "미세조정"으로 제한한다.

1차 구현 범위는 **post-solve 이동량 게이트**다. 최적화 잔차를 3D 이동량 기준으로 바꾸지는
않는다. P1과 P2의 효과를 분리해 측정하고, 정상 조정의 반복 탈락이 확인될 때만 3D 이동량
정규화를 별도 후속으로 검토한다.

후보 전체를 폐기하지 않고 **사지별로 판정하고 실패한 사지만 베이스로 복구**한다.
복구 후에는 전체 손실·개선량·해부학 게이트를 다시 계산한다. 안전한 사지를 다시 최적화하는
단계는 두지 않는다.

```text
전체 refine
  → 사지별 3D 이동량 측정
  → 실패 사지만 베이스 각도로 복구
  → 전체 자세 재검증
     ├─ 통과: 부분 refine 결과 사용
     └─ 실패/남은 사지 없음: 전체 베이스 반환
```

P2는 **충돌 검사가 아니다.** 이동량이 작아도 손이 몸을 뚫을 수 있으므로, P2 이후에도
관통이 남으면 P3 자기 충돌 게이트를 진행한다.

## 2. 왜 필요한가

현재 하드 바운드는 관절 채널당 각도(`REFINE_MAX_DELTA_DEG`)다. 그러나 같은 20°라도
어깨 회전은 손목을 크게 이동시키고, 팔꿈치 회전은 상대적으로 작게 이동시킨다. 각도 공간의
제약만으로는 3D 결과가 미세조정인지 보장할 수 없다.

정리 후 실 러프 3장 Top-5(15개)를 P1까지 적용해 검증했을 때 관절의 자연스러움은 전반적으로
좋았지만, 15개 중 5개가 손목 이동 `0.35 torso`를 초과했다. 특히 `171734` 러프에서
1·2·4번 후보의 손이 몸을 관통하는 현상이 관찰됐다.

| 후보 | 포즈 | 최대 손목 이동 | P2 예정 판정 |
|---:|---|---:|---|
| 1 | `Dig And Plant Seeds_00165_mirror` | `0.549 torso` | 과이동 사지 탈락 |
| 2 | `Dig And Plant Seeds_00165` | `0.576 torso` | 과이동 사지 탈락 |
| 4 | `Dig And Plant Seeds_00025_mirror` | `0.608 torso` | 과이동 사지 탈락 |

1·2번은 반대쪽 손목 이동이 각각 `0.124`, `0.153 torso`로 작다. 따라서 후보 전체를
폐기하면 정상적인 조정까지 잃는다. 사지별 판정이 필요한 직접적인 근거다.

또한 1~4번이 같은 `Dig And Plant Seeds` 패밀리라는 점은 별도의 검색 다양성 문제다.
P2는 Top-K 패밀리 중복을 해결하지 않는다.

## 3. 이동량 정의

캐릭터·BVH 스케일과 무관하도록 모든 이동량을 베이스 포즈의 몸통 길이로 정규화한다.

```text
torso = |shoulder_midpoint - hip_midpoint|
move(joint) = |joint_refined - joint_base| / torso
```

사지별로 두 값을 함께 본다.

```text
mean_limb_move    ≤ 0.20 torso
endpoint_move     ≤ 0.35 torso
```

- `mean_limb_move`: 팔은 팔꿈치·손목, 다리는 무릎·발목 이동량의 평균
- `endpoint_move`: 팔은 손목, 다리는 발목 이동량
- 평균만 보면 한 말단의 과이동이 숨고, 말단만 보면 사지 전체가 함께 밀린 실패를 놓칠 수 있어
  두 조건을 모두 사용한다.

사지와 COCO17 관절 대응은 다음과 같다.

| 사지 | 중간 관절 | 말단 |
|---|---:|---:|
| `left_arm` | 왼팔꿈치 7 | 왼손목 9 |
| `right_arm` | 오른팔꿈치 8 | 오른손목 10 |
| `left_leg` | 왼무릎 13 | 왼발목 15 |
| `right_leg` | 오른무릎 14 | 오른발목 16 |

`0.20/0.35`는 현재 평가셋에서 시작할 **초기값**이다. 라이브러리 커버리지와 실사용 표본이
늘어나면 `limb_decisions` 로그를 근거로 보정한다.

## 4. 후보 전체 폐기가 아닌 사지별 복구

P2 실패 하나로 후보 전체를 버리면 잘 조정된 반대쪽 사지도 사라진다. 따라서 최적화 결과의
파라미터를 사지별로 검사한 뒤 실패한 사지의 채널만 `base_params`로 되돌린다.

예상되는 `171734` 처리:

| 후보 | 처리 |
|---:|---|
| 1 | 과이동한 오른팔 복구, 왼팔 조정 유지 후 전체 재검증 |
| 2 | 과이동한 오른팔 복구, 왼팔 조정 유지 후 전체 재검증 |
| 4 | 조정 대상 오른팔이 탈락해 남은 사지가 없으므로 전체 베이스 반환 |

부분 복구 후에는 반드시 다음을 다시 검사한다.

1. 러프와의 최종 2D 손실과 `REFINE_MIN_GAIN`
2. 팔꿈치·무릎 굽힘각
3. 남아 있는 채택 사지가 최소 하나인지
4. 모든 값이 유한한지

부분 결과가 전체적으로 더 이상 개선되지 않으면 안전한 사지가 있더라도 전체 베이스를 반환한다.

## 5. SVD 블록화와 재최적화 결정

P1b는 현재 활성 사지 전체의 야코비안에 전역 SVD를 적용한다. 왼팔과 오른팔은 서로 다른
뼈 행과 파라미터 열을 사용하므로 `JᵀJ`는 본질적으로 사지별 블록 대각이다. 특이값이 같은
축퇴 부분공간에서는 SVD 기저가 좌·우 사지를 섞어 표현할 수 있지만, **기저 혼합이 실제
정규화 결합을 의미하지는 않는다.**

실 러프 3장 Top-5에서 측정한 결과:

| 측정 | 값 |
|---|---:|
| 다른 사지 에너지가 10%를 넘은 SVD 모드 | `7/120` (`5.8%`) |
| 최종 페널티 행렬의 사지 간 성분 중앙값 | `0` |
| 최종 페널티 행렬의 사지 간 성분 최댓값 | `2.55e-16` |

즉 현재 목적함수는 수치 오차 수준에서 이미 사지별로 분리돼 있다. 따라서 P2에서 실패 사지를
복구한 뒤 안전한 사지를 **다시 최적화할 필요는 없다.** 복구 후 전체 검증만 다시 수행한다.

그래도 P2 구현 전에 P1b SVD 호출은 사지별 블록으로 정리한다. 이는 P1 결과를 다시 튜닝하는
작업이 아니라 다음을 위한 작은 구조 개선이다.

- 코드 구조를 사지별 P2 판정과 일치시킴
- 진단 모드를 사지별로 해석 가능하게 함
- 향후 사지별 λ가 달라져도 실제 결합이 생기지 않게 보장
- 축퇴 공간에서 임의로 섞여 보이는 진단 기저 제거

블록 야코비안은 다른 사지의 0행까지 포함하기보다 사지 마스크와 열을 함께 자르는 편이 명확하다.

```python
for limb in active:
    cols = [
        k for k, joint in enumerate(fwd.param_joints)
        if limb_of[joint] == limb
    ]
    limb_mask = mask & _mask_for([limb])
    jac_block = directional_jacobian(
        fwd, base_params, limb_mask, w
    )[:, cols]
    vt_b, s_b, mult_b = svd_lambda_basis(
        jac_block, cfg.refine_svd_lambda_max_mult
    )
    # 전체 행렬의 해당 사지 블록에 다시 배치
```

## 6. 알고리즘

```text
1. 기존 유효성·관측 감도 게이트로 active 사지 결정
2. P1a + 사지별 블록 P1b로 한 번 최적화
3. 베이스/조정 3D 관절을 계산
4. active 사지마다 mean_move와 endpoint_move 계산
5. 임계값 초과 사지의 모든 회전 파라미터를 base로 복구
6. 남은 사지가 없으면 베이스 반환
7. 복구된 혼합 포즈의 2D 손실·gain 재계산
8. 사지별 굽힘각 검사; 새 위반 사지는 같은 방식으로 복구
9. 다시 전체 gain 검사
10. 통과한 사지만 RefineResult.limbs에 기록하고 BVH 저장
```

굽힘각 위반을 사지별로 복구할 경우, 복구 후 손실·gain 검사를 한 번 더 해야 한다. 구현은
무한 반복이 아니라 이동량 복구 1회 + 해부학 복구 1회로 상한을 고정한다.

## 7. `RefineResult` 진단 계약

기존 `limbs`에는 **최종 채택된 사지만** 남긴다. 임계값 보정과 실패 분석을 위해 고려된 모든
사지의 판정은 별도 `limb_decisions`에 기록한다.

```json
{
  "limbs": ["left_arm"],
  "limb_decisions": {
    "left_arm": {
      "accepted": true,
      "reason": "ok",
      "mean_move": 0.083,
      "endpoint_move": 0.153
    },
    "right_arm": {
      "accepted": false,
      "reason": "max_endpoint_move",
      "mean_move": 0.241,
      "endpoint_move": 0.576
    }
  }
}
```

최소 사유 vocabulary:

| reason | 의미 |
|---|---|
| `ok` | 모든 사지별·전체 게이트 통과 |
| `invisible_target` | 타깃에서 그 사지의 뼈가 온전히 보이지 않음 |
| `low_observability` | 2D 관측 감도 부족 |
| `mean_move` | 사지 평균 이동량 초과 |
| `max_endpoint_move` | 손목·발목 이동량 초과 |
| `joint_limit` | refine 때문에 팔꿈치·무릎 굽힘각 위반 |
| `global_no_gain` | 부분 복구 후 전체 개선량 부족 |

`mean_move`와 `max_endpoint_move`가 동시에 초과하면 더 직접적인 안전 위반인
`max_endpoint_move`를 대표 reason으로 쓰되 두 수치는 모두 남긴다.

전체 결과 reason 제안:

- `ok`: 모든 active 사지 채택
- `ok_partial`: 한 개 이상 사지를 복구하고 나머지를 채택
- `movement_gate`: 이동량 게이트 후 남은 사지가 없음
- `global_no_gain`: 부분 복구 후 전체 gain 부족

오프라인 `refine_top5.py`의 `manifest.json`에도 `limb_decisions`를 그대로 기록한다.

## 9. 검증 기준

### 자동 테스트

- 한쪽 팔만 이동량 초과 → 실패 팔 채널은 베이스와 완전히 동일, 반대쪽 팔은 유지
- 모든 active 사지 초과 → 조정 BVH를 쓰지 않고 베이스 반환
- 부분 복구 후 gain 부족 → 전체 베이스 반환
- 경계값 `0.20/0.35` 이하는 통과, 초과는 탈락
- `limb_decisions`에 채택·탈락 사유와 실제 이동량 기록
- 손·발·척추·루트 채널은 기존 불변식대로 직접 수정하지 않음
- scipy/numpy 백엔드가 같은 사지 채택 판정을 냄

### 실 러프 회귀

1. 현재 3장 Top-5를 같은 쿼리·DB로 재실행
2. 4-view와 CSP 메시에서 관절 자연스러움 확인
3. `171734` 1·2번은 부분 채택, 4번은 베이스 반환 여부 확인
4. P2 통과 후보에서 손-몸 관통이 남는지 기록
5. 관통이 남으면 P3 캡슐 충돌 게이트로 진행

P2의 성공 기준은 "관통 0건"이 아니라 **과이동 결과 0건 + 정상 조정 최대 보존**이다.
충돌 0건은 P3의 성공 기준이다.

## 10. 구현 순서

1. P1b SVD를 사지별 블록 호출로 정리하고 기존 P1 결과가 실질적으로 같음을 회귀 확인
2. 설정값과 사지별 3D 이동량 계산 추가
3. 사지별 복구 + 전체 재검증 구현
4. `limb_decisions`와 manifest 진단 배선
5. 자동 테스트
6. 실 러프 3장 Top-5 재실행
7. 남은 손-몸 관통을 보고 P3 진행 여부 결정

현재 상태는 **구현 및 1차 회귀 완료**다. 다음 판단은 `0.20/0.35` 임계값을 즉시
완화하는 것이 아니라, 실사용 표본에서 정상 조정의 반복 탈락 여부와 P2 통과 결과의
손-몸 관통 여부를 각각 기록하는 것이다.

1·2번의 4-view 진단에서도 복구된 오른팔은 모든 view에서 베이스와 동일했고, 채택한
왼팔의 손목 이동은 각각 `0.124`, `0.153 torso`였다. 4번은 조정 파일을 쓰지 않았다.

`124702`는 5개 모두 베이스로 돌아갔다. 네 후보는 active 팔의 평균 이동량이
`0.229~0.271 torso`로 `0.20`을 넘었고, 한 후보는 말단이 `0.453 torso`였다.
이는 현재 초기값이 보수적으로 작동한다는 신호다. 이 한 컷만으로 임계값을 올리지 않고,
실사용에서 정상 조정이 반복 탈락하는지 `limb_decisions`로 누적해 보정한다.

생성물은 `out/refine_p2/`에 있으며, P2를 통과한 결과의 실제 메시 자기 충돌 여부는
별도 P3 판단 항목으로 남는다.
