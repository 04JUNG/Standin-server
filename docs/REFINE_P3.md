# Refine P3 — 베이스 상대 자기 충돌 게이트

> 2026-08-02 · P3a 구현 및 실 러프 3장 Top-5 probe 완료
>
> 관련 문서: `REFINE_NEXT.md` P3, `REFINE_DESIGN.md`, `REFINE_P2.md`
>
> 현재 운영 결정: **P2 이동량 하드 게이트는 잠시 끄고(`REFINE_MOVE_GATE=0`),
> 이동량은 진단값으로만 남긴다. P1 결과 위에 P3a를 먼저 검증한다.**

## 1. 결론

P3는 진행한다. 첫 구현은 메시 기반 물리 시뮬레이션이나 충돌 회피 최적화가 아니라,
FK로 얻은 3D 스켈레톤을 캡슐로 근사하는 **post-solve 사지별 자기 충돌 게이트(P3a)**다.

```text
P1 refine 1회
  → P2 이동량 측정(로그만, 롤백 안 함)
  → P3a 베이스/조정 충돌 깊이 비교
  → 새로 몸통을 깊게 관통한 사지만 베이스로 복구
  → 전체 gain·굽힘각·충돌 재검사
     ├─ 통과: 안전한 다른 사지 조정은 보존
     └─ 실패/남은 사지 없음: 전체 베이스 반환
```

핵심은 **접촉과 관통을 구분**하고, 원래 베이스에 있던 충돌이 아니라 refine 때문에
새로 생기거나 유의미하게 심해진 충돌만 막는 것이다. 손을 가슴에 대거나 팔짱을 끼는
정상 포즈까지 전부 충돌로 판단하면 P3가 P2와 같은 과잉 롤백 문제가 된다.

P3a에서 정상 조정을 너무 자주 잃는 것이 확인될 때만, 충돌한 사지를 한 번 더 푸는
**충돌 페널티 재최적화(P3b)**를 추가한다. 처음부터 P3b까지 구현하지 않는다.

---

## 2. 직접 근거 — 왜 P2보다 P3가 먼저인가

실 러프 3장 Top-5를 P1과 P2로 비교한 사람 눈 평가:

| 러프 | 관찰 | 해석 |
|---|---|---|
| `124629` | P1·P2 모두 좋음 | 현재 P1 결과에 회귀를 만들면 안 되는 음성 표본 |
| `171734` | 왼손 관통은 남고, P1에서 좋아진 오른팔은 P2가 복구 | 이동량은 문제 사지를 지목하지 못함. 실제 충돌을 직접 재야 함 |
| `124702` | P1·P2 모두 사람 손질 필요 | 다리를 모은 착석 포즈가 부족한 검색 커버리지 문제. P3 범위 아님 |

`171734`에서 P2가 한 일과 필요한 일은 반대였다.

```text
실제 문제        = 왼손/왼전완의 몸통 관통
P2 롤백 대상     = 이동량이 큰 오른팔
사용자가 원한 것 = 좋은 오른팔 조정 유지 + 충돌한 왼팔만 안전 처리
```

따라서 현재 증거로는 `큰 3D 이동 = 나쁜 결과`라는 하드 판정이 성립하지 않는다.
P2 구현은 삭제하지 않지만 하드 게이트를 보류하고, 이동량 로그를 추후 조건부 P2 설계의
근거로 보존한다.

## 3. P3a 범위와 비범위

### 이번 범위

- 1인 포즈의 **왼팔/오른팔 대 몸통** 자기 충돌
- 전완과 BVH 손목→손끝 구간이 몸통 내부 코어를 관통하는지 검사
- 베이스와 조정본의 관통 깊이를 비교
- 실패한 팔의 회전 채널만 `base_params`로 복구
- 복구 후 전체 2D gain·굽힘각·충돌 재검사
- 모든 판정 수치를 `limb_decisions`와 Top-5 manifest에 기록

관측 감도 때문에 P1에서 동결된 팔도 충돌 수치는 기록하지만, P3가 그 팔을 새로 움직이지는
않는다. 이 진단으로 베이스 문제와 refine 신규 문제를 구분한다.

### 이번에 하지 않는 것

- 손가락 각각의 충돌: 공통 관절 계약이 없어 손 전체를 손목→대표 손끝 구간으로만 근사한다.
- 실제 CSP 데생 인형 메시 충돌: 이 서버는 메시와 체형을 알지 못한다.
- 양팔끼리, 양다리끼리, 팔-다리 충돌
- 2인 얽힘 포즈의 사람 간 충돌
- 충돌한 팔을 자동으로 밀어내는 재최적화(P3b)
- `124702`의 다리를 모은 착석 자세 생성: 라이브러리 보강 문제다.

P3a는 **깊은 손·전완-몸통 관통을 잡는 보수적 스켈레톤 프록시**다. 메시 충돌의
완전한 판정기가 아니다.

## 4. 충돌 기하 모델

### 4-1. 좌표와 스케일

충돌은 매칭 view의 2D 투영이 아니라 `bvh.fk`가 계산한 **BVH world 3D 좌표**에서 잰다.
카메라와 무관하므로 front/side/back에서 판정이 달라지지 않는다.

모든 길이는 베이스의 몸통 길이로 정규화한다.

```text
S = (left_shoulder + right_shoulder) / 2
H = (left_hip + right_hip) / 2
T = |S - H|
```

`T <= 1e-6`이거나 필요한 관절이 없으면 충돌 판정을 강행하지 않고
`collision_unavailable`로 기록한다. 잘못된 기하로 정상 결과를 폐기하는 것보다 낫다.

현재 라이브러리 1,313개를 측정한 정규화 폭 분포:

| 비율 | p10 | 중앙값 | p90 |
|---|---:|---:|---:|
| 어깨 폭 / 몸통 길이 | 0.531 | 0.579 | 1.077 |
| 골반 폭 / 몸통 길이 | 0.328 | 0.399 | 0.505 |

p90 어깨 값은 자세·스켈레톤 매핑의 영향으로 길게 튀므로 단일 전역 반경보다 실제
어깨·골반 폭을 쓰되 clip으로 극단값을 제한한다.

### 4-2. 몸통 — 테이퍼드 내부 캡슐

몸통 전체 외곽을 캡슐로 잡으면 가슴에 손을 대는 정상 접촉까지 충돌로 오인한다.
따라서 몸통 메시의 표면이 아니라 **깊은 관통만 잡는 내부 코어**를 근사한다.

초기 반경 후보:

```text
shoulder_width = |left_shoulder - right_shoulder|
hip_width      = |left_hip - right_hip|

r_shoulder = clip(0.38 * shoulder_width, 0.16*T, 0.24*T)
r_hip      = clip(0.45 * hip_width,      0.14*T, 0.20*T)
r(t)       = (1-t) * r_shoulder + t * r_hip
```

`t=0`은 어깨 중점, `t=1`은 골반 중점이다. 이 값으로 §10의 diagnostic sweep을 시작했고,
손끝 프록시와 `MIN_DEPTH=0.05`를 함께 썼을 때 알려진 정상 표본을 보존하면서
`171734` 왼팔의 깊은 관통을 분리했다.

### 4-3. 팔·손 — 샘플 캡슐

P3a는 각 팔에서 팔꿈치→손목 전완 구간을 검사한다.

```text
left_arm:  elbow=COCO 7, wrist=COCO 9
right_arm: elbow=COCO 8, wrist=COCO 10
```

전완 전체를 하나의 선분-선분 거리로 계산해도 되지만, 테이퍼드 몸통 반경을 적용하고
어느 지점이 충돌했는지 진단하기 쉽게 선분을 균등 샘플링한다.

- 팔꿈치 바로 주변의 정상적인 옆구리 근접을 줄이기 위해 전완의 `25%~100%` 구간 사용
- 초기 샘플 수 `9`
- 팔 캡슐 반경 후보 `0.035*T`
- 손목은 마지막 샘플로 포함되며 같은 반경의 구로 취급

최초 전완/손목 중심선 probe는 `171734`의 사람이 확인한 관통을 한 건도 잡지 못했다.
해당 결과는 손목이 몸통 코어 밖에 있고, 손 회전을 상속받은 손가락만 몸을 가로질렀기 때문이다.
따라서 BVH에 `Left/RightHandMiddle*` 계층이 있으면 손목에서 가장 먼 중지 관절까지의
world-space 구간도 같은 방식으로 검사한다. 중지가 없으면 Index 계층, 둘 다 없으면
전완/손목 검사로 fail-open 폴백한다.

- 손 구간 샘플 수: 전완과 같은 `9`
- 손 캡슐 반경: `0.025*T`
- COCO wrist 위치에 BVH hand→finger-tip world offset을 더해 매핑 오차를 줄임

이것은 손가락별 충돌이나 실제 메시 판정이 아니라 **대표 손 방향 프록시**다. 하지만 실제
실패가 손목 밖의 손 방향에서 생겼기 때문에, 손끝 구간 없이는 P3a의 알려진 양성을 검출할 수 없다.

### 4-4. 관통 깊이

전완 샘플 `p`를 몸통 축 `S→H`에 투영한다.

```text
t_raw = dot(p-S, H-S) / |H-S|²
t     = clip(t_raw, 0, 1)
c     = S + t(H-S)

clearance(p) = |p-c| - (r(t) + r_arm)
penetration(p) = max(0, -clearance(p)) / T
```

사지의 대표값은 샘플의 최대 관통 깊이다.

```text
penetration(limb) = max_p penetration(p)
```

평균을 쓰지 않는다. 손목 한 점의 깊은 관통이 나머지 정상 샘플에 묻히면 안 되기 때문이다.
함께 `sample_fraction`과 `collision_point`를 남겨 4-view 진단에서 위치를 표시할 수 있게 한다.

## 5. 접촉이 아닌 “새 관통” 판정

베이스와 P1 조정본에서 같은 충돌 점수를 계산한다.

```text
d_base   = penetration(base, limb)
d_solved = penetration(P1 result, limb)

new_collision =
    d_solved >= MIN_DEPTH
    and d_solved - d_base >= WORSEN_DELTA
```

초기 sweep 후보:

| 값 | 후보 | 역할 |
|---|---:|---|
| `MIN_DEPTH` | **`0.05 T`** | `171734` 양성(0.055/0.090)과 `124629` 최대 음성(0.043) 사이 |
| `WORSEN_DELTA` | `0.005 / 0.01 / 0.02 T` | 베이스에 이미 있던 충돌과 구분 |

두 조건을 같이 쓰는 이유:

- 절대 깊이만 보면 베이스의 기존 접촉까지 refine 탓으로 돌린다.
- 증가량만 보면 `0 → 0.006` 같은 얕은 노이즈도 충돌로 잡는다.
- 베이스보다 좋아졌지만 여전히 프록시 내부인 결과는 자동 폐기하지 않고 진단으로 남긴다.

베이스 자체의 충돌은 `collision_in_base`로 기록한다. P3a의 보장은 “모든 메시 충돌 0”이
아니라 **refine이 새로운 깊은 관통을 만들지 않음**이다.

## 6. P3a 알고리즘

```text
1. 기존 유효성·관측 감도 게이트로 active 사지 결정
2. P1a + 사지별 block P1b로 한 번 최적화
3. P2 이동량은 full solve 기준으로 계산해 로그만 기록
4. base와 solved의 팔-몸통 관통 깊이를 사지별 계산
5. 새 관통 사지의 모든 회전 파라미터를 base로 복구
6. 남은 사지가 없으면 전체 베이스 반환
7. 혼합 자세의 충돌을 다시 계산 — 복구 사지는 base 깊이와 같아야 함
8. 전체 2D loss와 REFINE_MIN_GAIN 재검사
9. 팔꿈치 굽힘각 재검사
10. 통과한 사지만 RefineResult.limbs에 남기고 BVH 저장
```

재검사 후에도 충돌이 남는 경우:

- 복구한 사지의 깊이는 base 깊이와 같아야 한다.
- 복구하지 않은 사지의 깊이는 full solve 때와 같아야 한다.
- 둘 중 하나라도 달라지면 사지 분리성·파라미터 그룹핑·FK 버그이므로
  `collision_unresolved`로 전체 베이스를 반환한다.

몸통은 고정이고 좌우 팔 파라미터는 분리돼 있으므로 한 팔 롤백이 다른 팔의 충돌을 새로
만드는 정상 경로는 없다. 따라서 반복 재판정·재최적화 없이 **동시 판정 1회 + 불변식 재검사
1회**로 상한을 고정한다.

`171734`에서 기대하는 동작:

```text
왼팔: 새 몸통 관통 → 베이스로 복구
오른팔: 충돌 없음 → P1의 유용한 조정 유지
최종: gain·굽힘각 재검사 후 ok_partial
```

P3a는 충돌한 팔을 더 좋은 비충돌 자세로 고치는 단계가 아니다. 우선 **나쁜 사지만 버리고
좋은 반대쪽 조정을 보존**해 현재 P2의 실패를 바로잡는 안전 게이트다.

## 7. P3b — 필요할 때만 충돌 사지 재최적화

다음 현상이 실사용에서 반복될 때만 P3b를 추가한다.

- P3a가 충돌은 막지만 러프와 맞던 팔 조정을 너무 자주 잃음
- 베이스 팔도 좋지 않아 롤백 결과의 가치가 낮음
- 같은 사지를 작은 깊이 보정만으로 살릴 수 있다는 4-view 근거가 있음

P3b는 충돌한 사지만 다시 풀고 다른 사지는 P1 결과로 고정한다.

```text
residual_total = residual_2d
               + residual_P1_regularization
               + sqrt(lambda_collision) * penetration_samples
```

- 시작점: P1 조정값
- 파라미터: 충돌한 사지의 기존 어깨·팔꿈치 회전만
- 기존 각도 바운드와 P1a/P1b 정규화 유지
- 재시도 최대 1회
- 충돌·gain·굽힘각을 모두 통과할 때만 채택
- 실패하면 P3a처럼 해당 사지를 베이스로 복구

깊이 모호성을 이용해 2D 투영을 거의 유지한 채 팔을 몸통 밖으로 보내는 것이 목표다.
하지만 충돌 잔차의 비선형성과 프록시 오차가 있으므로 P3a 데이터 없이 먼저 만들지 않는다.

## 8. 결과·진단 계약

기존 `limbs`에는 P3까지 통과한 최종 사지만 남긴다. `limb_decisions`에는 P2 이동량과
P3 충돌 진단을 함께 남긴다.

```json
{
  "reason": "ok_partial",
  "limbs": ["right_arm"],
  "limb_decisions": {
    "left_arm": {
      "accepted": false,
      "reason": "self_collision",
      "mean_move": 0.083,
      "endpoint_move": 0.153,
      "collision": {
        "checked": true,
        "status": "new_penetration",
        "pair": "left_forearm:torso",
        "base_depth": 0.000,
        "solved_depth": 0.061,
        "final_depth": 0.000,
        "sample_fraction": 0.875
      }
    },
    "right_arm": {
      "accepted": true,
      "reason": "ok",
      "mean_move": 0.362,
      "endpoint_move": 0.549,
      "collision": {
        "checked": true,
        "status": "clear",
        "pair": null,
        "base_depth": 0.000,
        "solved_depth": 0.000,
        "final_depth": 0.000,
        "sample_fraction": null
      }
    }
  }
}
```

예시 수치는 형식 설명용이며 실제 `171734` 측정값이 아니다.

사지 최종 action reason 추가:

| reason | 의미 |
|---|---|
| `ok` | P1·P3와 전체 게이트 통과 |
| `self_collision` | refine 때문에 몸통 관통이 새로 생기거나 심해져 사지 복구 |
| `collision_unresolved` | 사지 복구 후에도 충돌 점수가 원복되지 않음 |
| `global_no_gain` | 충돌 사지 복구 후 전체 개선량 부족 |

접촉 진단 자체는 기존 action reason과 섞지 않고 `collision.status`에 둔다.

| collision.status | 의미 |
|---|---|
| `clear` | 내부 코어 관통 없음 또는 임계 미만 |
| `new_penetration` | 베이스 대비 새로 생기거나 유의미하게 깊어진 관통 |
| `in_base` | 베이스에도 관통 프록시가 있었으며 refine 신규 실패로 판정하지 않음 |
| `unavailable` | 필수 관절·몸통 스케일이 없어 fail-open으로 진단 생략 |
| `unresolved` | 롤백 후 기대한 base/solved 깊이로 돌아오지 않은 불변식 실패 |

전체 결과 reason:

- `ok`: active 사지 모두 채택
- `ok_partial`: 충돌 사지를 복구하고 다른 사지 채택
- `collision_gate`: 충돌 복구 후 채택 사지가 없음
- `collision_unresolved`: 재검증 불변식 실패
- `global_no_gain`: 부분 결과의 전체 gain 부족

HTTP `RefineResponse`, refine 사이드카, `refine_top5.py`의 `manifest.json`에 동일 구조를
직렬화한다. `diag_refine_3d.py`의 4-view 시트에는 몸통 코어와 게이트가 폐기한 P1 최대
관통 위치를 표시한다. 전체 샘플 좌표는 결과 계약을 불필요하게 키우지 않도록 저장하지 않는다.

## 10. 검증 계획

### 10-1. Stage 0 — diagnostic-only probe ✅ 완료

충돌 기하를 구현하되 `REFINE_COLLISION_GATE=0`으로 두고 판정값만 출력한다.

1. 동일 쿼리·DB로 실 러프 3장 Top-5의 P1 결과 재생성
2. 몸통 반경·깊이 threshold 후보 sweep
3. 다음 사람 라벨과 충돌 프록시를 비교

| 표본 | 기대 |
|---|---|
| `124629` 좋은 후보 | 새 충돌 0 — 거짓 양성 금지 |
| `171734` 1·2·4번 왼손 | 왼팔 양성 |
| `171734` P1에서 좋아진 오른팔 | 오른팔 음성 — 반드시 보존 |
| `124702` | P3 품질 판정에서 제외. 커버리지 문제 |

이 표본만으로 일반 임계값을 확정할 수는 없다. 최소한 알려진 실패를 잡고 알려진 정상 결과를
보존하는지 확인한 뒤, 실사용 로그로 보정한다.

### 10-1-1. Stage 0 실측 결과 (2026-08-02)

전완/손목만 검사한 최초 probe는 `171734`를 놓쳤다. 대표 손끝 구간을 추가한 뒤:

| 표본 | 결과 |
|---|---|
| `171734` #1 왼손 | `new_penetration`, `0.054948 T` |
| `171734` #2 왼손 | `new_penetration`, `0.089534 T` |
| 같은 후보의 오른팔 | 모두 `clear`, P1 조정 보존 |
| `124629` Top-5 | 신규 깊이 최대 `0.042681 T`; `MIN_DEPTH=0.05`에서 롤백 0건 |
| `124702` Top-5 | P3 개입 0건. 기존 착석 라이브러리 커버리지 문제 그대로 |

게이트를 켠 결과 `171734` #1/#2는 `ok_partial`로 왼팔만 베이스 깊이 `0`으로 돌아갔고,
오른팔 조정과 전체 2D 개선(`#1 0.128→0.072`, `#2 0.137→0.077`)은 유지됐다.

사람이 관통을 표시한 `171734` #4는 P1 관측 감도 게이트가 왼팔을 애초에 동결한 후보라
P3a가 되돌릴 조정이 없다. 현재 스켈레톤/대표 손끝 프록시의 베이스 깊이도 `0`이므로,
이 건은 **베이스 메시·손가락 형상 또는 프록시 사각지대**로 기록한다. P3a의 보장 범위는
refine이 새로 만든 관통을 막는 것이며 베이스 포즈의 메시 충돌을 자동 수정하는 것이 아니다.

### 10-1-2. 미사용 러프 holdout 결과 (2026-08-02)

임계값 보정에 사용한 세 장을 제외하고 `scripts/eval_p3_holdout.py`로 나머지를 평가했다.
Gemini 태그는 쓰지 않고 RTMPose가 검출한 모든 인물을 왼쪽→오른쪽으로 정렬했으며,
검색 거리 게이트는 끄고 P3 자체의 표본을 최대한 확보했다.

| 항목 | 결과 |
|---|---:|
| 러프 | 11장 |
| RTMPose 검출 인물 | 25명 |
| Top-5 후보 | 125개 |
| P3 충돌 측정까지 도달 | 86개 후보 / 172개 팔 |
| P3가 복구한 후보 | 13개(적용 가능 후보의 15.1%) |
| P3가 복구한 팔 | 14개 |
| 복구 깊이 | `0.052720~0.210794 T`, 중앙값 `0.144298 T` |
| 양수지만 복구하지 않은 깊이 | `0.015862~0.041865 T` |

holdout에서도 `0.041865`와 `0.052720` 사이에 빈 구간이 생겨 `MIN_DEPTH=0.05`가
최초 세 러프의 숫자만 외운 결과라는 우려는 줄었다. 14개 중 12개는 `0.075 T` 이상이라
대부분은 임계값을 조금 옮겨도 판정이 유지된다.

하지만 14건 중 9건이 같은 다인 컷(`131112`)의 두 사람에 몰렸고, 손을 가슴·얼굴에 대거나
팔을 교차하는 러프가 포함돼 있다. 4-view 스틱에서는 P1 팔이 몸통 중심을 가로지르는 경향이
확인되지만, 이것만으로 실제 CSP 메시의 오탐/정탐을 확정할 수 없다. 임계값은 **유지하되
추가 튜닝하지 않고**, 저장된 P1/P3 BVH를 CSP에서 비교한 사람 라벨을 다음 근거로 사용한다.

### 10-2. 자동 테스트

- 몸통 밖 전완 → 충돌 0
- 몸통 중심을 가로지르는 전완 → 양의 관통 깊이
- 같은 자세를 전체 10배 스케일해도 정규화 점수 동일
- 베이스에 있던 동일 충돌 → `self_collision`으로 신규 판정하지 않음
- 베이스보다 유의미하게 깊어진 충돌만 양성
- 왼팔만 충돌 → 왼팔 채널은 베이스와 완전히 동일, 오른팔 조정 유지
- 양팔 모두 충돌 → 조정 파일을 쓰지 않고 전체 베이스 반환
- 부분 복구 후 gain 부족 → 전체 베이스 반환
- 복구 후 collision score가 베이스와 같지 않으면 `collision_unresolved`
- scipy/numpy 결과의 충돌 사지 판정 일치
- 손·발·척추·루트 채널 직접 수정 없음

### 10-3. 사람 눈·CSP 검증

- 매칭 view만 보지 않고 4-view 스틱피겨 확인
- 최종 판정은 실제 CSP 데생 인형 메시에서 손-몸 관통 확인
- `171734`에서 왼손 관통이 사라지고 오른팔 P1 개선이 보존되는지 확인
- `124629`에서 기존 좋은 결과가 한 건도 롤백되지 않는지 확인

P3a 완료 기준:

```text
알려진 새 관통 검출 + 알려진 정상 팔 보존 + 사지별 복구 불변식 통과
```

스켈레톤 프록시상 충돌 0만으로 CSP 메시 충돌 0을 주장하지 않는다.

## 12. 결정 사항

- P2는 삭제하지 않고 **하드 게이트만 잠시 비활성화**한다.
- P3a는 팔-몸통의 **새로운 깊은 관통**만 대상으로 한다.
- 후보 전체가 아니라 충돌 사지만 복구한다.
- 이동량이 커도 충돌하지 않고 유용한 조정이면 보존한다.
- 베이스 충돌은 진단하되 기본적으로 refine 신규 실패로 판정하지 않는다.
- 충돌 사지 재최적화는 P3a 실측 후에만 추가한다.
- `124702`는 P3 성공 기준에 넣지 않고 착석 라이브러리 보강 과제로 분리한다.

현재 상태는 **P3a 구현·기본 활성화 완료**다. `REFINE_MOVE_GATE=0`으로 P2는 계속
진단만 하고, `REFINE_COLLISION_GATE=1`과 `MIN_DEPTH=0.05`로 새 깊은 관통만 사지별
복구한다. 다음 단계는 더 많은 실사용 표본에서 거짓 양성/음성을 수집하는 것이며,
P3a가 유용한 팔 조정을 반복해서 잃을 때만 P3b를 검토한다.
