# 검수 완료 58개 추가 및 썸네일 스타일 유지

기준 스테이징 번들 `lib-20261021-21b1b3d9`의 5,862개에 다른 검수 세션의 완료본 58개를 추가한다. 새 번들은 `lib-20261105-c7817702`이며 포즈 5,920개, 검색 투영 23,680개다. 기존 포즈·투영 DB 행은 값까지 비교해 그대로 보존했다.

## 썸네일

- `outline-half-strong-v1`: 흰 배경, C 1/2 외곽선(512px 기준 0.65px), 대비 2.6, 밝기 보정 0.22.
- 전신·반신·흉상·두상 범위별 45도 간격 8방향. 총 189,440장. 현재 소비자 계약은 30도 간격이 아니다.
- 새 스타일 자산 버전: `outline-half-strong-v1-799022dea7bd`.
- 실행 코드에 박혀 있던 5,862개 제한을 manifest의 포즈 수로 바꾼다. 최대 10,000개, 포즈당 정확히 32장, 모든 이미지·기록 해시, 경로·압축 해제 용량 제한은 유지한다.
- 기존 스타일 복구 코드는 PR #165로 develop에 병합되어 있다. 이 변경도 병합해야 이후 일반 코드 배포가 58개 확장을 계속 지원한다.

## 최종 검수 자세와 출력 연결

원본 제공 BVH와 최종 보정 FBX가 다른 포즈가 있어 최종 FBX의 관절로 단일 프레임 BVH를 다시 구성했다. 52개 관절의 재수입 오차는 최대 0.05084mm다. 새 썸네일도 이 최종 FBX 표면으로 만들었다.

`converter.reviewed_library`는 운영자가 해시로 고정한 BVH·FBX 카탈로그에 한해 검수 FBX를 사용한다. 검수 당시와 정확히 같은 기본 캐릭터만 해당하며 체형 커스텀, 다른 캐릭터, 좌우 반전, 변경된 BVH는 기존 변환 경로를 유지한다. 이때 등록된 원본 손가락 회전을 별도 단계에서 전달하고 명시적으로 선택한 손 프리셋을 우선한다. 원본 관절이 없는 경우 새 제스처를 임의로 인증하지 않는다.

필요 설정은 `REVIEWED_LIBRARY_ROOT`, `REVIEWED_LIBRARY_SHA256`이다. ECS 초기화 컨테이너가 `scripts/install_reviewed_library.py`로 불변 S3 묶음을 설치하며 `REVIEWED_LIBRARY_ARCHIVE_URI`와 `REVIEWED_LIBRARY_ARCHIVE_SHA256`도 받는다. 앱에는 읽기 전용 볼륨을 연결한다. 기존 체형 자산 초기화 컨테이너와 모든 `BODY_*`, `CSP_*`, `CONVERTER_SHAPE_*` 설정을 보존한다.

## 검증 및 한계

- 신규 58개: BVH·검색 특징값·232개 기본 썸네일·개인정보 패턴·메타 허용 목록·리그 검사 통과.
- 전체 5,920개: 개인정보 패턴·리그 검사, 기존 5,862개 DB 및 23,448개 투영 행 보존 확인.
- 기존 배포 DB에는 `search_v2`, `prop_guides` 등 오래된 번들 작성기의 메타 허용 목록 밖 필드가 있다. 이를 삭제하지 않고 보존했으며 신규 항목에만 엄격한 허용 목록을 적용했다.
- 썸네일·검수 FBX 및 체형·손·변환 계약 회귀 테스트 총 113개, 기본 스모크 54개 통과. 실제 Blender에서 전신·반신 FBX와 GLB 생성, 반전 시 손가락 30개 전달 확인. Windows 임시 폴더/소켓 제약은 Linux 컨테이너에서 분리 검증했으며, 소스 옆에 임시 파일을 만드는 캐시 테스트는 컨테이너의 메모리 폴더에서 실행했다.
- 검수 기록은 자동 시각 검수이며 사용자 수동 검수나 모든 체형의 미세 손 접촉 인증을 의미하지 않는다. 새 러프 데이터 전체 A/B 평가를 수행했다고 표시하지 않는다.
- 로컬 증빙: `data/diagnostics/thumbnail-library-5920-20261105/`의 검증·배포 영수증. 라이브러리, 사용자 입력, 캐릭터 자산은 Git에 포함하지 않는다.

## 배포 및 롤백

라이브러리·스타일·검수 FBX를 각각 내용 해시가 붙은 S3 경로로 올리고, 현재 스테이징 task definition의 설정을 복제해 이미지와 해당 자산 핀만 변경한다. BFF의 `POSE_THUMBNAIL_REVISION`은 스타일 압축의 SHA256으로 갱신한다. 등록 직전에 기존 task definition이 달라지지 않았는지 검사한다. 문제가 있으면 배포 영수증에 저장한 이전 task definition으로 되돌린다. 운영 환경은 변경하지 않는다.
