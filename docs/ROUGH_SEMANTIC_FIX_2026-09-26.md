# 러프 의미 검색 원인 분석과 수정 결과

2026-09-26 · 최종 재현 자산: `artifacts/rough_semantic_fix_20260926/release-run`, `release-index`

## 결론

가장 큰 원인은 **검색 모델보다 색인에 필요한 의미가 없었던 것과 조건을 문장 하나의 유사도로 합친 것**이다. 같은 E5 모델과 같은 라이브러리를 유지하고 색인·부위 조건 비교를 바꿨다. `/analyze`에서도 opt-in으로 실제 후보와 썸네일 URL을 반환한다.

이것은 모든 컷의 자세가 정확해졌다는 결론이 아니다. 완전한 팔·다리·접촉 조합의 부족과 소품/행동 의미 미검증이 남는다. 현재 후보는 원본 BVH 전체이며 상하체 조합이나 refine 결과가 아니다.

[실제 모델 전후 비교](http://127.0.0.1:8773/comparison/index.html) · [질의별 전체 결과](http://127.0.0.1:8773/release-run/review/index.html)

기존 E5의 revision, tokenizer, prefix, pooling, L2 정규화 및 ONNX 구현은 그대로 사용한다. 임베딩이나 ANN을 바꾸지 않고도 색인 개선만으로 변화가 확인되었다. 1,215개 규모에서는 전수 점수 계산이 가능하므로 이번 구현은 ANN 근사 오차가 없다.

## 2. 라이브러리 규모와 부족분

|---|---:|---:|
| 서기 | 789 | 396 |
| 좌면에 앉는 형태 | 128 | 64 |
| 쪼그리기 | 40 | 20 |
| 무릎 꿇기 | 19 | 10 |

복수 구조에 해당하는 포즈가 있으므로 행의 합은 전체와 다르다. 좌면·바닥의 실제 접촉을 검증한 라벨이 아니라 몸의 기하에 대한 규칙 판정이다. 미분류 223개에 다른 유용한 포즈가 있을 가능성이 있다.

현재 규칙에서 **양 무릎을 꿇고 팔로 자기 몸을 감싸는 조합**, **앉아서 책상 위 팔에 머리를 기대는 조합**은 충분한 후보를 찾지 못했다. 라이브러리 전체에 정말 없는지와 측정 규칙이 놓쳤는지는 추가 수동 분류가 필요하다. 실패를 숨겨 서 있는 팔짱 포즈를 정답으로 표시하지 않고, 불일치 항목을 가진 수정용 근사 후보로 반환한다.

## 3. 구현한 검색 과정

1. 러프에 대한 기존 VLM 응답을 한 번만 사용한다. 추가 VLM 호출 없이 슬롯과 evidence_note를 읽는다.
2. 원본 박스·인물 귀속·가시성을 검사하고 기존 라우터의 인물별 S 경로를 실행한다. 그룹 관계 경로는 없다. 하체 단독 컷 제외는 유지한다.
3. 전신/상체/하체 질의에서 시점만 있는 문구를 제외한다. 서로 다른 슬롯 가설은 각각 조회한다.
4. 현재 BVH로 생성한 자연어 구조 문서를 E5로 검색한다. 문장 절별 점수를 평균하고 동일 문구 반복을 제거한다.
5. 전체 1,215개 후보에 대해 요청에 해당하는 지지 형태, 손 높이·위치, 팔·다리 조건을 비교한다. 이미 나온 Top-5만 재정렬하지 않는다.
6. `supported`이면서 body_shape/contact_cue 근거인 지지 상태는 compatible → unknown/partial → contradiction 순으로 검토한다. 이는 VLM 가설 내 의미 후보 순위이며 기존 기하 후보를 제거하지 않는다. tentative/scene_context는 약한 선호로 사용한다.
7. 조건의 최대 불일치와 평균 불일치를 별도로 반영해 한 사지의 큰 오류가 여러 유사점에 가려지지 않게 한다. 같은 mirror 가족에서 하나를 남긴다.
8. Top-K, 구조 조건별 비용, 지지 판정, 미검증 의미, 원본 BVH URL, 정면/3·4 모델 URL을 반환한다. 정확 일치나 refine 권한은 부여하지 않는다.

`a_minimal_support.py`, `b1_pose_facts.py`의 기존 2D A/B1 경로는 그대로 있다. 이번 의미 후보 내부 검토는 새 3D 구조 모듈이며, 기존 A/B1을 실행했다는 뜻은 아니다. 기하 후보와 의미 후보의 최종 통합/카메라 맞춤은 별도 단계다.

## 4. 같은 러프에 대한 최종 비교

- 실제 러프 17컷, VLM 인물 슬롯 35개.
- 원본 박스 오류 3개는 보류, 32명 검색.
- 계획된 의미 요청 162개 중 시점 단독 20개 제외, 실제 포즈 후보 반환 142개.
- 동일한 각 인물의 **마지막 전신 질의**를 전후 비교했다. 가장 잘 나온 질의를 사후 선택하지 않았다. 다른 가설과 모든 질의는 전체 결과 화면에 보존했다.
- 모델/라이브러리/VLM 응답은 동일하다. VLM의 이미 존재하는 근거 설명 사용과 자연어 문서 생성도 수정 범위에 포함된다.

| 자동 구조 지표 | 기존 | 자연어 문서·절별 검색·미러 다양성만 적용 | 구조 조건 검토까지 적용 |
|---|---:|---:|---:|
| Top-1 구조 조건 통과 / 32 | 13 (40.6%) | 21 (65.6%) | 30 (93.8%) |
| Top-5 중 조건 통과 후보 있음 / 32 | 17 (53.1%) | 26 (81.3%) | 30 (93.8%) |
| Top-1 지지 형태 compatible / 31 | 18 | 26 | 30 |
| Top-1 명시적 지지 형태 모순 / 31 | 11 | 4 | 0 |

**40.6% → 93.8%, +53.1%p는 내부 구조 검사 통과율이다. 검색 정확도 향상률이 아니다.** 같은 규칙이 순위와 검사에 사용되므로 독립 평가가 아니다. 32명 중 11명은 검사 가능한 세부 사지 조건이 없으며, 27명에는 적어도 하나의 미검증 문구가 있다. 따라서 이 수치를 작가 채택률이나 정답률로 쓰면 안 된다. 화면에서 작가의 `바로 사용 가능 / 수정하면 사용 가능 / 사용하기 어려움 / 판단 불가`를 받아야 실제 품질을 계산할 수 있다.

중간 실험의 16→30, 14→30 등은 조건 정의가 확정되기 전 수치다. 최종 수치는 `diagnosis.json`의 13→30을 사용한다. 개발 사례로 반복 점검한 결과이며 별도 holdout 성능은 아직 없다.

## 5. 실행·API·롤백

기본 평가 구현은 `structured_v2`, 이전 구현은 `--implementation dense_v1`로 별도 빌드하여 비교할 수 있다. 빌드에는 DB·BVH·격리 목록·encoder profile·구현·벡터 해시가 묶인다. 다른 버전의 빌드를 억지로 재사용하지 않는다.

```bash
.venv/bin/python scripts/eval_rough_semantic.py \
  --responses artifacts/rough_vlm_review_20260926/flash-lite \
  --out <새 평가 폴더> --build <새 색인 폴더>

.venv/bin/python scripts/eval_rough_semantic_fix.py \
  --root artifacts/rough_semantic_fix_20260926 \
  --run release-run --index release-index
```

현재 로컬 검증 빌드를 `/analyze`에 연결하는 설정:

```bash
EXPERIMENTAL_ROUGH_ROUTER_MODE=shadow
EXPERIMENTAL_ROUGH_SLOTS_ENABLED=1
ROUGH_SEMANTIC_ENABLED=1
ROUGH_SEMANTIC_BUILD_DIR=artifacts/rough_semantic_fix_20260926/release-index
ROUGH_SEMANTIC_FACTS_PATH=artifacts/rough_router_phase2_20260922/semantic-refresh/current-member-facts.jsonl
```

응답은 `rough_semantic.people[].queries[].results`에 들어간다. `person_index`는 VLM의 원래 인덱스다. 기존 `people[].candidates`와 혼합하지 않는다. 새 응답에는 `bvh_url`, `preview_urls.front`, `preview_urls.three_quarter`, `constraint_costs`, `violations`가 있다. `score`는 임베딩 유사도이고 실제 순위는 구조 검토를 포함하므로 점수 내림차순과 다를 수 있다.

- API 기본값은 off. 운영 배포/기동 설정은 변경하지 않았다.
- `ROUGH_SEMANTIC_ENABLED=0`이면 추가 검색을 끈다.
- 색인 실패는 `rough_semantic.status=unavailable`, 슬롯 부재는 `insufficient_semantics`로 반환하고 기하 결과를 보존한다.
- router 로그에는 실행된 의미 후보와 build ID도 남긴다.
- 파일 복구: `scripts/rollback_rough_router.py artifacts/rough_semantic_fix_20260926/checkpoint.json`으로 먼저 dry-run. `--apply`는 이 작업 이후 수정이 없을 때만 복구한다. 이전 작업 체크포인트보다 이번 것을 먼저 복구해야 한다.

## 7. 남은 품질 경계

- 자유형 의미는 E5가 처리하지만 결정적 구조 검사는 현재 지원하는 조건만 검증한다. 부정문·복합 OR·소품·세부 손가락·타인과의 접촉까지 완전한 의미 논리를 구현한 것은 아니다.
- 정적 BVH 하나로 걷기/달리기 동작의 시간적 의미나 바닥 접촉을 증명할 수 없다. 보폭 등 기하만 비교한다.
- VLM의 잘못된 인물 수, 좌우 해석, 불충분한 자세 설명은 검색만으로 복구되지 않는다.
- 상세 의미 미검증, 미분류 라이브러리, 근사 후보는 API와 평가 화면에 공개한다. 채택률이 확인되기 전 운영 품질 승격을 선언하지 않는다.
- 다음 품질 작업은 이 화면의 작가 평가와 미분류/희소 자세의 실제 모델 검수다. 라이브러리 확장은 무조건적인 배수 증가보다 꿇기·좌면 앉기·누움·손-몸 접촉 조합의 부족분을 채우는 것이 타당하다.
