# 그룹 경로 제거와 실제 의미 검색 실행 검증

> 2026-09-26 · 사용자 변경 지시 반영 · 저장된 Flash-Lite 17컷 재사용 · 새 VLM 호출 0

## 1. 변경

- 새 라우터의 `unsupported_group_relation`, `group_excluded` 입력, 관계 대상 전파를 삭제했다. `contact`/`entangled` 및 컷 전체 `hugging`/`fighting`/`holding_hands`로 검색을 제외하지 않는다.
- 기존 `Pipeline._evaluate_slot`의 얽힘 세트 미구현 강제 폴백도 제거했다. 모든 인물은 같은 인물 귀속·관측 관절·구조 안전 조건으로 검색한다. 관계 태그만 바꿨을 때 solo와 동일한 후보를 반환하는 회귀 검사를 추가했다.
- 신규 VLM 프롬프트는 그룹 관계를 분류하지 않는다. 기존 JSON 호환용 `relationship`는 `solo`로 고정하고 확장 슬롯의 interaction/related_person_indices는 요청하지 않는다. 과거 응답의 관계 필드는 재현·감사를 위해 읽을 수 있지만 경로 결정에 쓰지 않는다. 접촉 중인 인물도 각각 세도록 명시했다.
- 하체 단독 입력 제외는 유지한다. 인물 귀속이 불명확하면 보류한다.
- 재검수에서 발견한 정규화 박스 범위 오류는 clip/추정 보정하지 않고 거부한다. 저장된 3개 잘못된 박스가 새로운 개인 검색에 잘못 연결되지 않도록 replay와 shadow 모두 검증한다.

## 2. 기존 의미 검색에 바로 연결한 경우의 문제

저장된 슬롯에서 생성한 의미 질의는 **162개 전부 기존 v2 한국어 규칙 파서에서 `clarify`**로 분류됐다. 검색 전 되묻기로 끝나므로 그대로 연결할 수 없다. 실제 작가에게 질문하지 않았다.

기존 의미 빌드 5개를 현재 DB 기준으로 검사했다. 3개는 geometry DB mismatch, 2개는 manifest schema mismatch로 로딩 조건을 통과하지 못했다. 이 파일들의 해시를 바꾸거나 검증을 우회하지 않았다. 상세: `run2/existing-runtime-audit.json`.

## 3. 실제 실행한 경로

```text
저장된 Flash-Lite 원문 + 동일 이미지/기존 관절 캐시의 해시 검증
 → 인물별 슬롯 파싱 + 박스·관절 귀속 검증
 → 그룹 선택지가 없는 SearchPlan
 → 모든 S_upper / S_lower / S_full 질의
 → 고정된 실제 ONNX multilingual-E5-small 인코더
 → 현재 BVH 측정값으로 만든 부위별 문서와 유사도 검색
 → 질의당 Top-5 실제 라이브러리 member 반환
 → 후보 ID·BVH 해시·격리 정책 검증 및 원문 로그
```

`src/experimental/rough_semantic.py`에 재사용 가능한 `RoughSemanticSearch`와 `execute_semantic_plan`을 구현했다. 운영에서 쓰는 pinned E5 인코더를 그대로 사용하고, 비어 있지 않은 영문/한글 질의를 규칙 파서가 선행 차단하지 않게 했다.

실험 색인은 현재 DB와 해시가 일치하는 1,215개 BVH 측정값을 사용한다. 33개 기존 격리 포즈는 제외한다. 전신/상체/하체 **3,645개 문서**는 관측된 관절 관계에서 생성하며, 없는 동작 태그나 접지 상태를 꾸며 넣지 않는다. 좌우 member를 보존한다. 문서 길이 제한은 관절 관계 경계에서 분할하여 처리하며 토큰을 조용히 잘라내지 않는다. 첫 빌드 시 길이 제한 오류를 확인해 이 처리를 추가했다.

부위별 문서로 검색하지만 반환 객체는 **전신 BVH member**다. 실제로 팔·다리를 잘라 붙이거나 상하체 조합을 완료했다는 뜻이 아니다. 기존 `/semantic-search` v2와 완성된 v3.3 빌드로 위장하지 않는 별도 실험 색인이다.

박스 오류로 보류한 사례는 `131040:P1`, `131040:P2`, `131127:P3`다. 두 번째 사례는 그룹 태그의 차단은 제거됐지만 잘못된 박스라는 별도 문제로 여전히 보류된다. 독립 여성 `131056:P2`와 좌측 남성 `131112:P0`은 이제 실제 의미 검색을 실행한다.

후보는 현재 DB에 존재하며 반환 시 BVH 해시를 검증했다. `match_source=semantic_rough`, `exact_match_status=not_evaluated`, `refine_allowed=false`를 유지한다. E5 유사도는 정확도·확률이 아니다. 유사도 순위로 항상 Top-K를 반환하는 시험이므로 **162/162 반환을 정확도 100%라고 해석하면 안 된다.**

예시: 무릎 꿇기 124637의 전신 질의는 `g1__M_Move8__n08_f0692`, 앉기 124702는 `MH__callharvey3d_sittingfloorstretch2`를 Top-1으로 반환했다. 이들은 실제 반환 ID이지 올바른 정답으로 판정한 포즈가 아니다. 모델 포즈의 작가 채점은 아직 없다.

## 5. 테스트와 한계

- 라우터 회귀: **30/30**.
- 기존 파이프라인/관절 추출: **35/35**. 관계 태그로 인물을 일괄 차단하지 않는 동작 포함.
- 새 박스·부위 문서·S 실행 계약: **5/5**.
- 이전 단계 카메라·자산/인물 귀속: **11/11**.
- 핵심 smoke: **51/51**.
- 위 단위 검사는 계약 검사이며, 별도로 실제 E5와 현재 라이브러리를 사용한 162건 실행을 완료했다.

**확인한 것은 저장된 VLM 출력 → 인물별 의미 질의 → 실제 현재 BVH 후보 반환까지다.** 새 `/analyze` 요청에서 VLM·포즈 추정을 다시 실행하지 않았다. 운영 `/analyze`에 의미 후보를 섞는 기본값을 켜지 않았고, G/S/F 공통 재정렬·카메라 맞춤·후보 품질 판정·조합·refine은 이번 의미 분기 시험의 범위 밖이다. 기존 파이프라인의 그룹 강제 폴백 제거는 코드에 반영되어 있다.

현재 문서는 정적인 관절 관계 중심이어서 소품·접촉 의도·복잡한 동작 의미가 부족할 수 있다. 저장된 VLM의 인물 병합, 가시성 과신, 동시 동작과 대안 가설 혼합도 자동으로 해결되지 않았다. 다음 검증은 반환된 실제 모델 포즈의 상체/하체 일치 및 수정 가능성을 보고 G/F 근거와 카메라 평가를 연결하는 것이다.

## 실제 모델 이미지 검토 추가 (2026-09-26)

검토 HTML을 원본 러프와 **질의별 실제 Top-5 모델** 비교 화면으로 교체했다. 159개 반환 member의 정면·3/4 미리보기 318개를 사용하며 순위는 바꾸지 않았다. 기본 선택은 지지 상태를 포함한 마지막 전신 질의이며 다른 질의도 선택할 수 있다. 기존 라이브러리 모델 미리보기로, 러프에 맞춘 카메라나 refine 결과가 아니다.

이미지 육안 대조에서 기본 전신 질의 Top-1의 구체적인 불일치를 확인했다: 124629의 손-허리 동작 대신 팔을 옆으로 뻗음, 124637의 무릎 꿇기 대신 서서 팔 교차, 124702의 벤치 앉기 대신 바닥 앉기. 따라서 위 162/162는 검색 연결 성공을 의미하며 실제 자세 품질이 확보됐다는 뜻이 아니다. 작가 정답 채점이나 전체 정확도 수치는 아직 없다.

이후 의미 검색 평가기는 모델 이미지 HTML도 자동 생성한다. 이번 화면 변경의 롤백은 `artifacts/rough_semantic_visuals_20260926/checkpoint.json`이며, 이전 검색 코드까지 복원할 경우 이 checkpoint를 먼저 복원한다.
