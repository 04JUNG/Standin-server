# 소품 포함 포즈: 검색·미리보기·FBX 연결

## 문제와 적용 범위

문장 검색의 `objects=sword` 태그는 동작의 의미를 나타낸다. 태그만으로 검 메시가 존재하는 것은 아니다.
또한 로컬 복구 결과에 소품이 있어도 배포 변환기가 몸·손만 다시 만들면 최종 FBX에서 소품이 사라진다.

이 변경은 R7에서 검수한 170개 장면(손에 드는 소품 150개, 지지대만 있는 장면 20개)을 런타임에 연결한다.
무기에는 검·단검·창·방패·권총·소총·활 등이, 일상 소품에는 컵·휴대폰·책·가방·우산·식기 등이 포함된다.
소품은 형태와 배치를 나타내는 기본 도형 모델이다. 상세 제작 에셋이나 모든 체형의 무관통 보증으로 취급하지 않는다.

## 데이터와 책임 분리

- `converter/scene_library.v1.json`: 원본 BVH SHA256에 결합한 배치 레시피. 승인·보류·제외를 구분한다.
- `converter/scene_hand_stage.py`: 원본 손가락 → 사용자 지정/장면 기본 손 모양 순서로 적용한다.
- `converter/scene_props.py`와 종류별 모듈: 소품 생성, 양손 접촉 보정, 뼈에 고정한다.
- `config/pose_scene_assets.v1.json`: 추론 서버가 읽는 가벼운 물리 소품 목록. 원본·레시피·검수 FBX 해시가 있다.
- `src/pose_scene_assets.py`: 태그와 실제 소품 존재를 구분하고, 검증된 검색 후보 안에서 안정적으로 정렬한다.

변환 순서는 몸/체형 → 원본 손가락 → 손 선택 → 소품 → 절단/카메라 → FBX·GLB·미리보기다.
FBX와 미리보기는 같은 최종 파일을 사용한다. 변환 API는 장면 레시피 영수증도 검사한다.
소품 적용 결과는 몸 리타게팅의 기본 캐시에 저장하지 않는다. GLB 캐시 키에는 손 복원 코드와 장면 레시피 버전을 포함한다.

## 검색 활성화와 배포

`SEMANTIC_REVIEWED_PROPS_FIRST=1`을 **소품 변환기가 배포된 뒤** 추론 서버에 설정한다. 기본값은 꺼짐이다.
요청한 소품이 모두 실제로 포함된 후보를 우선하며 기존 점수, 자격 조건, exact/near 구분, 개수 제한을 유지한다.
응답 `matched.scene_props`에 실제 소품과 적용 범위를 기록한다. 미등록 포즈에 태그만 보고 소품을 만들지 않는다.

배포 순서:

1. 현재 스테이징의 체형 커스텀 변경을 포함한 변환기에 이 변경을 통합한다. 오래된 이미지로 전체 교체하지 않는다.
2. 변환기의 FBX·GLB·미리보기와 캐시 키를 확인한다. 기존 키의 캐시를 새 키로 이름만 바꾸지 않는다.
3. 추론 서버의 목록 파일을 함께 배포한 뒤 정렬 플래그를 켠다.
4. 검·총과 컵·휴대폰 검색에서 후보, 미리보기, 다운로드 FBX를 확인한다.
5. 이상 시 정렬 플래그를 먼저 끄고 기존 태스크 정의로 되돌린다.

이번 로컬 검증 완료를 스테이징 배포 완료로 해석하지 않는다. 현재 스테이징에는 별도 체형 변경이 있어 통합 배포가 남아 있다.

## 검수 증거 (2026-11-03)

- 170개 원본 BVH·레시피·승인 기록과 4범위 FBX/GLB 해시를 검증했다.
- 새 변환기로 검, 반전 검, 소총, 창, 컵, 휴대폰, 책, 반신 컵 8개를 다시 생성했다.
- 8개 모두 FBX 재가져오기에서 소품 메시가 남았고 GLB가 동일한 최종 FBX 해시를 가리켰다.
- 32개 전체 방향 이미지와 32개 손 확대 이미지를 확인했다. 기본 소품의 배치를 확인하는 검수이며 상세 에셋 품질 승인은 아니다.
- 8개 자동 접촉 검사에서 몸/소품 삼각형 교차·포함 정점 0, 양손·자기 손가락·손/몸 검사 통과.
  이는 검사 방식의 범위 안에서 얻은 결과이며 모든 충돌의 완전한 증명은 아니다.
- 관련 회귀 테스트 181개, 스모크 54개, 문법 검사 통과.
- 스테이징 체형 카드 저장·재열기는 별도 UI 검증에서 남성 기본 185cm/근육 0.65로 확인했다.
  앱 종료 후 다시 실행해도 값과 미리보기가 유지됐다. 이 소품 변경의 스테이징 UI 검증과는 구분한다.

로컬 증거는 `data/diagnostics/props-search-export-20261103/`에 있으며 Git에 포함하지 않는다.

## 재생성

```powershell
python scripts/build_scene_asset_catalog.py --base <복구자료> --catalog config/pose_scene_assets.v1.json --coverage <작업폴더>/coverage.json
blender -b --python-exit-code 1 --python tests/converter/verify_scene_delivery.py -- --library <라이브러리> --character <캐릭터.fbx> --out <작업폴더>/delivery
python scripts/build_scene_asset_gallery.py --base <복구자료> --catalog config/pose_scene_assets.v1.json --thumbnails <스타일썸네일폴더> --output <작업폴더>/gallery
python -m http.server 8778 --bind 127.0.0.1 --directory <작업폴더>/gallery
```

갤러리는 검수 자산만 담은 별도 폴더를 제공한다. 복구 자료 루트나 실제 사용자 입력 폴더를 서버 루트로 쓰지 않는다.

## 다음 확장과 제한

전체 5,862개를 조사했다. 검 태그 459개 중 실제 검 모델이 등록된 태그 일치 장면은 26개,
휴대폰 132개 중 3개, 컵 74개 중 5개, 책 41개 중 4개다. 미등록은 모두 결함이라는 뜻이 아니다.
벽·물·다른 사람처럼 동작의 배경을 설명하는 태그도 있어 자동으로 손에 붙이면 안 된다.

무기(검/단검 → 창/방패 → 총/활)와 일상(컵/식기 → 휴대폰/책 → 가방/우산)을 함께 확장한다.
각 포즈에서 사용 손, 접촉 지점, 손 모양, 물체 축을 확인한 뒤 보류 레시피로 만든다.
몸·손·소품 교차 검사 → 전체 4방향/손 확대 검수 → FBX/GLB 동일성 확인을 통과해야 승인 목록을 갱신한다.

원본 BVH가 보정되어 SHA가 달라진 결과에는 기존 장면을 임의로 이식하지 않는다.
사용자 지정 체형·손 모양과 다른 캐릭터는 기준 캐릭터의 승인 증거를 그대로 공유하지 않는다.
BVH에는 소품 메시를 담지 않으며, 소품 출력은 FBX/GLB 대상이다.
