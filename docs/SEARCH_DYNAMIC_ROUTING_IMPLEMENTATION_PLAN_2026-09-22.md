# 다이나믹 라우팅 기반 검색·조합 구현 순서

> 2026-09-22 · 구현 계획. 이 문서의 단계는 아직 완료된 기능을 뜻하지 않는다.
> 목표: 현재 라이브러리에서 작가가 적은 수정으로 사용할 전신 또는 상·하체 조합 후보 제공.
> 상위 전략: [검색 전략 v2](SEARCH_EDITABLE_POSE_STRATEGY_2026-09-22.md).
> 범위 정정: 외부 입력은 러프 이미지뿐이다. 본문의 초기 자연어·사용자 조건·잠금 관련 항목은 이번 구현 범위에서 제외하며 image-only v1.1가 우선한다.
> P2 구현 기준 정책: [라우터 확정 규칙 v1.1](SEARCH_ROUTER_RULES_DRAFT_2026-09-22.md). 확정 규칙에 따라 슬롯·관측 계약을 구체화한 뒤 구현한다.

> 1차 범위: 그룹 관계와 하체 단독 관측 입력은 미지원. 현재 P0/P2 기초 구현과 P1 자산 스냅샷을 진행했으며 실제 검색/조합 연결은 미완료. [AI 작업용 인수인계](HANDOFF_AI.md)의 `T2`에서 현재 상태와 검증 경로를 확인하고, 롤백은 `scripts/rollback_rough_router.py`를 따른다.

## 1. 결정한 순서

```text
P0 계약·평가 기준 고정
   ↓
P1 카메라·자산 기준 정리
   ↓
P2 검색 요구서 + 다이나믹 라우터
   ↓
P3 전신·상체·하체 후보 검색 + A/B1 팩트 재사용
   ↓
P4 공통 골격 + 폭넓은 상·하체 조합
   ↓
P5 공통 카메라 적합·자세 조정·최종 평가
   ↓
P6 실제 모델 작가 평가
   ↓
P7 이미지 API 통합·점진 적용
```

P2의 순수 정책 구현은 P0 이후 P1과 독립적으로 진행할 수 있다. P3 색인/검색 어댑터와 P4 공통 골격 변환도 계약이 정해지면 독립적으로 개발 가능하다. 다만 품질 비교는 동일 자산·카메라 기준에서 합쳐 실행한다. 단계별 구현 완료와 운영 승격은 구분한다. 날짜·소요 시간은 빌드/조합/렌더 시간 측정 후 산정한다.

## 2. 기존 구현과 새 작업의 경계

- `src/routing.py`: VLM shot으로 core/bust/skip을 고르는 기존 조기 라우팅. 관측 관절을 이용하는 새 검색 라우터와 역할이 다르다.
- `src/pipeline.py`: 기존 인물 수·귀속·cascade·confidence 계약을 유지하며 최종 통합 시 검색 오케스트레이터를 연결할 자리.
- `src/experimental/a_minimal_support.py`, `b1_pose_facts.py`: 관측 팩트 계산을 검토해 재사용. 현재 제외 정책과 Top-K 재정렬 정책은 frozen 비교 기준으로 유지한다.
- `src/experimental/intent_fusion.py`: 초기 shadow 비교 기준. 기하 후보가 없을 때 종료하고, 기존 A 제외를 유지하는 현재 구조는 자연어 전용·부위 조합을 포괄하지 못한다. 새 오케스트레이터의 계약을 여기에 억지로 맞추지 않는다.
- `src/semantic_*`: 기존 검색/임베딩/자산 로딩 재사용 가능성을 먼저 확인한다. v3.3는 설계 기준이며 구현된 런타임으로 가정하지 않는다.
- `src/camera.py`, `library.py`, `refine_v2.py`: 투영·색인·보정 규약을 함께 확인한다. 의미 후보의 기존 refine 금지는 새 실험 조정기와 구분한다.

현재 운영의 순수 기하 규칙과 새 의미 결합 실험을 모드로 구분한다. VLM action의 검색 사용과 bust 검색 확장은 이번 목표에 따른 명시적 설계 변경이며, 운영 적용 시 관련 계약/설명도 함께 갱신한다.

## P0. 공통 계약과 평가 기준을 먼저 고정

### 구현할 것

아래 내부 타입을 정의한다. 이름/파일 위치는 구현 시 확정하며 기존 공개 응답과 동일하다고 가정하지 않는다.

- `SearchRequest`: 인물 귀속, 입력 종류, 관측 관절/마스크, 사용자 조건, VLM 가설, 부위 간 관계, 잠금 조건.
- `SearchPlan`: 실행 채널, body_region, 가설, 후보/시간 예산, 실행 사유, 채널 불가 시 복구 정책.
- `CandidateMaterial`: 원본 member ID·mirror·자산 해시, 부위, 검색 출처/순위, A/B1 팩트.
- `PoseProposal`: 원본 또는 조합 포즈, U/L 출처, 공통 골격 버전, 카메라, 검증 결과, 잔여 오류, 생성물 handle.

의미 색인의 `unit/member` scope와 `full/upper/lower` body_region을 별도 필드로 둔다. 관측 없음은 unknown이고 일치 점수 0 또는 만점으로 바꾸지 않는다. 기하 L2와 임베딩 유사도를 무보정 합산하지 않는다.

기존 28명과 작가 판정은 개발 비교 기준으로 봉인한다. 새 holdout, 실제 모델 평가시트, 동일 Top-K/수정 시간 예산을 준비한다. 이전 성공/실패 라벨을 새 목표에 맞춰 덮어쓰지 않는다.

### 완료 기준

전신 러프·반신 러프·자연어 전용·관절 실패·부위 잠금·상충 조건·다인 접촉을 계약으로 표현할 수 있다. 생성 후보를 원본 pose_id로 잘못 내보내지 않는 경계가 명확하다.

## P1. 카메라와 라이브러리 기준 정리

### 구현할 것

1. 앞/뒤·좌/우·깊이·yaw/elevation/roll·원근 규약을 투영, 실제 모델 렌더, 직렬화에서 일치시킨다.
2. 단순 2D 관절 오차 외에 비대칭 포즈와 가림 순서로 물리적 앞뒤를 검증한다. 앞면 미리보기 토글만 바꾸는 것으로 끝내지 않는다.
3. 평가용 geometry DB와 원본 BVH 목록/해시를 고정한다.
4. 같은 자산을 대상으로 의미 빌드를 명시 선택하고 대응 member를 검증한다. 기존 빌드의 manifest를 고쳐 불일치를 숨기지 않는다.
5. 현재 자산을 쓰는 개발용 빌드와 v3.3의 봉인된 승격 자산을 구분한다. 다른 inventory의 결과로 기존 승격 기준 통과를 주장하지 않는다.

### 완료 기준

검색 투영과 결과 모델의 방향·관절·가림이 설명 가능하게 일치한다. 의미 후보가 참조하는 모든 원본을 동일 라이브러리에서 확인할 수 있다. 카메라 교정 전/후 결과와 해시는 별도로 남긴다.

## P2. 인물별 VLM 의미 슬롯과 다이나믹 라우터

### 선행 순서

1. [image-only 규칙 v1.1](SEARCH_ROUTER_RULES_DRAFT_2026-09-22.md)의 확정 경로를 구현 기준으로 적용한다.
2. 기존 VLM 1회 분석을 인물별 의미 슬롯으로 확장한다. 상체 동작, 하체 형태/지지 상태, 부위 가시성, 접촉, 시점, 관계를 근거와 unknown/대안 가설로 출력한다.
3. 현재 강제 단일 선택 프롬프트를 수정하고 schema/provider/인물 귀속 검증을 함께 맞춘다. 관절 좌표는 VLM이 생성하지 않는다.
4. 같은 러프에서 얻은 관절과 슬롯의 가시성·귀속 충돌 처리, 부위별 기하 가능성을 구현한다.
5. 고정 슬롯 replay로 결정적 규칙을 먼저 검증하고 실제 VLM 출력까지 포함한 흐름을 평가한다.

입력은 이미지뿐이다. 의미 검색 문장은 유효한 VLM 슬롯으로 구성한다. 사용자 요구·자연어 진입·부위 잠금은 라우터 입력에 없다. 관측 가능한 부위는 G, 구체적인 의미는 S, 유효 관절 팩트는 F, 단서 없는 한쪽 부위의 완성 대안은 D를 사용한다. 적격 U/L이 있으면 전신과 함께 C를 탐색한다.

bust/half 조기 종료를 새 실험 경로에 맞추고, count reconcile과 귀속 신호는 유지한다. VLM 의미 성공이 기하 신뢰도를 승격하지 않는다. 채널 실패·자산 불일치·근거 부족을 기록하며 mock로 품질 평가를 채우지 않는다.

### 완료 기준

슬롯 누락/unknown/복수 가설/잘못된 인물 귀속, 가시성 충돌, 관절 실패, 반신 하체 맥락/무근거, 얼굴/다인 예외를 재현한다. VLM 오류와 라우터 오류를 분리할 수 있고 가려진 관절은 기하 성공으로 처리되지 않는다.

## P3. 전신·부위 후보 검색과 A/B1 팩트 통합

### 구현 순서

1. `retrieve(request, plan) → materials` 공통 인터페이스와 채널별 trace를 만든다.
2. 전신 기하/의미 어댑터로 실제 같은 DB의 후보 합집합을 먼저 실행한다.
3. 상체/하체 기하 피처·정규화를 정의한다. 부분 anchor/결측 처리와 query/library 대칭성을 검증한다.
4. 실제 부위 사실에 근거한 상체/하체 문서·임베딩을 만든다. v3.3 부위 색인 확장 변경안을 별도로 남기고, 전신 임베딩을 부위 검색 구현으로 간주하지 않는다.
5. A/B1 관측 팩트 기반 보완 검색을 넣는다. 구조 조건은 전체 후보의 선행 강제 필터가 되지 않는다.
6. 범위별 합집합·출처 보존·좌우/mirror 처리·부분 다양성을 적용한다. 필요하면 RRF로 작업 순서를 정하고 각 채널/가설 후보가 평가 기회를 갖게 한다.

v3.3 구현은 member 사실·검색 문서·dense 회수부터 진행한다. 엄격한 자연어 조건의 exact 판정 전체를 먼저 완료해야 부위 조합에 착수할 수 있는 순서로 만들지 않는다. 아직 검증하지 않은 조건은 충족으로 표시하지 않는다.

### 완료 기준 / 첫 중간 결과물

같은 입력에 대해 전신·상체·하체 후보를 실제 모델로 나란히 볼 수 있다. “서 있는 팔짱 상체”와 “팔이 다른 무릎 꿇기 하체”가 각각 재료로 회수되는지 확인한다. 전신/부위/기하/의미/구조 출처와 누락 이유가 기록된다. 이 단계의 시트는 재료 검수이며 조합 성공/최종 정확도로 보고하지 않는다.

## P4. 넓은 상·하체 조합

### 구현할 것

공통 골격·기준 자세·축 변환, root/pelvis/spine 소유권을 정한다. lower의 root/pelvis를 기반으로 upper를 pelvis-relative로 재구성하고, Hips에 들어 있는 상체 기울기를 잃지 않게 한다. 원본 채널 단순 이어붙이기는 사용하지 않는다.

고정 템플릿 외에 검색한 적격 U/L 조합을 지원한다. 원본/좌우 변형·누움/기댐/비틀림을 표현할 수 있게 설계하고 부류별 실제 검증 커버리지를 기록한다. 손가락과 다인 결합은 독립 계약을 갖는 후속 범위로 명시한다.

쌍의 골격/접합 가능성을 먼저 평가하고, 유망한 쌍과 다른 자세 가설만 정밀 solve한다. 라이브러리 전체 N×N을 저장하지 않는다. 전신 후보도 같은 후보 목록에 유지한다.

조합 결과는 재현 가능한 BVH/내부 포즈와 출처를 갖고, 실패 시 해당 조합을 버린다. 독립 부위끼리 잘 맞았다는 이유로 전신 성공으로 처리하지 않는다.

### 완료 기준 / 두 번째 중간 결과물

검색한 U/L로 실제 모델을 생성해 전신 원본과 비교할 수 있다. 서로 다른 소스 골격, 허리 경계, 좌우, 기울기, 접촉 실패 사례를 확인한다. 제한된 템플릿 데모만으로 넓은 조합 완료를 선언하지 않는다.

## P5. 공통 적합·조정과 최종 평가

### 구현할 것

원본/조합 후보를 같은 평가 인터페이스로 처리한다. 원본과 조합에는 각각 가능한 안전 베이스와 복구 대상을 명시한다.

1. 완성 후보의 거친 카메라 가설을 탐색한다.
2. 소수 가설 주변에서 카메라를 세밀하게 맞춘다.
3. 제한된 관절 보정과 필요 최소 반복을 실행한다.
4. A/B1 팩트, 의미 조건, 상체/하체 오차, 접촉, 실제 메시 상태를 재평가한다.
5. 유효하지 않은 결과를 제외하고 조건 충족/근사 대안을 구분한다.
6. 남은 수정 부담과 다양성으로 Top-K를 고른다. 관측 없는 부위는 기하 성공 점수가 없다.

기하/조합 후보의 공통 적합 코드는 공유하되 입력 자격과 안전 검증을 생략하지 않는다. 기존 의미 후보 refine 금지를 flag 하나로 풀지 않는다. 새 실험 조정 계약으로 실행하고 출처·원본·결과 검증을 보존한다.

최종 조합에는 하나의 카메라만 적용한다. 자동 변형량은 안전 진단, 작가 수정 부담은 별도 항목이다. 후보·시점 증가에 따른 시간, 앞뒤 혼동, 하체 악화, 극단 원근/roll 보상을 함께 측정한다.

### 완료 기준

전신/조합이 같은 기준으로 비교되고 상체 평균이 하체 실패를 숨기지 않는다. preview와 내보내는 결과가 같은 최종 포즈/카메라를 참조한다. 유한값·소유권·안전 베이스 복구·접촉·관측 마스크 검증이 통과한다.

## P6. 실제 모델 기반 작가 평가

### 비교 실험

동일 라이브러리·컷·Top-K·수정 예산에서 다음을 분리한다.

1. 기존 기하 검색 및 기존 A/B1 기준선.
2. 새 라우팅 + 전신 기하/의미 합집합.
3. 부위 검색 + 조합 추가.
4. 자동 적합/조정 추가.

가능한 개발 사례에서는 모든 유효 채널을 실행하는 예산 확대 기준과 라우터도 비교한다. 라우터가 좋은 후보 경로를 너무 일찍 끄는지, 비용을 얼마나 줄이는지 따로 본다. 가설 수/카메라 수 확장 회귀도 별도 기록한다.

지표: 정해진 수정 예산 안의 Top-K 활용 가능률, 수정 없이 사용 가능한 비율, 실제 수정 시간, 의미 보존, 상체/하체 개별 판정, 기존 성공→실패, 채널별 지연 및 전체 p50/p95. 수정 부담 대리 점수를 실제 시간으로 보고하지 않는다.

### 완료 기준

방법 이름을 가린 실제 모델 시트와 작가 편집 과제 결과가 있고, 기능별 이득/회귀와 비용을 구분할 수 있다. holdout과 승격 기준은 결과를 보기 전에 고정한다. 개선이 확인되지 않은 경로는 실험 상태에 두고 원인을 수정한다.

## P7. 이미지 API 통합과 점진 적용

### 구현할 것

`Pipeline.process_cut`에서 버전 선택 가능한 검색 오케스트레이터를 호출한다. 이미지에서 만든 인물별 슬롯·관절로 SearchRequest/Plan/Candidate를 구성한다. 별도 자연어 API를 이번 라우터의 입력으로 연결하지 않는다. 기존 응답 계약과 BFF 변경점을 명시한다.

생성 후보에는 U/L ID·해시, rig/조합 버전, 최종 BVH handle, 카메라, 검증 상태가 필요하다. 원본 ID 다운로드로 조합 결과를 대체하지 않는다. 실제 CSP/뷰어 구현은 담당 팀과 연결할 계약으로 전달한다.

캐시는 이미지·인물 슬롯·관측·VLM 모델/프롬프트·원본/rig·라우터/카메라 정책 버전을 포함해 잘못된 재사용을 막는다. 부위별 observed/inferred/unspecified를 결과 계약으로 전달한다.

기능별 off/shadow/on을 둔다. shadow에서는 기존 응답을 유지하고 신규 후보를 기록한다. 승인된 자산과 검증된 경로부터 제한 적용하며 오류 시 검증된 기존 경로로 복구한다. 외부 API/모델 호출 수와 timeout도 trace에 기록한다.

### 완료 기준

러프별 슬롯/관절/최종 후보의 귀속이 유지되고, 결과 화면과 실제 전달 BVH가 일치한다. 의미 장애·조합 실패·timeout·자산 불일치에 대한 복구가 확인된다. 기존 smoke/API/feature 대칭성/refine 안전 계약과 새 통합 계약이 통과한다.

## 3. 라이브러리 확장과 후속 학습

라이브러리 보강은 P0부터 별도 버전으로 병행한다. 검색 실패/접합 실패/재료 부재/스키닝 실패를 구분하고 실제 재료가 없는 행동·하체 상태를 우선 채운다. 고정 라이브러리 실험과 확장 라이브러리 실험은 별도 표로 보고한다.

파인튜닝·학습 기반 라우터·학습 리랭커는 선택/기각/수정 로그와 비교 기준이 쌓인 뒤 검토한다. 원본 Sketch2Pose 생성 후보 연결도 이번 필수 구현 경로의 선행 조건으로 두지 않는다.

## 4. 최초 착수 묶음

첫 작업 범위는 P0 + P1의 재현/교정 + P2의 오프라인 SearchPlan이다. 완료 시 입력별 실행 경로와 이유를 확인할 수 있다. 이어서 P3에서 실제 재료 검색을 확인하고 P4를 붙인다. 라우터만 만든 상태를 검색 정확도 개선 완료로 보고하지 않는다.
