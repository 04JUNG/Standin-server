# 검색 전략 v2 — 수정해서 쓸 수 있는 포즈를 검색·조합한다

> 2026-09-22 사용자 피드백 반영. 이전 목표 파이프라인의 후보 결합, A/B1 배치, 조합 우선순위를 대체하는 설계 제안.
> 이 문서의 통합 구조는 구현 완료 상태가 아니다. 기존 `intent_fusion`은 비교 기준인 초기 shadow 구현으로 유지한다.
> 실행 순서와 단계별 완료 기준: [다이나믹 라우팅 구현 계획](SEARCH_DYNAMIC_ROUTING_IMPLEMENTATION_PLAN_2026-09-22.md).

> 입력 범위 정정: 이번 구현은 러프 이미지와 그 이미지에서 도출한 VLM 슬롯·관절만 사용한다. 본문의 자연어 입력·사용자 조건·잠금은 이전 확장 구상이며 현재 라우터 범위에서 제외한다. [확정 규칙 v1.1](SEARCH_ROUTER_RULES_DRAFT_2026-09-22.md)가 우선한다.

> 1차 제외: 그룹 관계 후보와 하체만 보이는 입력. 상체·전신 경로를 우선 구현하며 제외 입력은 명시적 미지원으로 기록한다.

## 1. 목표와 변경점

목표는 원본 라이브러리에서 러프와 가장 가까운 자세 하나를 고르는 것이 아니라 **현재 자산으로 작가가 적은 수정 후 사용할 수 있는 포즈를 제공하는 것**이다. 라이브러리 확장은 병행하지만 확장 완료를 검색 개선의 선행 조건으로 두지 않는다.

- 기하와 의미는 독립적으로 후보를 넓히는 검색 채널이다. 둘 다 맞는 교집합만 남기거나, 기하 Top-5 안에서만 의미 재정렬하지 않는다.
- 전신, 상체, 하체 검색을 처음부터 나눈다. 전신 후보와 상·하체 조합 후보가 동시에 만들어져 같은 최종 평가를 받는다.
- A/B1의 관측·구조 팩트를 후보 탐색, 조합 탐색, 조정 후 평가에서 재사용한다. 모두를 뒤쪽의 일괄 탈락 게이트로 만들지 않는다.
- 시스템이 크게 조합/보정해도 작가가 바로 쓸 수 있다면 유용하다. 원본 BVH 대비 회전 변화량은 안전 진단이며 작가의 수정 비용과 동일하지 않다.

## 2. 전체 파이프라인

```text
러프 컷 + 선택적 사용자 요구 / 독립 자연어
  ↓
인물별 의도·증거 구조화
  사용자 지정 / 실제 관측 / VLM 추정 / 불명확
  상체 동작 / 하체 상태 가설 / 부위 간 관계 / 관측 마스크
  ↓
동일 원본 라이브러리에 대한 병렬 후보 탐색
  ┌ 전신: 전신 기하 + 전체 문장 의미 + 구조 조건 보완
  ├ 상체: 상체 기하 + 상체 문장 의미 + 팔/몸통 팩트 보완
  └ 하체: 하체 기하 + 하체 문장 의미 + 다리/지지 팩트 보완
  ↓ 각 범위 안에서 후보 합집합, 출처·가설 보존
  ┌ 전신 후보 ─────────────────────┐
  └ 상체 U × 하체 L → 접합 후보 탐색 ─┤
                                    ↓
              공통 골격의 완전한 포즈 후보
                                    ↓
       후보별 카메라 적합 + 제한된 자동 조정
                                    ↓
    의미·상체·하체·관계 일치 / 실제 메시 / 남은 수정량 평가
                                    ↓
      작가가 쓸 수 있는 다양한 Top-K
      직접 사용 / 자동 조정 결과 / 조합 결과
                                    ↓
      “상체 유지”, “하체 앉기”, “이 손 위치 유지”로 재탐색
```

위 병렬은 논리적 경로이며 실제 동시 실행 수는 비용 측정 후 정한다. 자연어 전용 경로는 관절/러프 정합 점수가 없고 의미·구조 조건만으로 각 범위를 탐색한다.

## 3. 기하와 시맨틱을 어떻게 나누고 합치는가

### 3.1 입력을 먼저 부위와 관계로 분해한다

예: “팔짱을 끼고 무릎을 꿇은 인물”.

| 범위 | 의미 검색 문장 | 기하 검색 대상 |
|---|---|---|
| 전신 | 팔짱을 끼고 무릎을 꿇은 자세 | 실제 보이는 전체 관절 |
| 상체 | 팔짱을 낀 상체 | 실제 보이는 몸통·어깨·팔 |
| 하체 | 무릎을 꿇은 하체 | 실제 보이는 골반·다리 |
| 관계 | 손/팔 교차, 지지·접촉 등 명시된 관계 | 해당 부위가 관측될 때의 관계 |

상체 검색에서 하체가 다른 후보를 감점해 버리면 쓸 수 있는 팔짱 재료를 잃는다. 하체 검색에서도 팔 동작은 평가하지 않는다. 손–무릎 같은 상·하체 간 관계는 삭제하지 않고 최종 전신/조합 평가로 넘긴다.

한 전신 텍스트 임베딩만으로 부위 검색을 흉내내지 않는다. 부위별 문서/임베딩은 실제 부위 사실에서 생성한다. 현 v3.3 문서 유형·predicate 계약에 없는 부위 색인 변경은 별도 변경안과 평가를 통해 추가한다. 구현 전 부위 검색기의 존재를 가정하지 않는다.

### 3.2 각 범위에서 독립적으로 후보를 찾는다

각 범위 s에 대해:

```text
G_s = 해당 범위의 관측 기하로 검색한 후보
S_s = 해당 범위의 동작 설명으로 의미 검색한 후보
F_s = 확인 가능한 구조/부위 조건으로 보완 검색한 후보
P_s = G_s ∪ S_s ∪ F_s
```

`F_s`는 A/B1의 정보를 Top-5 이후에만 쓰지 않기 위한 후보 확보 경로다. 예를 들어 “팔꿈치가 굽고 손목이 높음” 또는 “양 무릎이 명확히 굽음”을 만족하는 재료도 별도로 찾는다. 유효 관측이 없으면 해당 조건 채널을 실행하지 않는다. 구조 조건 하나가 전체 검색의 선행 필터가 되지 않게 독립 경로를 유지한다.

후보 수는 전신/상체/하체, 기하/의미, 자세 가설별 예산으로 제한한다. 초기 파일럿 예시는 채널별 20개이며 성능값이 아니라 조정할 탐색 예산이다. 의미 Top-20과 기하 Top-20의 합집합이 기본이며, 조건 검색 예산과 중복 제거를 별도 기록한다.

### 3.3 합집합을 언제 줄이는가

1. 같은 scope·pose member·가설의 중복을 합치고 검색 출처·순위를 모두 보존한다.
2. 같은 family의 mirror는 좌우 의미가 확정되기 전 무조건 합치지 않는다. 부위 검색은 해당 부위의 유사도도 사용해 하체만 다른 상체 후보가 목록을 독점하지 않게 한다.
3. 제한된 작업 큐의 순서를 잡는 용도로 RRF 등을 시험할 수 있다. 임베딩 유사도와 기하 L2를 무보정 합산하지 않는다.
4. 채널별 단독 유효 후보와 다른 자세 가설이 조기에 전부 사라지지 않도록 후보 확보율을 측정한다. 고정 의미 순위 구간 밖으로 B1이 절대 못 나가게 하는 규칙은 최종 설계에서 강제하지 않는다.
5. **최종 Top-K는 자동 조정/조합 후의 완전한 포즈를 평가해서 선정**한다. 검색 순위 합산만으로 종료하지 않는다.

기하만 좋은 후보, 의미만 좋은 후보도 수정 후 좋아질 수 있다. 합집합이 넓힐 가능성과 비용을 함께 측정한다. 의미 후보가 가리키는 미리보기 카메라를 러프 정합 카메라로 쓰지 않는다.

### 3.4 반신의 하체 채널

반신에서 하체가 가려졌다면 `G_lower`와 관측 무릎 팩트는 없다. 대신 원본 컷 맥락의 자세 가설 또는 사용자 조건으로 `S_lower`를 수행한다. 서기/앉기가 모호하면 각각의 후보군을 유지한다. 다리 좌표를 생성해 기하 점수를 채우지 않는다. 기본 서기만 제공하는 정책은 사용하지 않는다.

## 4. A/B1은 게이트인가, 사후 검토인가

**둘 중 하나로 고정하지 않는다. 재사용 가능한 구조·부위 증거와 비교 함수로 만든다.**

| 시점 | A 계열 | B1 계열 |
|---|---|---|
| 검색 입력/색인 | 자세·지지 형태 가설, 후보의 관측 가능한 구조 사실 | 상체/하체별 굽힘·손 위치 등 팩트 |
| 후보 확보 | 구조 조건별 보완 검색 | 부위 조건별 보완 검색 |
| 후보/조합 우선순위 | 자세 상태와 후보의 양립 가능성·수정 부담 | 부위의 모순, 필요한 관절 수정, 경계 연결 오차 |
| 자동 조정 후 | 자세 의미/구조가 유지되는지 재검증 | 남은 관측 부위 불일치와 접촉 오류 재측정 |

기존 A v1과 B1 v1은 frozen 비교 기준으로 남긴다. 현 A의 일방향 강제 제외·distance guard, 현 B1의 Top-K 재정렬만으로 위 역할이 구현된 것은 아니다.

### 탈락과 수정 가능성을 구분한다

- **현재 모양이 다르지만 고칠 수 있음:** 팔 위치, 손목 높이, 일부 무릎 굽힘 등. 재료/수정 후보로 유지하고 필요한 수정과 의도 보존 여부를 평가한다.
- **가설이 불확실함:** VLM의 앉기 추정, 가려진 하체, dead zone. 불확실 표시와 대안 유지. 이를 반대 의미가 확정된 후보와 같은 오답으로 취급하지 않는다.
- **유효한 결과로 제공할 수 없음:** 손상된 골격/변환, 유한값 실패, 허용되지 않은 인물 귀속, 검증을 통과하지 못한 심한 변형·관통 등. 출력에서 제외하거나 검증된 베이스로 복구한다.
- **명시 조건과 맞지 않음:** 해당 조건을 고치거나 다른 재료로 교체할 수 있는지 먼저 본다. 최종 결과가 여전히 다르면 조건 충족 결과로 표시하지 않는다. 근사 대안은 차이를 표시해 제공한다.

굽은 무릎 = 앉기, 편 무릎 = 서기로 단정하지 않는다. 2D 팩트, BVH의 실제 3D 각도, 검수된 자세 상태, 물체와의 관계를 분리한다. 단일 BVH로 실제 의자나 바닥 접촉을 확정하지 않는다.

## 5. 상·하체 조합을 넓게 지원한다

### 5.1 시작부터 독립 후보 생성 경로

전신 후보가 존재해도 조합을 탐색한다. 같은 입력에서 원본/보정 전신과 조합 결과가 경쟁한다. 제한된 하체 템플릿은 초기 디버깅 기준일 뿐 제품의 최종 범위가 아니다.

목표 범위는 라이브러리에서 검색한 임의의 적격 상체 U와 하체 L이다. 서기·앉기·꿇기·쪼그리기·한쪽 다리 지지·이동/공중 포즈 등 실제 확보한 재료를 쓸 수 있어야 한다. 모든 조합이 자연스럽다는 보장은 하지 않으며 단일 포즈에서 알 수 없는 동적 균형/의도를 임의로 정답 처리하지 않는다.

### 5.2 조합이 성립하도록 만들 공통 구조

- 서로 다른 BVH를 하나의 canonical skeleton·기준 자세·회전 규약으로 맞춘다. 원본 회전 채널을 그대로 이어 붙이지 않는다.
- 원본/좌우 mirror, 부위 마스크, 부모 체인, pelvis-relative 방향, 골 길이, 재료 출처를 보존한다.
- 하체 L의 root·pelvis·다리·발을 베이스로 사용하고 상체 U의 목표 방향/위치를 해당 pelvis 기준으로 재구성한다.
- 몸통의 기울기가 Hips에 들어 있는 U도 지원하도록 root/pelvis/Spine 역할을 명시한다. 필요한 경우 접합부 배분이 다른 소수 버전을 탐색한다.
- 상체에 몸통·팔·머리/목·손목을 일관된 영역으로 다루되, 손가락 세부는 별도 손 포즈 계약과 연동한다. 이 범위를 현재 v1에서 지원한다고 주장하지 않는다.
- 손–무릎, 팔–몸통, 양손 접촉 등의 관계를 최종 조합 전체에서 다시 검증하고 제한된 IK/최적화로 조정한다.
- 누움·기댐·격한 비틀림도 world-up 직립을 강제로 적용하지 않는다. 의도와 골격/메시 안전으로 판단한다.
- 다인 포옹/격투는 인물별 무관한 조합으로 풀지 않는다. 인물 간 접촉과 소유권을 가진 별도 조합/관계 문제다.

### 5.3 조합 폭과 비용을 동시에 관리

라이브러리 전체 N×N을 파일로 저장하지 않는다. 요청마다 상체·하체 후보군에서 조합한다. 예를 들어 U 20개와 L 20개면 최대 400개 쌍의 경계/부위 특징을 가볍게 평가할 수 있다. 이는 초기 예산 예시이며 측정 전 속도를 보장하지 않는다.

거친 점수 상위 쌍, 다른 자세 가설, 서로 다른 출처를 남기는 단계별 탐색을 사용한다. 유망한 쌍에만 실제 pose solve와 메시 검증을 적용한다. 카메라는 최종 조합마다 하나를 적합한다. 같은 골격/조건의 재료와 조합은 해시·버전 기반으로 캐시한다.

작가가 U 또는 L을 잠그면 해당 재료를 보존하고 다른 쪽 탐색에 예산을 집중한다. 의미 없는 작은 변형 수십 개 대신 서로 다른 수정 가능한 대안을 제공한다.

## 6. 최종 점수는 ‘수정 후 사용 가능성’에 맞춘다

전체 후보와 조합 후보 모두 같은 평가 항목을 사용한다.

1. 동작의 핵심 의미·사용자 지정 조건이 얼마나 보존되는가.
2. 보이는 상체와 하체가 각각 얼마나 맞는가. 상체 평균으로 큰 하체 오류를 숨기지 않는다.
3. 손발 접촉, 좌우, 부위 간 관계가 맞는가.
4. 카메라가 과도한 고도/roll/원근으로 다른 자세를 억지로 맞추고 있지 않은가.
5. 자동 조정 후 작가에게 남은 수정 부위와 어려움은 무엇인가.
6. 실제 모델의 골격/관절/메시가 사용 가능한가.

초기에는 이 항목들을 분리해 기록하고 의도 유지·허용 가능한 수정 범위를 작가 판정으로 보정한다. 임의 가중치 합산을 ‘최적 점수’로 고정하지 않는다. 자동 solve 전후의 잔여 오차, 움직여야 하는 체인 수, 유지해야 하는 접촉의 파손 등을 수정 부담의 대리 지표로 쓰되 실제 수정 시간이라고 부르지 않는다.

원본에서 크게 변했다는 이유만으로 좋은 조합 결과를 낮게 평가하지 않는다. 시스템 계산 비용과 작가 작업 비용은 따로 측정한다. 기존 refine non-regression은 검증된 베이스 대비 보정 안전 조건으로 유지하고, ‘원본이 비슷해야만 새 조합을 허용’하는 정책으로 확대 해석하지 않는다.

## 7. 라이브러리 확장은 병행 과제

현재 라이브러리 고정 평가와 확장 라이브러리 평가를 분리한다. 자산이 늘어난 효과를 검색 알고리즘 개선으로 보고하지 않는다.

수집 우선순위는 실패 분석에서 정한다.

- **검색 실패:** 실제로 있는 적격 전신/부위 재료를 회수하지 못함 → 색인/검색 개선.
- **조합 실패:** 좋은 부위가 각각 있으나 연결·접촉·골반 경계가 깨짐 → 조합/보정 개선.
- **재료 부족:** 적합한 전신도 상체/하체 재료도 없음 → 해당 행동·하체 상태를 수집.
- **모델 변형 실패:** BVH는 맞지만 실제 캐릭터가 깨짐 → 리타게팅/스키닝 개선.

같은 서기 포즈를 많이 늘리는 대신, 필요한 상체 동작·하체 상태·접촉 관계·체형/극단각 재료의 빈 구간을 채운다. 기본 동작뿐 아니라 손 주머니, 팔짱, 무릎 꿇기, 기대기 등 실제 평가에서 반복된 실패 유형을 우선 조사한다.

## 8. 경계 계약과 구현 순서

1. **평가 기반:** 앞뒤/좌우/깊이 카메라 규약 교정, 동일 DB와 의미 build 고정, 실제 모델 미리보기 일치 확인.
2. **재료 색인:** 전신/상체/하체 기하와 의미 문서·구조 팩트. 부분 기하 정규화는 관측 가능한 anchor로 정의하고 query/library 양쪽에 같은 함수를 적용한다. 기존 전신 피처는 한쪽만 변경하지 않는다.
3. **후보 확보와 넓은 조합:** 세 scope의 후보 합집합, 공통 골격 변환, 상·하체 쌍 탐색, 출처/잠금/가설 유지. 시맨틱만 먼저 완료하고 조합을 먼 후순위로 미루지 않는다.
4. **적합·검증:** 원본과 조합에 공통 카메라 적합, 제한 solve, A/B1 재평가, 메시 검증.
5. **작가 평가·반복 탐색:** 같은 최종 후보로 preview/export, 남은 수정 표시, 재료 잠금·교체.

현재 API의 의미 후보 refine 금지는 그대로다. 새 조합/조정은 별도 실험 서비스와 provenance를 가진 생성 후보 계약을 설계한 뒤 연결한다. `semantic_user`를 `geometry`로 바꿔 제한을 우회하지 않는다. 생성 후보는 U/L 원본 ID·해시, canonical rig/조합 버전, 최종 BVH handle, 카메라, 검증 결과가 필요하다. 단일 원본 pose_id로 export하지 않는다. 기존 CutResult 경계를 유지할 확장 모델은 BFF/클라이언트와 동기화한다.

기존 A/B1 off/shadow/on 및 현재 `intent_fusion`은 비교 기준으로 유지한다. 이번 문서는 이 실험들을 운영에 켜거나 새 gate를 바로 적용하라는 지시가 아니다.

## 9. 평가 설계

같은 라이브러리, 같은 컷, 같은 시도 시간 예산에서 다음을 비교한다.

| 조건 | 확인할 효과 |
|---|---|
| 현 기하 검색 | 기준선 |
| 현 A+B1 | 기존 규칙의 효과 |
| 전신 기하+의미 합집합 | 의미 채널의 후보 회수 효과 |
| 부위 검색 + 넓은 상·하체 조합 | 현재 라이브러리 재사용 효과 |
| 위 후보들에 자동 적합/조정 추가 | 실제 수정 부담 감소 |

주요 지표는 **Top-K 안에 정해진 수정 예산으로 사용할 후보가 있는 비율, 실제 수정 시간, 동작 의미 유지, 상·하체 각각의 적합성, 기존 성공→실패**다. 처음부터 수정 없이 일치하는 비율도 별도로 유지한다. 판정 기준/수정 예산은 평가 전에 고정하고 이전 ‘활용 어려움’ 라벨을 자동으로 성공으로 바꾸지 않는다.

실제 작가가 선택·수정하는 과제로 검증하고 방법 이름을 가린다. 가려진 하체 정답은 원작자 또는 대응 원본으로 검증하며 확인 불가능한 사례는 강제 정답 판정하지 않는다. 현재 28명은 개발용, 새로운 작가/작품은 holdout으로 분리한다. 확장 라이브러리는 이 표를 별도로 다시 실행한다.
