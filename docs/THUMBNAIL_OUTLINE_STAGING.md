# C 1/2 · 대비 강하게 썸네일

## 적용 범위

- 선택한 비교 화면 C 스타일: 흰 배경, 512px 기준 외곽선 0.65px, 명암 대비 2.6, 밝기 혼합 0.22.
- 5,862개 포즈 × 전신·반신·흉상·어깨 포함 두상 4범위 × 8방향 = **187,584장**.
- 현재 배포된 썸네일 방향은 **45° 간격**이다. 30°는 검색 카메라 탐색 격자이며 썸네일 규격이 아니다.
- `yaw_A` 자산은 원본 좌표계에서 렌더링한다. 검색 시점 `yaw_Y`는 기존처럼 `A=(-Y)%360`으로 연결한다. 이미지를 반전하거나 BVH 정면을 다시 정의하지 않는다.
- 검수된 손·소품 포함 최종 GLB/FBX 표면을 사용한다. 반신·흉상은 기존 피부 가중치 기반 절단과 절단면 봉합을 사용한다. 검색 DB, BVH, 원본 FBX/GLB, 사람의 검수 결과를 수정하지 않는다.

## 생성과 검증

`pose_curation.thumbnail_style`은 생성·검증·포장을 분리한다.

1. `build`: 원본 BVH/FBX/GLB 해시를 검증한다. Blender 작업자는 기존 `framing.py`를 사용해 임시 범위별 표면을 만들고, OpenGL 렌더러는 8방향을 한 묶음으로 렌더링한다. 모든 이미지의 빈 화면·경계 잘림과 SHA256을 검사한다. 포즈 완료 기록은 원자적으로 저장한다. 중단 후에는 같은 렌더러 버전·이미지 해시를 만족하는 완료 포즈만 재사용한다.
2. `package`: 187,584장의 JPEG 규격과 해시, 5,862개 포즈 기록, 전체 수량을 다시 확인한다. 완성된 `thumbs/styled/`만 tar.gz에 포함한다. DB·BVH 등은 포장하지 않는다.
3. 런타임: S3 URI와 아카이브 SHA256을 모두 지정해야 활성화된다. DB 해시와 라이브러리 버전, 모든 이미지 해시를 기동 시 검사한 후 게시한다. 경로 탈출·심볼릭 링크·허용 범위 밖 파일·부분 릴리스는 거절한다.

```powershell
python -m pip install -r requirements-curation-thumbnails.txt
python -m pose_curation.thumbnail_style.build `
  --base <검수된_라이브러리_작업폴더> `
  --output <새로운_오버레이_폴더> `
  --converter-root <고정된_검수_변환기_체크아웃> `
  --blender <blender.exe> --workers 6
python -m pose_curation.thumbnail_style.package <오버레이_폴더> <새_릴리스.tar.gz>
```

변환기 파일 내용은 렌더러 버전에 포함된다. 이미 검수한 변환기 파일을 이 작업 때문에 수정하지 않는다. 생성 도중에는 생성기·셰이더·변환기 소스를 변경하지 않는다. 렌더링용 Python에 ModernGL과 OpenGL 3.3 이상이 필요하며, 추론 서버에는 GPU 라이브러리를 추가하지 않는다.

입출력 재시도처럼 외형을 바꾸지 않는 수정 뒤에는 검토한 이전 버전을 `--reuse-revision <SHA256>`으로 명시할 수 있다. 기존 이미지·원본 형상 해시를 다시 검사하며, 기존 포즈 기록의 생산 버전을 덮어쓰지 않는다. 릴리스는 포함된 생산 버전 목록을 선언하고 응답은 각 이미지의 실제 생산 버전을 기록한다. 셰이더·카메라·절단·인코딩이 달라졌다면 이 옵션으로 재사용하지 않는다.

## 스테이징 전달 규약

`POSE_THUMBNAIL_OVERLAY_URI`와 `POSE_THUMBNAIL_OVERLAY_SHA256`을 스테이징 추론 태스크에 지정한다. 둘 다 없으면 기존 동작을 유지한다. 설치 시 원래 라이브러리를 유지하고 별도 `thumbs/styled` 디렉터리만 추가한다.

- 라이브러리 4방향 썸네일: 새 자산의 전신 0°·45°·90°·180° JPEG를 사용한다.
- 후보 8방향 및 기본 포스터: 현재 BFF가 검증하는 `frozen-retarget-v1` PNG 전달 규약을 유지한다. 원본 JPEG는 검증 후 PNG로 변환하고, 응답 해시는 실제 PNG에 맞춘다.
- 실제 렌더러는 `X-Standin-Native-Render-Method: reviewed-surface-outline-v1`, 스타일은 `X-Standin-Thumbnail-Style`, 자산 버전은 `X-Standin-Poster-Asset-Version`에 별도로 기록한다. 옛 렌더러가 만들었다고 위장하지 않는다.
- 후보 응답은 기존 `private, no-store`를 유지한다. 전체 릴리스를 선언한 뒤 이미지가 없어지면 옛 이미지/다른 방향으로 조용히 폴백하지 않는다.
- 정면 카메라, 3D 최종 미리보기, FBX/BVH 내보내기와 선택 캐릭터 렌더링은 이 썸네일 전용 스타일과 별개다.

## 배포·롤백

`Dockerfile.thumbnail-overlay`는 배포 전에 확인한 스테이징 이미지 digest를 기반으로 변경 모듈만 추가하는 후보 이미지다. 기본 Dockerfile에도 같은 코드가 포함되므로 PR 병합 후 일반 빌드에서도 기능을 사용할 수 있다.

1. 생성·포장·코드 검증과 대표 이미지 검수를 마친다.
2. 스테이징 버킷에 내용 기반 새 키로 업로드한다. 기존 키와 운영 버킷을 덮어쓰지 않는다.
3. 현재 스테이징 태스크 정의를 저장하고 이미지·오버레이 환경변수만 변경한다. 시작 유예와 기존 모델·서비스 설정을 보존한다.
4. 정상 기동, 원본 라이브러리 동일성, 4범위×8방향 응답, PNG/JPEG 규약과 BFF 검증을 확인한다.
5. 문제 발생 시 저장한 이전 태스크 정의로 서비스를 되돌린다. 기존 S3 라이브러리와 자산은 남아 있으므로 재생성 없이 복구한다.

BFF의 `POSE_THUMBNAIL_REVISION`에는 **아카이브 SHA256(소문자 64자리 16진수)**을 넣는다. 스타일 이름이나 `asset_version` 문자열을 넣으면 안 된다. 클라이언트의 문장 검색 결과 검증은 썸네일 URL의 `revision`을 `[a-f0-9]{7,64}`로 제한한다. 검색 API가 200을 반환해도 이 규칙을 어기면 앱에서 `SEMANTIC_CONTRACT`가 발생한다. 스타일 이름은 기존 이미지 헤더의 `X-Standin-Poster-Asset-Version`으로 별도 전달한다.

배포 확인에는 이미지 API 검사뿐 아니라 실제 클라이언트에서 문장 검색 → 결과 목록 → 새 썸네일 표시까지 포함한다. 2026-11-03 스테이징 검수에서 스타일 이름을 캐시 버전으로 넣은 오류를 발견해 아카이브 해시로 수정했다.

CDK의 태스크 정의를 다시 배포하면 수동 스테이징 후보 설정이 바뀔 수 있다. 장기 채택 시 이 두 환경변수와 후보 이미지 버전을 정식 인프라 배포 설정에 반영한다.
