# 평가 자료·사람 평가 양식

관련 문서: [검색·리파인·최종 FBX 하네스 보완 설계](../EVALUATION_HARNESS_SEARCH_REFINE_FBX_DESIGN_2026-10-27.md)

이 폴더의 CSV는 **빈 검토·수집 양식**이다. 실제 사용자 자료나 평가 결과가 들어 있지 않다. 기존 `standin_eval`이 바로 읽는 JSONL 스키마와 다르며, 구현 때 ID 대응·선택값·누락값을 검사하는 변환기를 추가해야 한다. 원본 CSV도 봉인해 보관한다. CSV는 Excel에서 한글이 보이도록 UTF-8 BOM으로 저장했다.

## 1. 지금 도원이 준비할 파일

```text
rough-eval-intake/
  rough-intake.csv
  person-intent.csv
  images/
    C001.png
    C002.png
    ...
```

1. **2026-10-27 업데이트:** 러프 PNG 323장은 이미 제공되어 inventory 준비를 완료했다. 새로 수집을 시작할 필요는 없다. 제공 자료의 그룹·권한·인물 의도를 보충하는 절차는 [사용자 준비 및 사람 평가](USER_PREPARATION_AND_HUMAN_REVIEW.md)를 따른다. 아래 분량은 원 설계 당시의 파일럿 제안이며 확정 표본 요구가 아니다. 같은 파일의 crop·수정본은 사람이 원본 묶음을 확인한다.
2. `rough-intake.csv`에 컷별 한 줄을 적는다. 모델 결과를 보고 편한 컷만 남기지 않는다.
3. `person-intent.csv`에 인물별 한 줄을 적는다. 인물 별칭과 위치 설명만 주면 bbox 초안·영구 ID·관절 라벨·해시는 구현 담당자가 만든다.
4. 최종 검증용 자료는 작품/원본 장면이 다른 추가 20~30장부터 별도 보관한다. 위 첫 분량과 혼합하지 않는다. 정식 최종 필요 표본 수는 이후 산정한다.

인물 수가 0이거나 제품 대상이 아닌 컷도 입력 상태 그대로 적는다. 타깃 정의와 라우팅 평가에 필요하다. 동작을 모르면 `판단 불가`, 인물이 어떤 물체에 가렸으면 물체와 가린 부위를 적는다. 보이지 않는 관절 좌표를 새로 그릴 필요는 없다.

## 2. 러프 접수표의 값

| 칸 | 작성 방법 |
|---|---|
| 컷ID / 파일명 | 예: `C001` / `C001.png`. 파일명이 바뀌어도 컷 ID 유지 |
| 작가그룹ID / 작품ID / 원본페이지장면그룹ID | 실명 없이 `A01/P01/S01` 같은 별칭 사용. crop·resize·같은 원본은 같은 장면 묶음 |
| 평가세트 | 첫 자료는 `D0` 또는 `D1`, 별도 봉인 자료는 `D2`. 담당자가 최종 분리 확인 |
| 대표셋_어려운셋 | `대표` 또는 `어려움`. 연속 컷 안에 어려운 컷이 있어도 수집 출처는 대표로 유지 |
| 인물수 | 배경 인물 포함 여부가 애매하면 비고에 적고 함께 확정 |
| 태그 | 예: `다인;가림;손-허리접촉;측면`. 여러 개 가능 |
| 평가사용허용 / 팀내공유허용 / 외부VLM전송허용 | 각각 `허용/불허/확인 필요`. 외부 전송 불허 자료는 실제 VLM 실행에서 제외 |

## 3. 인물 의도표의 값

| 칸 | 작성 방법 |
|---|---|
| 인물별칭 / 위치설명 | 예: `왼쪽 주인공` / `화면 왼쪽 의자에 앉은 인물` |
| 3D보조대상 | `예/아니오/판단 불가`. 결과를 보기 전에 결정 |
| 핵심동작 / 보존할부위 | 예: `오른손을 허리에 짚고 서 있음` / `오른팔의 벌어진 방향` |
| 인물기준좌우 | 인물 자신의 왼쪽·오른쪽을 사용. 애매하면 명시 |
| 보이는방향 / 가린부위 | 예: `측면에 가까운 45도` / `왼팔꿈치가 몸통에 가림`. 확신 없는 각도를 정답 숫자로 강제하지 않음 |
| 접촉_지지의도 | 손바닥/손등 중 무엇이 어디에 닿는지, 지지발·의자·공중 여부. 알 수 없으면 `판단 불가` |
| 작가가아는숨은자세 | 이미지 밖 의도를 알고 있을 때만 기록. 이미지에서 관측된 사실과 구분 |
| 희망체형 / 왼손 / 오른손 / 출력범위 | 원하는 이름을 적으면 담당자가 정확한 ID/버전으로 확정. 미지정은 `미지정` |

예시 의도 문장: “등을 약간 숙이고 오른손바닥 전체를 오른쪽 허리에 댄다. 왼팔은 물체 뒤에 가려져 있어 위치를 판단하기 어렵다.” 이때 왼팔 위치를 확정 정답으로 만들지 않는다.

## 4. 결과가 나온 뒤 작성할 평가표

`평가세션ID`, `배정ID`, `익명후보ID/익명파일ID`와 수정 대상 ID는 하네스가 채운다. 평가자에게 기준/신규 버전, 원래 rank, 비공개 좌우 대응표를 노출하지 않는다. 공개용 파일명에도 버전명이 드러나지 않게 한다. 평가자 별칭은 작업자 간 구분이 가능하게 유지한다.

### 공통 선택값

- 일치: `맞음/일부 다름/다름/판단 불가`.
- 활용 가능성: `바로 사용/참고 후 수정/사용 어려움/판단 불가`.
- 결함: `없음/의심/확인`과 구체적 부위·이유를 함께 기록.
- 심각도: `없음/경미/중대/판단 불가`. 경미·중대의 예시와 수정 시간 T는 첫 D1 평가에서 맞추고 최종 검증 전에 고정.
- 미작성은 `미평가`, 그림·결과만으로 결정할 수 없음은 `판단 불가`. 둘 다 성공으로 바꾸지 않음.

### 검색: search-review.csv

후보별 한 줄이다. 핵심 동작·방향·좌우, 활용 가능성과 수정해야 할 부분을 적는다. 익명 후보 union을 평가한 결과로 원래 Top-1/Top-5를 계산한다. 실제 순위 화면에서 고르는 시간은 별도 사용자 과제로 기록한다. 임의의 “정확도 8점”보다 구체적인 수정 이유를 남긴다.

### 리파인: refine-review.csv

동일한 선택 포즈의 두 결과를 한 배정으로 비교한다. `러프에더가까운쪽`은 `왼쪽/오른쪽/같음/판단 불가`. 양쪽 각각의 활용성·핵심 자세 보존·결함·심각도를 적는다.

실제 수정 과제는 하네스가 지정한 **한 개 익명 결과**에 수행하고 시작·종료·완료 여부를 기록한다. 시각은 동일 타임존의 ISO 8601 형식 또는 도구가 자동 기록한 값을 사용한다. 같은 작가가 같은 러프를 연달아 수정해 생기는 학습 효과를 줄이도록 순서를 교차 배정한다. 완료하지 못한 과제는 중단 이유와 제한 도달을 기록하고, 빠른 성공으로 계산하지 않는다.

### FBX: fbx-review.csv

실제 저장한 파일을 사용하는 제작 도구에서 연다. 도구·버전·OS와 파일 열기 성공/실패, 선택 인물·체형·손·출력 범위·배치가 맞는지 적는다. 파일 열기만 성공했지만 포즈가 쓸 수 없으면 활용 가능성에 그대로 표시한다.

결함 스크린샷은 별도 파일로 저장하고 양식에는 ID만 적는다. 원본 러프와 화면은 승인된 평가 저장 위치에서만 공유한다. 사람이 눈으로 이상을 찾는 평가와 자동 전신 메시 검사는 각각 필요하다.

## 5. 담당자에게 넘길 때

- 원본 PNG, 접수표, 인물 의도표, 별도 D2 자료의 보관 담당/그룹 목록을 전달한다.
- 지원할 체형 5종의 실제 catalog ID·해시와 커스텀 조합을 구현 담당자와 맞춘다. 사용자가 해시를 수작업으로 적을 필요는 없다.
- 실제 작업자 2명 이상과 도구/OS를 확보한다. 평가 시간과 반복·이중 평가 분량은 D1 파일럿 후 결정한다.
- 제공한 컷 수, 인물 수, 평가 완료 수, 독립 작가/작품 묶음 수를 구분한다. 30장 파일럿을 정식 출시 성능 검증 완료로 표시하지 않는다.
