# 사용자 준비 및 사람 평가 대기 항목

2026-10-27 KST. **운영 미배포.** 제공된 러프를 다시 모을 필요는 없다. 현재 323개 PNG(84,092,609 bytes)를 원본 읽기만으로 조사했다. SHA-256이 같은 파일은 0개이고 고유 바이트 내용은 323개다. 크기 확인 실패는 0개다. 이는 crop/resize/유사 컷 중복이 없거나 323개가 독립 표본이라는 뜻이 아니다. 작가·작품·장면 출처 323개 모두 미확정이며 인물 정답은 아직 없다.

## 기계적으로 완료된 준비

- 파일별 SHA-256, byte size, 이미지 width/height, 상대 경로와 해시 기반 컷 ID.
- exact duplicate 그룹 목록 및 출처 미확정 목록. 파일명 유사도로 출처·독립 표본을 만들지 않음.
- 컷별 323행의 `rough-intake.csv`: ID/파일명만 채우고 동의는 `확인 필요`, 인물수/그룹/분할/라우팅은 비워 둠.
- 빈 `person-intent.csv`, `profile-matrix.csv`, `review-sessions.csv`와 원본 5종 평가 양식.
- 원본 해시가 바뀌었거나 누락/중복 ID·bbox·인물수·D1/D2 출처 누출·미확정 평가 동의가 있으면 기존 dataset으로 변환하지 않는 오프라인 import.

로컬 산출물은 이 구현 워크트리의 `out/eval/rough-preparation-20261027-v1/`에 있다. 원본 경로·파일명·행별 해시는 Git에서 무시되는 이 폴더에만 보관한다. PR에는 [집계](rough-inventory-summary.json)만 포함한다. 원본 PNG/BVH/FBX는 커밋하거나 외부 provider로 보내지 않았다. `inventory.jsonl`은 원본 메타데이터를 봉인하며 완료한 라벨은 별도 CSV로 저장한다.

## 준비 양식 → 기존 dataset

원본 5종 CSV를 그대로 보존했다. inventory에서 생성한 접수·인물 의도표는 기계 검증용 열을 추가한다.

- `expected_route`: 사람이 `core/bust/skip` 중 확정.
- `person_id`: 요청 순번과 별개의 영구 ID. 담당자가 부여하고 중복을 검사.
- `bbox_xyxy`: 픽셀 좌표 `[x1,y1,x2,y2]`, `bbox_source`에 출처, `bbox_confirmed=예`일 때만 확정.
- `3D보조대상`, `out_of_scope`: `예/아니오`; `scale_class`: `near/far`. 판단 불가는 pending 상태로 남긴다.
- `평가세트`: `D0/D1/D2/D3`. D1/D2가 작가·작품·장면 ID를 공유하면 import를 차단한다. ID는 자료 전체에서 유일하게 이름 짓는다.

외부 VLM 전송 동의는 `허용/불허/확인 필요`를 그대로 저장한다. 이 변환기는 내부 사용 동의나 외부 전송을 대신 승인하지 않으며, legacy provider 명령은 이 작업의 실행 대상이 아니다. 완료되지 않은 323행을 import하면 `INCONCLUSIVE`, `exported=false`다.

## 구현 검증과 별도로 남은 실제 실행

오프라인 fixture는 코드 계약·분모·실패 처리를 검사한다. 실제 모델/장비 성능, 지원 profile별 Blender 재import·변형 메시 검사, 인물 간/소품 관통, 설치 앱의 native 저장·취소·stale receipt, CSP 활용성은 각 실제 증거가 추가되어야 한다. mock/strict snapshot 1건으로 전체 체형·포즈·출력 범위를 인증하지 않는다.

D1 파일럿에서 구간별 시간 예산, 품질 최소 개선, 허용 회귀, 독립 묶음 수·라벨러 수·통계 정책을 정한 뒤 결과를 보기 전에 봉인한다. 323장 자체를 확정 출시 표본 수로 간주하지 않는다. 라벨·지원 범위·검사 완료·시간 예산이 부족한 report는 INCONCLUSIVE다.
