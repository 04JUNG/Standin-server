실제 파일 저장·재로드·CSP 통과

선택된 라이브러리 BVH를 저장 기록에서 다시 연 로컬 QA 실행입니다. 러프 원본 분석·검색 정확도 수치는 없습니다.

BFF가 기록한 구간 시간

이 기능 검수에서 관찰한 서버 구간입니다. 공정한 성능 비교나 전체 사용자 대기 시간으로 사용하지 않습니다. 준비·다운로드·로컬 저장은 서로 다른 시점입니다.

01 · saved history → selected BVH

분석 기록에서 실제 라이브러리 포즈를 선택

저장 기록의 로컬 QA fixture를 실제 앱에서 열었습니다. BFF는 검증한 라이브러리 BVH 바이트를 Linux Converter로 전달했습니다.

실행하지 않은 분기

원본 이미지 분석, VLM, 포즈 추출, 최근접 검색, refine: 이 내보내기 실행에서 호출하지 않았습니다. 해당 단계의 점수나 시간을 만들지 않습니다.

02 · BFF createSelectionResolver

모델·최종 authoring source·컨트롤을 함께 고정

카탈로그의 정확한 모델 ID와 자산 SHA, 규칙/source SHA를 선택 및 receipt에 연결합니다. SSR2는 별도 자산 게이트이며 이 커스텀 FBX는 최종 authoring source와 컨트롤러로 생성합니다.



03 · interactive snapshot → client shared reader → 3D surface
권위 패킷과 실제 3D 표시
실제 클라이언트 바이너리 리더가 state SHA와 모델 SHA를 검증했습니다. QA 창을 활성화한 뒤 최종 3D 표시를 관찰했습니다. 기능 검수의 화면이며 실제 앱 반복 wall-clock은 별도로 기록합니다.


04 · BFF export receipt → native save
앱이 내려받아 로컬 파일로 저장
네이티브 저장 완료 화면을 관찰했고 실제 디스크 바이트가 현재 BFF export receipt의 SHA·길이와 일치합니다. 파일을 직접 export한 결과로 이 단계를 대체하지 않았습니다.


05 · fresh Linux Blender → capture / compare
디스크에 저장된 FBX를 독립 재로드
별도 Linux/amd64 Blender 프로세스가 저장 파일을 다시 읽었습니다. 권위 패킷과 대조한 위치·행렬·가중치·노멀 오차는 모두 0입니다.


06 · actual CSP UI
가져오기 → .clip 저장 → 닫기 → 재열기
네이티브 저장 파일과 같은 SHA의 FBX를 새 검증 문서에 가져왔습니다. 검수 문서만 저장하고 닫은 뒤 다시 열었습니다.
