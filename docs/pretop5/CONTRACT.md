# Candidate preparation: candidate-refine-v1

Engine owns this contract. Updated for the user's 2026-11-06 correction: **search → source-only candidate refinement → Top5 → user pose selection → actual body/shape/hands → selected target/final FBX verification**. No body/shape/hands/appearance application, target mesh load/retarget, per-target candidate recalculation or intermediate FBX before Top5. Implementation base: server develop f260b1e6843996935ab287cdfad63465c18f7266. No unmerged source dependency. Opt-in private BFF transport; no deployments authorized.

## HTTP and authority

`GET /internal/candidate-refine/v1/capabilities`, `POST /internal/candidate-refine/v1/prepare`, `POST /internal/candidate-refine/v1/reuse` require `Authorization: Bearer <CANDIDATE_REFINE_TOKEN>` (32+ characters) and `CANDIDATE_REFINE_ENABLED=1`. Default disabled. BFF authenticates installation/job/person, atomically registers observations/search candidates, then submits authoritative inputs. Never proxy arbitrary client RefineRequest, paths, safety claims or target URLs. Engine resolves source by registered pose_id, verifies SHA on prepare/cache/reuse, and freezes a private read-only bytes snapshot. BFF owns durable async job/status/lease/current-revision invalidation. Prepare is a bounded internal batch call; UI uses BFF jobs. Do not record exposure, selection or analysis-quota events during preparation.

## Request (machine schema: schema.json)

Common `contract_version=candidate-refine-v1`, `batch_id`, `owner_id`, `job_id`, `candidate_set_revision`. `candidates` (1..10): `person_id`, `candidate_id`, `source_sha256`, `request` (existing source RefineRequest fields, `render_thumbnail=false`, `refine_v3` absent/null). Unknown fields including `target`, body/shape/hand/appearance are rejected. Observation/policy/camera fields are unchanged. Scores and all original policy lineage fields (`refine_allowed`, `refinable_limbs`, `lower_body_observed`, `skeleton_state`, `coverage_class`, `slot_origin`, `skeleton_source`) are required; an automatic batch cannot use the legacy missing-lineage v1 exception. At most five candidates per person per chunk; unique identities, original order preserved.

**Ten is a transport chunk bound, not a product person limit.** For 3+ people BFF retains one job/revision, submits sequential bounded chunks (no 5N fanout), and opens one Top5 barrier only after every registered candidate in every chunk is terminal. Never truncate candidate 11+. `request.camera` is the exact registered search camera, not a reconstruction from display view.

Batch budget 1..120000ms, candidate execution budget 1..30000ms; defaults 60000/5000. Queue wait consumes batch budget. Process-wide source execution admission (default C=1, alternative C=2) is shared by new candidates and legacy `/refine` while this opt-in feature is enabled; selected legacy work has priority over queued candidate work. Batch executor admits at most 20 candidates; shared execution gate has at most 20 waiters. Legacy selected queue wait is bounded to the configured source timeout (1..30s); saturation returns 503 REFINE_SOURCE_BUSY + Retry-After:1 without starting another solver. With feature OFF legacy behavior is unchanged. Queue-full is retryable and is not retried internally. These are local resource bounds, not product latency guarantees. Native source deadlines are cooperative; expired/running work keeps its actual slot until completion. BFF must discard late responses by lease/revision. One active preparation per job/revision; no independent 5N HTTP fanout. Set BLAS thread limits once in worker launch configuration when comparing C=1/2, never mutate global environment per request.

## Response

Same common binding, `all_terminal=true`, ordered `results`: `person_id`, `candidate_id`, `context_fingerprint`, `source_fingerprint`, `status` (`ready_refined`, `ready_base`, `unsupported`, `failed_retryable`), `reason`, `quality_scope=source_only`, `engine` exact code/config/library/source revision, `source_sha256`, `artifact_sha256`, `bvh` exact display/selected source text (including original bytes on safe retention), `prepared_id`, `timing`. No target receipt, no target safety assertion, no PNG, no FBX. Generic display skeleton/model is display-only.

`ready_base` means normal existing safety/policy retention; timeout/crash is `failed_retryable` with no usable prepared ID or artifact. One failed candidate does not discard others. Source-only BVH does not certify target skin/contact or final FBX. `bvh` is UTF-8 text; `artifact_sha256` hashes those exact encoded bytes. Base bytes are unchanged, not reserialized. BFF must serve the prepared BVH/model made from it; an original static thumbnail cannot represent `ready_refined`.

Timing: current `queue_ms`/`execution_ms` are zero for cache/in-flight reuse, underlying computation remains in `origin_queue_ms`/`origin_execution_ms`; `total_ms` includes current wait. `cache=miss|hit|in_flight`. Single-flight merges running identical source contexts. Normal retention can cache; failures/timeouts cannot become successful entries. Caches are bounded private process-local TTL optimizations (default 64 entries/600s, exposed as prepared_capacity/ttl_seconds), never durable authority; restart/expiry/capacity eviction invalidate prepared IDs. BFF must handle reuse 409 as invalidated/reprepare rather than use an unverifiable prepared result. This implementation requires one engine service process for prepared-ID affinity; multi-replica persistence/routing is not provided.

## Immutable identity and reuse

Source identity includes owner/job/person/candidate-set/candidate, complete observation/ownership/policy/camera, source SHA, exact source adapter/solver/selector/config/library/code revision and source file/runtime package digests. Capabilities expose actual source_code_sha256 plus Python/NumPy/SciPy versions, even in a local checkout. **Body/shape/hand/appearance are excluded.** They live in the later selected target identity; changing them must not invalidate source or cause VLM/search/source solver execution. Batch ID is not part of the source identity, allowing reopen/duplicate request reuse within the same revision. Cross-owner private result sharing is prohibited. Source file integrity and authoritative library set_id (entangled-set policy) are checked even on cache hits and after solving. Config/source changes and corrupt cache entries block stale reuse.

`POST .../reuse`: common owner/job/candidate-set binding plus `person_id`, `candidate_id`, `prepared_id`, `context_fingerprint`. Return original prepared result after owner/revision/source hash/current engine checks. **Selected source solver calls = 0.** BFF still verifies current authoritative revision/selection; this API does not create a confirmed selection or export permission. Source result is reused as input to the selected-only target phase. If later target/scene work changes pose, BFF must publish the new preview revision and verify its exact final file before download.

## v3/v4 and selected target provider

Preselection only applies the existing accepted source v2.5.4/v1 path and existing fixed camera transport/normalization/ownership/occlusion/quarantine gates. No new VLM call. v3 remains off/shadow in the legacy path; candidate preparation does not spend time recomputing shadow diagnostics or promote its output. `source_refine` capability reflects configured source support; `target_refine=false`, `automatic_parts=false`, `scene_joint_validation=false`, `accepted_automatic_profiles=[]`. This empty allowlist is deliberate. No v4 `user_confirmed`/`reviewed_library` is synthesized. Actual body/skin/current-FBX-dependent v3 target or v4 native parts remain after user selection and require their existing explicit intent/accepted profile evidence.

Target owner exclusively owns converter_api and converter files. Its separate `SelectedTargetProvider.prepare(selected_source_bvh_bytes, binding, target)` takes `phase=selected_target`, authoritative selection revision, `prepared_source_id`, owner/job/person/candidate/context/output SHA binding and registered target selection ID/revision. It is **never called from source prepare**. Only selected candidates/combinations get body/shape/hands, target mesh/contact checks and final FBX/preview correspondence. Target structural checks are not collision safety certification. Target provider contract and endpoints are owned by target role and consumed by BFF after source reuse; no unmerged dependency required by this engine PR.

## Scene admission boundary

Existing /scene and explicit /parts endpoints keep one actual slot and legacy 503 Retry-After busy behavior. Automatic candidate preparation never enters or retries this slot, so it cannot starve manual/final work. Repeated HTTP cancellation must retain admission until actual worker completion. One Blender scene is not mutated by multiple threads. Only selected interaction combinations get scene validation; no 5^N precomputation.

## Integration

BFF public DTO/prepare/status/lease/chunk lifecycle belongs to BFF. Public queued/running/invalidated/cancelled are coordinator states; this internal batch reports terminal observations. Fullscreen/bar use the same source context/result. Unknown capability retains existing selected-only compatibility behavior. schema.json is generated from api.candidate_refine_models (prepare/reuse request/response definitions).
