# P1 정답 목표 비교와 악화 원인 분석

2026-11-06 KST. P0 검수·split의 의존성을 반영한 `codex/refine-v5-p1` 작업이다.
현재 결론은 **두 예제에서 학습한 전역 팔 방향 보정으로 일반화하기 어렵고, 관측·좌표계·부모
관절의 보정 범위를 함께 바꿔야 한다**는 것이다. 실제 입력·가중치는 동결한 개발 진단이다.

## 1 목표 비교의 출처

사용자가 제공한 사람이 수정한 정답 FBX를 사람 목표로 사용했다. 그 3D를 고정 정면에
투영한 `human_fbx_2d_projection`과 같은 러프의 `automatic_rtmpose_2d`를 동일한
source FK·정규화·관측점 마스크·회전 범위에서 비교했다. 12개 원장을 보존하고,
공통 관측점이 없는 2개는 unobservable로 기록해 양쪽 모두 10개에서 계산했다.

**이 목표는 사람이 러프 위에 직접 클릭한 2D 라벨이 아니다.** 해당 라벨은 제공되지
않았고 VLM으로 관절 좌표를 만들어 사람 라벨로 대체하지 않았다. FBX에도 camera가
없어 고정 정면은 진단용 가정이다. 따라서 아래 차이는 관측·화풍·시점·대상 해석이 섞인
목표 불일치이며 RTMPose의 순수 검출 오차나 실제 러프의 픽셀 정확도로 단정하지 않는다.
실제 camera/직접 2D 좌표를 확보하면 이 비교를 같은 계약에서 재실행할 수 있다.

## 2 같은 목표점에서의 범위 비교

위치 오차는 고정된 B0 몸통 길이로 정규화한 2D 관절 거리다. 포즈 유사도 백분율이 아니다.
부모 범위를 여는 경우 팔의 범위는 그대로 두어 효과를 분리했다.

| 실험 범위 | 사람 FBX 투영 목표로 맞춘 뒤 오차 | 자동 목표로 맞춘 뒤 사람 FBX 투영 오차 |
|---|---:|---:|
| 보정 전 | 0.3860 | 0.3860 |
| 팔 4본 각 12° 이내 | 0.3120 | 0.3385 |
| 팔 4본 각 60° 이내 | 0.1207 | 0.2264 |
| 같은 팔 범위 + 척추 chain 총 8°·쇄골 각 5° | **0.0861** | **0.2202** |

자동 목표에 대한 자체 오차는 마지막 실험에서 0.2999→0.0391까지 줄었지만 사람 FBX
투영 기준으로는 0.2202가 남았다. solver가 목표에 잘 맞는 것과 목표 자체가 작가의
정답을 나타내는 것은 별개의 문제다.

60°는 원인을 분리하기 위한 수치 실험 범위다. 실제 인체 가동범위·관통·보호 부위를
승인한 profile이 아니며 production 상한을 늘리지 않았다. root/골반 이동·길이 변경은
열지 않았고 각 실험은 원본 B0에서 시작한다. 범위를 재설정하며 누적 상한을 우회하지 않는다.

## 3 추가 10개 악화는 가시성 문제만이 아니다

기존 전체 10개·40본 평균은 52.01°→54.71°였다. P0 검수로 확실히 보이는 공통
팔 부분만 남기면 8개·28본에서 **47.10°→49.21°**로 여전히 악화한다.
원래 월드 좌표의 혼입을 분리해 고정 몸통 frame 상대 방향으로 보면 같은 부분에서
**41.02°→44.39°**로 악화한다. 가려진 부위와 전역 회전만으로 현상을 설명할 수 없다.
몸통 frame 방향 지표는 몸통 자체 회전의 정답 여부를 평가하지 않으므로 별도 보고한다.

### 학습 신호 두 개의 한계

두 학습 쌍으로 얻은 선형 보정 가중치의 실제 rank는 2다. 정규화 전 수정 제안은 두
훈련 수정량의 조합에 제한된다. 학습 목표 하나는 허리로 손을 굽히는 자세, 다른 하나는
얼굴로 손을 올리는 자세다. 다양한 펴진 팔·교차·몸통 변화의 수정 방향을 대표하지 못한다.

006은 원래 팔을 펴는 참고인데 001/074 수정량을 약 0.37/0.51 계수로 섞어 전달한다.
원래 29.4°이던 평균 방향 오차가 54.2°가 된다. 이는 실제 측정한 전이 실패다.
002는 월드 방향만 보면 42.5°→33.9°로 좋아지지만 몸통 상대 방향은 30.1°→40.3°로
나빠진다. 해당 source와 GT의 몸통 frame 차이는 약 93.7°다. camera/view를 입력하지
않은 절대 방향 학습은 몸통·시점 차이를 팔의 움직임으로 보상할 수 있다.

### 특징만 바꿔서는 해결되지 않았다

아래는 동일한 두 supervision 쌍·같은 평가 10개·같은 절대 방향 loss에서 특징을 바꾼 결과다.

| 특징 | 추가 10개 방향 오차 |
|---|---:|
| 원본 유지 | **52.01°** |
| 평균 수정량 | 57.82° |
| 24×24 픽셀만 | 53.94° |
| 현재 팔 기하만 | 55.84° |
| 픽셀 + 현재 팔 기하 | 54.71° |
| RTMPose 구조화 관측 + 현재 팔 기하 | 54.93° |

따라서 배경 픽셀이 유일한 원인이라고 단정할 수 없다. 관측 특징은 개선할 필요가 있지만
대표 학습 쌍의 범위, 출력 표현과 source 조건화도 함께 부족하다. GT를 사용해 두 수정량의
조합 계수를 별도 다중 초기값으로 탐색한 진단은 평균 42.06°를 얻었다. 이는 GT를 본
유한 탐색 결과이며 학습 성능·보장된 전역 최적값·이론적 오차 하한이 아니다.

### 감독 범위와 표현의 한계

초기 두 쌍의 sanity 학습은 GT의 네 팔 방향을 모두 사용했다. 따라서 cropped/partial
부위까지 작가의 3D reference로 재현한 결과이며, 이미지에서 직접 관측 가능한 목표만
학습한 결과는 아니다. 새 학습에서는 **관측 목표·숨은 부위의 약한 prior·라벨 없음**을
분리한다. 하체 메시를 제거한 GT의 남은 다리 본을 임의의 하체 정답으로 학습하지 않는다.

단위 뼈 방향은 축 방향 twist를 결정하지 못하고, 현재 출력에는 손목/손 프레임·손가락이
없다. 방향 오차가 0에 가까워도 손바닥/손등·손가락·머리 시선이 맞았다는 뜻은 아니다.
다음 모델은 관절 위치와 local SO(3) 수정, 검수된 palm/sole/head frame을 구분해서
학습해야 한다. 2D에서 알 수 없는 축은 prior/다중 가설로 다루고 관측했다고 만들지 않는다.

## 4 실제 FBX와 저장 경계

001/006/074의 부모 확장 실험을 실제 FBX로 저장·재수입했다. 별도의 readback 검증기에서
입력 65본의 목록·부모 관계·길이와 계획한 관절 위치를 확인했다. 최대 관절 위치 차이는
약 **0.0042mm**, 최대 길이 차이는 **0.0007mm 미만**이었다. source bytes도 보존했다.
이는 파일 운반·기구학 검증이며 메시 관통·접촉·완전한 포즈 일치를 인증하지 않는다.

검증 중 기존 export 설정을 반복 적용할 때 `Head_end_end` 같은 말단 본이 늘어나는
문제를 발견했다. frozen converter는 그대로 두고 V5에만 `ignore_leaf_bones=False`
입력과 새 leaf를 추가하지 않는 저장 어댑터를 넣었다. 이미 들어온 말단 본은 제거하지
않으며 전체 이름·부모·길이를 검사한다. 단일 명령 P1 재현도 이 경계를 사용해 두 사례를
다시 실행했다. 이전 파일들은 덮어쓰지 않았으며 최초 실패 자료도 private run에 보존했다.

같은 시점 렌더를 확인하면 001의 손목·손바닥, 006의 머리 방향·다리, 074의 손 표면·머리
관계가 여전히 다르다. 위치 loss의 개선을 작가가 요구한 전체 포즈의 성공으로 세지 않는다.

## 5 다음 학습 모델과 보정 범위

### 데이터와 학습

1. 새 P0 분할을 사용한다. 개발 63샘플 중 source 재구성이 가능한 것은 58개이며,
   현재 보수적 팔 관측 mask를 통과하는 source는 39개다. 두 개만 학습한 결과를
   단순 확대 해석하지 말고 다양한 펼친 팔·접촉·몸통·하체 동작을 포함한다.
2. 처음 1–4개 sanity에는 허리 손/얼굴 손 외에 **펴진 팔과 교차 팔**을 포함한다.
   이후 개발 split에서 학습하고 검증 split으로 checkpoint를 고른다. 파생 이미지·B0
   perturbation은 같은 그룹에 두고 고유 샘플 수를 부풀리지 않는다.
3. 입력은 **부위별 이미지 특징 + 모델 관측/visibility + 현재 source의 관절·뼈 frame +
   검색 camera/view**다. 선폭·배경을 3D 두께로 피팅하지 않고 표현 유형별 근거를 고른다.
   초기 후보는 고정 이미지 encoder와 작은 공유 part head다. 이를 구조화 기하만 쓰는
   작은 head와 동일 데이터로 비교한 뒤 채택한다. 새 대형 모델 설치·학습은 이번 작업에 없다.
4. 출력은 절대 월드 방향 네 개에서 **body/source frame의 관절 목표·부위별 회전 제안과
   불확실성**으로 넓힌다. 팔·다리의 공통 구조는 공유하되 좌우·수정 대상·가림을 명시한다.
   방향 loss와 함께 endpoint·어깨/골반 anchor·부위 관계를 감독한다. GT camera를
   모르는 경우 그 상태를 유지하며 추론에 GT frame이나 평가 label을 넣지 않는다.

[Sketch2Pose](https://github.com/kbrodt/sketch2pose)의 뼈 방향·단축·자기 접촉과,
[PoseFix](https://arxiv.org/abs/2309.08480)의 현재 포즈를 조건으로 한 수정 문제는 참고할
기제다. 이 저장소의 적은 자료에서 효과가 있다는 결론은 위 비교 실험으로 확인해야 한다.

### 보정 범위와 선택

- 기존 하체·지지 정책을 유지하면서 공통 골반/몸통 frame을 먼저 고정하고 관측된
  하체와 상체 목표를 다룬다. 다음 source 실험은 **제한된 척추·쇄골 + 팔/다리의 공동
  solve**로 하며, 부모 영향으로 움직이는 비대상 부위와 지지 조건을 함께 검사한다.
- 손목 위치만으로 만족하지 않는다. source에서는 손/발 방향 의도를 보존하고, 사용자
  선택 후 실제 body와 손이 정해지면 palm/back/sole의 표면 방향·접촉과 목/머리의
  관측 목표를 별도 profile로 맞춘다. 피부 메시·손 프리셋은 Top-5 전에 적용하지 않는다.
- 새 범위는 source-rig·target별 검증과 independent selector를 거쳐 정한다. 이번의
  60°를 그대로 기본값으로 올리거나 score가 높다는 이유로 unknown 권한을 열지 않는다.
  불확실한 부위는 원본을 유지하고 실제 유효 파일로 정확 복구한다.

## 6 재현과 검증 자료

P0 `curation`을 먼저 실행하고 아래는 새 출력 경로로 실행한다.

```sh
blender --background --factory-startup --python-exit-code 1 \
  --python experiments/refine_v5/extract_rigs_v2.py -- PRIVATE_RUN
python -m experiments.refine_v5.diagnose_v2 --root PRIVATE_RUN \
  --curation CURATED_JSON --out NEW_DIAGNOSIS_JSON
OPENBLAS_NUM_THREADS=1 python -m experiments.refine_v5.goal_probe_v2 \
  --root PRIVATE_RUN --curation CURATED_JSON --out NEW_GOAL_JSON
```

기본 목표 비교는 common mask다. `--mask-policy available`은 추가 관측 coverage를
보는 별도 실행이며 공통 표본 결과와 섞지 않는다. private 기본 run의 goals-common.json은
그 공통 실행의 원시 기록이다. 실제 파일 검증은 `verify_goal_native_v2.py`, 별도 readback은
`recheck_saved_native_v2.py`, 작은 학습 재현은 `run_pilot`로 수행했다.

`evaluation/refine_v5/p1-followup-summary-v2.json`에 요약·케이스별 진단·hash를 둔다.
raw goals/FK/FBX/render는 private run의 review-v2에 있다. 독립 사람 blind, 직접 클릭 2D
좌표, camera calibration, 피부/접촉 검증은 별도로 필요하며 이번 결과로 인증하지 않았다.

최종 검증: P0/P1 계약·수치 회귀 **22/22**, 스모크 **54/54**, compileall·diff 검사가 통과했다.
